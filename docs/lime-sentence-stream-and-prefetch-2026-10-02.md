# 青柠首播、完整缓存与浮动开发入口

## 原因与设计

最近云端记录证明，旧修复没有解决全部问题：快速角色模型结构不合法导致三条 quick 回答都生成失败，耗时约 7.09、7.36、7.49 秒；普通请求仍等待整份规划，首音频约 5.12 秒。不能把已出现的三条用户接话建议当作已有完整回复音频。客户端此前建议文字一出现就结束查询，也没有把完整候选音频下载到手机。

服务端权威改动在独立的 `../starrynight-server`，见其 `docs/sentence-first-voice-2026-10-02.md`。核心角色台词改为 JSON mode 句子流；完整第一句经过校验就发布、开始 TTS，后续句子／目标反馈和独立的可选表演继续生成。普通请求和预生成共用同一流水线。保留角色、人设、语言、账户隔离、目标状态、记忆提议、中文本地语义与逐字／近似复制检查；心声仍不朗读，完整元数据只提交一次。非法可选字段过滤而非重写正确台词。

第一版 Character 多对象输出实测格式失败，没有发布到生产；快速通用模型单根 JSON mode 两次限量真实验证均成功。只截完整 beat，不按 token 朗读破碎的句子，也不拼补模型文字。

客户端修改：

- 建议文字出现后继续跟进三条回答的准备状态；完整 PCM 到达就写入按账号／角色隔离的持久 WAV 缓存。场景预备状态同样下载音频，携带已下载 id 避免重复传输；兼容旧服务端没有该字段的响应。
- 点击完整候选时先由服务器验证上下文、正式消费和登记，然后用手机已有音频播放，网络返回的重复 PCM 不重复播放；仍在生成时继续接入同一个生成任务。
- 首句后的 `reply.script.updated` 增量更新同一消息和非朗读段落，揭示进度不倒退。完整核心生成结束才预测下一轮，避免半句上下文反复取消／计费；此时当前音频可以仍在播放。
- 语音耗时标注增加模型首 token、首句校验就绪、核心生成完成；流持续时间不等于首播延迟。

## 浮动开发者入口

会话页新增小号 `{}` 图标，轻点直接进入当前角色的开发者页，拖动可移动；位置按页面比例保存并限制在安全区域与底部菜单之外。保留 44 pt 触摸范围，视觉图标仅 13 pt、半透明。模型触摸／取景手势会避开该按钮。

移除角色资料页的旧开发入口和不可达子页面。仅 `STARRY_TEST_TOOLS` 版本创建按钮，发行版没有入口。模拟器隔离 UI 不启动 Unity，因此增加仅 Debug 模拟器的实际 UIKit 控制器验证入口；测试检查真实按钮拖动、打开当前角色开发者页和返回，不冒充真实模型渲染验证。

生产新版已激活，所有四个服务 active、健康检查 200，匿名管理入口 401；未激活的失败版本没有替代正式服务。客户端签名 Release 构建、iPhone 17 安装及启动成功。

实际手机追踪进一步发现：21:35:27 青柠完整预取接话首输出 436.26 ms，是一个真正的手机缓存样本；21:36:28 重启的完整缓存问候仍需 1,491.76 ms，其中重复 register_opening 单独占 562.21 ms，服务端首 PCM 367.52 ms，客户端音频会话 78.91 ms、引擎 48.41 ms。首播与整句播放结束（8.93 s）必须区分。

据此追加持久的初始问候登记确认，按账户／角色存储，重置会话后清除；合并同时登记任务，已有确认的重启不再重复请求。最后一条尚未准备完的接话在内部复制检查后失败，新增明确的私有修订反馈且改为首句直接提供新具体内容；去掉把旧台词再次堆到避免语料里这种误导，保留真实对话历史。去重使用有界纯函数缓存并消除 FTS 与最近列表的重复计算，不改变账户检索范围或门槛。最终三项模拟器 XCTest 均通过；追加游客导入会清除原账户的服务器确认，并单独复测问候规则通过。生产最后激活 `20261002T134954Z-c203b31aa6b6`，四项服务 active、公网健康 200、管理匿名 401；新发布的桌面／手机浏览器耗时瀑布与完整 JSON 导出均通过。原始追踪、对话、音频、安装结果和 xcresult 全留忽略的 `.local/`，公共 Git 只提交源码、测试和本记录。

最终补丁无线首次安装在 180 秒超时，给足大包安装时间后重试成功；CoreDevice 的安装及启动结果均为 success，iPhone 17 已运行这次原生补丁。包约 13 GB，主要是既有角色数据，不是语音补丁自身大小。iPad 当前不可用，没有等待或声称本次 iPad 真机验证。

更新后实机记录：22:20:41 青柠完整缓存 appLaunch 首输出 839.88 ms，首次成功登记 112.64 ms；随后同版本已登记角色的会话请求登记耗时仅 0.04～0.10 ms。22:20:55 小猫切入接管未完成预生成，首输出 879.20 ms。用户随后实际触发三次小猫完整缓存接话，首文字 108.97／121.41／506.70 ms，首输出 585.90／562.54／1,068.88 ms；音频会话 14～30 ms、引擎 29～39 ms。必须记录这些较慢样本，不能只挑前面的 436 ms。首缓冲入队至 mixer 阈值检测还约 380～490 ms，包含音频内容起音／设备输出与回调调度，现有记录不足以把这段全部归因于网络或模型，未通过降低检测阈值来伪造达标。

## 最后一段起音等待与可撤回处理

直接读取手机已有 WAV、零 AI 调用：三条小猫缓存人声开始超过原始振幅 32/32768 的位置约 288.8／291.8／302.9 ms；另一个青柠样本约 251.2 ms。这是真实内容中的极低电平前缀，并非全部 400 ms 都是 App 卡顿；剩余设备输出／回调调度仍独立存在。

新增独立 `SpeechOnset.swift`，只处理每段开头单声道 24 kHz／16-bit PCM，阈值 32/32768（约 -60 dBFS），最多跳过 6,000 帧（250 ms），保留至少 960 帧（40 ms）起音缓冲；不处理句中停顿，短暂极轻声整段保留。流式最多持有初始约 290 ms 音频数据后作出有界决定，不等待整句。网络首包、内置开场、持久缓存都共用播放入口。

原始 PCM 单独保留，WAV 缓存仍写未裁原录音；只修改播放缓冲及真实播放时长／口型时间轴。耗时记录增加 `audio.onset_padding_removed_ms.<beat>`，可核对实际跳过多少；没有改小出声检测阈值。若撤回，恢复 CloudSpeech 的 append／ready 缓冲修改并移除 SpeechOnset 即可，现有缓存无需再下载或生成。

最终三项模拟器 XCTest 在稳定源码上再次通过，新增有界裁切、跨块、Int16.min、轻声起音保护、句中保留、短轻声保留、真实播放时长及原 WAV 完整性检查。带 300 ms 前缀的预取音频 fixture，真实 mixer 首输出 130.99 ms，日志确认为跳过 250 ms；先前测试编译早于最新 fixture 修改、显示 0 ms 裁切，因此没有拿那次结果冒充最终验证。最终原生 Release 构建、深度签名及真机安装通过；最终使用下面记录的正常 40 角色构建。

服务端最后发布 `20261002T141944Z-6251fb412eea`，另修正管理页误隐藏数字鉴权耗时；267 passed / 4 skipped，实际部署值 3.148 ms 可见、真实 Authorization 仍隐藏。新发布浏览器瀑布及 JSON 导出通过；后台预生成本身没有 gateway 鉴权字段，不把字段缺失当作调用异常。
