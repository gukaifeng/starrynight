# 消息页：相处资料与会话管理

## 最终行为

消息列表保留左滑后的“不显示”和红色“删除”。内容末端以 24 点宽的透明遮罩渐隐；共同的圆角背景从列表底色过渡到操作区，随展开进度显现。按钮仍在条目右侧，左右横向手势与纵向滚动沿用原有 UIKit 方向判定。

普通点击条目打开「你们的故事」资料卡，先了解这段关系，再决定是否进入会话。卡片显示角色头像和名字、关系与称呼、相识天数、对话轮数、相伴天数、记忆数、初次相遇和最近互动日期、最近一句、最近两件共同记忆。底部提供“进入会话”和“不显示”；点击空白处或左上角返回也可关闭。搜索命中的具体聊天记录仍可直接进入对应消息位置。

羁绊阶段使用当前账户、当前角色的已有记录计算：“初次相遇、开始靠近、渐渐熟悉、相伴日常、故事渐深”。对话轮数按用户有效发言计，相伴天数按出现有效消息的自然日去重；空白的流式占位不参与。它不是 AI 对用户的好感评分。当前客户端最多保留 1,000 条消息，因此日期与统计是本机可用记录的视图，并非服务端的永久累计统计。未来接入权威累计统计时可替换独立的 `ConversationRelationshipSummary`，不必重写资料卡。

## 重置安全与账户隔离

右上角省略号进入「会话管理」子页面，沿用同一面板和标题位置，以渐变切换，不叠加第二层 sheet。只有这个子页面有“重置角色”，并再次确认会清空聊天记录、共同记忆和相处进度，保留订阅、称呼和个人设置，且不可撤销。

`ViewerCoordinator.resetConversation` 与删除共用既有服务端清空事务：先持久化 reset nonce，暂停该角色同步和新对话，等待服务器确认后再清空本地记录及对应语音缓存。失败时保留原记录，继续重试同一个 nonce；不能在服务端状态未确认时继续发言。重置成功保留消息列表条目，删除成功才隐藏条目。“不显示”只改变列表显示状态，可撤销，记录和记忆不变。

简体中文、繁体中文、英文均补齐此流程的界面文案；角色名字、用户称呼和真实聊天内容按原文显示。

## 验证与测试边界

为原生 UI 新增隔离的 Debug 模拟器测试入口：

```bash
bash scripts/test_native_ui.sh ConversationInfoCardTests,MessageListScrollTests MessageRelationshipNativeVerified
```

入口使用生产 SwiftUI 页面与数据存储，独立 bundle ID `app.starrynight.native-ui-fixture`，不包含 UnityFramework，也不打包网络连接配置；生成器拒绝真机和分发模式，构建阶段拒绝 Release 和 archive。测试数据和清空成功/失败回执仅在 `DEBUG && targetEnvironment(simulator)` 且显式 fixture 参数启用时注入。不会操作真实账户、付费 AI 接口或手机上的现有聊天。

资料卡四项 XCTest 已通过：中文关系数据、二次确认取消和成功清空、重启后的清空持久化及进入会话路由；隐藏/撤销保留记忆；网络失败保留记录并阻止新会话；英文界面翻译且聊天原文不变。测试同时审查乱序消息和空白占位的统计处理。首次测试的两项失败来自旧名册“一屏到底”的假设，以及无 Unity 的测试壳无法得到渲染完成信号；已修正为按 41 角色滚动，以及检查真实会话准备页路由。补齐翻译时曾出现 Swift 跨行 `+` 运算符空格缺失的编译错误，修复后重新编译并复跑，未跳过失败。

截图检查覆盖资料卡概览、重置警告、左滑渐变；据截图把卡片高度收紧到 590 点，并给操作区过渡底色补充圆角。结果包留在 `.local/checks/MessageRelationshipNativeVerified.xcresult`，日志在 `.local/logs/MessageRelationshipNativeVerified.log`。这验证原生交互与本地事务行为，不代表已完成 Unity 渲染、真实服务器清空或真机帧率测试。
