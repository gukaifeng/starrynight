# 0.97 待机手臂、表现连续性与静音耗时

StarryNight 0.97.0 / 128 对当前全部 16 角色做共用适配。保留作者模型、骨架、原始片段与菜单；没有调用 AI 图片、音色或对话生成接口。本次原作物理能力与宿主适配分别记录。

## 手臂与配饰根因

原 PhysBone 与运行链未发现映射 UpperArm、LowerArm、Hand 的物理段，因此绑定完整人形骨骼、头发和衣物能动，不代表手臂原本也是物理链。VRChat 自身的跟踪/IK、基础 Animator 与 PhysBone 是不同系统，不能仅凭骨骼齐全判断 App 已等价获得全部 VRChat 动作。

实际缺陷在 FX 投影：Humanoid 源动画采样为 Generic 骨曲线后，旧宿主让 FX 重新覆盖人形站姿。默认 FX 第一层应屏蔽人形肌肉；自定义第一层按实际允许的骨路径保留。现投影仅用于 FX 图，原作手动片段仍保持绝对采样数据。[VRChat 官方 Playable Layers](https://creators.vrchat.com/avatars/playable-layers/)规定该默认遮罩，并区分人形肌肉、非人形 Transform 和 FX 组件动画。

另修正 Humanoid body mask 被错误继承到所有后代的问题：仅匹配真实人形映射骨；耳朵、尾巴、袖子等继续使用自己的 Transform mask，作者显式 Transform 遮罩仍按最长路径继承。当前 Lime 第一 FX 层有仅手指的自定义人形遮罩，但 FX 图中没有 Humanoid 源片段；其余 15 个为默认遮罩。保留自定义语义，不能把所有未来 FX 人形动画一律删掉。

`AvatarIdleArmReview` 对保存的生产 Package prefab 求值，对比真实 Idle 基线与 Animator 2 秒后的状态，控制器必须有有效层。肩到手向下方向点积越接近 1 越接近下垂，仅作为站姿比较，不是美术评分：

| 角色 | 旧左 / 右 | 新左 / 右 | 结论 |
| --- | --- | --- | --- |
| Koharu | 0.685 / 0.695 | 0.969 / 0.964 | 消除 FX 导致的额外张臂 |
| Sio | 0.958 / 0.956 | 0.962 / 0.962 | FX 不再覆盖原待机人形姿态 |
| 其余 14 角色 | 逐个记录 | 保留原值 | 未统一强改作者手臂站姿 |

私有证据 `.local/checks/idle-arms-v097-before.json`、`idle-arms-v097-after.json`。没有由头发惯性推断手臂配置，也没有给整个人形挂 ragdoll。

`AvatarArmFollow` 是本次明确的 App 适配，在实际整体转动时加入有限阻尼旋转惯性：上臂/前臂/手腕上限 3/4/1.8 度，不平移关节，不累积修改原骨姿态。120 Hz 内部子步用于稳定积分。场景中的随机小幅转动也可带动它；它不是原作新动作、不是完整手臂物理、没有伪造可被 AI 调用的作者表现。

## 选择、替换与恢复的连续性

旧图只有部分直接会话参数过渡得到加长，部分相对时长、退出状态与原生参数驱动仍会瞬切。新的会话过渡以 0.32 秒为基础，换算相对片段时长，保留作者 exit-time 条件。`AvatarPoseContinuity` 在基础 Animator 之后、嘴型/眨眼/注视/次级物理之前使用五次平滑桥接。原生状态行为直接改参数也会被检测。

持续测试又捕获了 Hikarun 的 write-default 通道在切换尾帧突然释放：只从固定起点交叉淡化到每帧变化的目标，仍会在目标突变时跳动。现对不连续的人形目标重新桥接，并限制每骨 360 度/秒；桥接期间每形变最大每秒 6 个原标准单位，若尚未追上目标则继续收敛，不在 0.32 秒尾帧硬贴目标。无过渡时只采样基线，避免每帧重写全部骨和形变。

叠加恢复顺序明确：手臂惯性 15，已有宿主/原片段/眨眼/表现 20/25/30/35，连续性 40；下一帧 Animator 之前清理上帧适配，不把适配再次叠入参考姿态。讲话嘴型、眨眼、注视与原物理仍在之后工作。

原作手动片段预览保留独立通路。源动画内的漫画符号闪动、眨眼等多关键帧通道单独统计，不能为了让检测通过就删除作者特效。例如 Fiona Mesugaki1 的 OptionShock1-2 有原 0/0.25/0.5 秒闪动关键帧；首次检查把这类特效内部变化混同静态表情切换，导致失败。后来将它单列，但切换首帧仍检查所有形变，并继续严格检查静态表情与骨骼跳变。未通过日志保留在私有目录。

## 数值验证

- 全名册原待机/AI 自动表现：`pose-v097-after.json`，16 角色、443 用例，0 项姿态安全失败；包括 Hikarun 30 秒跨原呼吸/空状态周期。
- 原生会话参数选择与恢复：`continuity-v097-after.json`，16 角色、1,092 用例，分别按 60、120 Hz 求值。首帧最大形变增量 0.001305 标准单位（约完整形变 0.13%），静态形变最大帧增量 0.100000，骨骼最大约 6.001 度，120 Hz 阈值相应减半。
- 手臂惯性：32 用例，两种刷新步长的最大可见旋转约 2.364～2.367 度；持续转动后静止可消退，恢复与最近原动画局部旋转一致，无关节平移。

这些是保存 prefab 的 Editor CPU 数值检查，不是设备 FPS，也不穷举作者所有特殊服装与动作组合。实际播放器、OSS 与设备结果另列于下节。

## 静音与非播放耗时

原开发者列表主要突出首次出声，无输出时显得没有耗时；静音内置开场还未创建完整会话追踪。现静音开场照常创建并持久化追踪，记录准备、文字到达、表现分派；联网请求无论有无音频事件，都保存服务端生成/表演规划快照与客户端接收、解码、请求处理完成。

请求处理完成标记在网络流消费结束后、等待音频 drain 之前，区别于扬声器播放完。内置开场和持久回放在本地资源就绪时记处理完成，不伪造服务端生成耗时。静音请求的 wants_audio=false 保留：未请求 TTS 不额外花钱生成，只明确未执行，缺值不是 0 毫秒。

新增表现分派与 Unity 指令确认。Unity receipt 附加本地单调时钟 processingMs，记录验证/控件选择 CPU 时间；客户端记录跨桥往返及指令状态，只对 accepted 且 executed>0 标记首次接受表现。这些不是 Animator 求值、动画完成时间或 GPU 渲染时间。客户端、引擎、服务端时间只在各自时钟内计算，不直接相减不同机器时间。

开发者“语音耗时”列表以请求处理时长为主，静音/页面不可见说明未播放，已有部分输出后静音则说明后续未播放；详情展示文字、处理完成、音频、表演计划、分派、输出与服务端 marks/spans，并可导出完整记录。客户端准备、表现分派与 Unity 控制跨度即使不足 1 毫秒也默认显示，完整细分环节开关不再只称作音频环节。记录不含对话正文、音频与凭证。

`Native-Timing-v097-final.xcresult` 验证隔离实际静音开场仍执行原表情回调、产生准备/分派记录，带无音频事件的服务端快照仍保存，重建 timeline 后保留；`Native-Playback-v097-r1.xcresult` 验证真实 AVAudioEngine 输出线程、持久语音回放和取消。服务端新增无音频流快照回归，`test_voice_trace.py` 4 项通过，无生产代码和进程变更。首次 pytest 因缺少 PYTHONPATH 收集失败，补上 PYTHONPATH=. 后通过，未调用提供商。

## 打包、运行与发布

- 当前发布版本为 StarryNight 0.97.0 / build 128。iOS 与 iOS Simulator 均完成真实 Unity 导出；导出前检查保存场景中的 16 个角色均连接到有效的新控制器、连续性组件和 6 关节惯性组件。两个平台的 Fiona、Mizuki、Ramune 共 6 个自包含 Bundle 均重建通过。
- Xcode iPhone 模拟器 Debug 和真机签名 Release 编译均成功；签名包通过 `codesign --verify --deep --strict`。真机包位于私有 `.local/build/DeviceDerivedData/Build/Products/Release-iphoneos/CharacterHost.app`。
- 实际 iPhone 17 Unity 播放器：`Continuity-v097-Player.xcresult` 的 `testBundledRolePerformancePreviewsAndHikarunBreathing` 通过，耗时 444.960 秒。顺序进入全部 13 个内置角色，执行各角色原作控件、恢复，检查 Unity 实际收到的参数与选择；每角色还断言实际请求处理、Unity 指令确认和引擎控制计算耗时存在。该实际播放器验证区别于 Editor 的 60/120 Hz 数值求值。
- 本次尝试向既有 iPhone 安装时，CoreDevice 返回无法定位该设备（1011），没有安装成功。按用户外出时允许使用模拟器的约定继续完成验证，没有等待解锁或把签名编译成功描述为手机安装成功。
- OSS release 4 已发布：54 对象通过长度与 SHA-256 元数据验证，16 项市场目录与 6 项平台 release 写入成功。正常 TLS 验证的商店 API 在 ios / ios-simulator 都返回 16 角色，Fiona、Mizuki、Ramune 的版本均为 4。旧 release 1/2/3 保留，既有账户、对话和记忆不变，没有重启服务器。脱敏报告 `oss-v097-after.json`。
- 下载检查额外发现验收漏洞：`DownloadManager-v097.xcresult` 首次虽通过（146.239 秒），检查安装元数据后发现 Fiona 仍使用 release 3。原因是本地目录缓存可能先允许既有资源打开，测试只等待模型出现，没有证明新 Bundle 被实际加载。该次结果不能计作 Fiona release 4 验收。
- 已改进下载测试准备：通过 App 资源管理删除隔离测试账户的三项既有角色资源，再向服务器申请新票据并加载。原文件和用户会话保持不变；最终逐一核对本机实际 package.json 的版本。
- 首次强制新下载运行已经加载三项 release 4，但在删除 Ramune 后重下载的末段失败：测试在资料页呈现动画结束前立即检查 `download.exists`，误走进入会话按钮分支；后续层级明确显示实际存在的是下载按钮。改为等待所需下载按钮出现后点击，没有用固定睡眠掩盖问题。该次失败保留为 `DownloadManager-v097-fresh.xcresult`，不能计作完整删除/重下载验收。最终重跑结果另列于下一项。

- 修正后的 `DownloadManager-v097-fresh-r2.xcresult` 完整通过，耗时 157.118 秒：三项全新 OSS 下载、真实 Unity 加载与原作表现恢复、取消删除、活动 Ramune 确认删除及重下载均通过。运行后直接核对本机已安装 `package.json`，Fiona、Mizuki、Ramune 都是 ios-simulator release 4，脱敏记录 `installed-roles-v097.json`。仅账户鉴权和资源网络请求，自动化参数禁止付费 AI。
- 耗时面板最后一项小于 1 毫秒准备/控制跨度展示调整后，模拟器 Debug 与真机签名 Release 再次编译通过，签名校验通过。恢复普通模拟器工程生成，不保留私有账户测试资源引用；真机 App 不含账户测试文件。

## 回滚边界

手臂惯性独立组件 AvatarArmFollow，可单独禁用；它的恢复器不改原作者资产。FX/遮罩与连续性修复位于公共生成器及 AvatarPoseContinuity，不应因为不喜欢惯性风格一并回滚。角色 ID、账户、订阅、对话与记忆不变。新增 receipt 计时字段兼容旧接收方。

方法与陷阱已补入项目 VRChat 导入技能 natural-idle.md 与角色待机标准。原模型、曲线、生成 prefab、图片、音频、ZIP、账户配置与原始验证记录继续留在忽略的私有目录。
