OSS 实测为私有 Bucket。共上传 54 个不可变对象：16 个角色各 3 个预览（封面、头像、试听），以及 3 个角色各 2 个平台运行包。真机和模拟器分开编译；客户端不读取 OSS Key，也不遍历 Bucket。

云端商店由 PostgreSQL 保存角色公开资料、媒体引用和发布清单，下载认证复用账户 Bearer 会话、角色可见性和限流。媒体与运行包使用 15 分钟有效的 GET 预签名 URL，模型下载直接走 OSS。服务器 OSS 凭证在私有配置中，未进入客户端、发布归档或两个公开 Git 仓库；收缩为指定对象的 `oss:GetObject` 后，分发无需写权限。

## 关键处理

- Unity 运行时此前未启用 AssetBundle 模块，编译提示类型被转发但缺少模块；补入官方 `com.unity.modules.assetbundle` 后，使用 LZ4、严格检查、自包含构建。新增输出目录先刷新 AssetDatabase，再移动资产，保留 GUID。
- 原资源集合把「音乐暂未安装」等同于「角色结构不兼容」，首轮模拟器下载测试因此暴露预条件失败。现在结构兼容检查与安装状态分开，只有明示下载交付的角色允许资源暂缺，进入会话前仍强制下载并校验。
- 下载先校验 ZIP 的大小/SHA-256，再用 ZIPFoundation 校验所有成员、路径、平台及内容哈希；Unity 加载时另校验 bundle CRC。下载中断不覆盖已有版本，只有校验完成才原子激活。最多每秒十次进度更新，避免大文件下载回调不断刷新聊天 UI。
- 下载后的音乐、问候音频、问候脚本、氛围及图片从已验证包注册，保持角色与账号隔离；已有角色的轻量本地图像可继续用于预览。新商店描述可登记到通用目录，不需要另写每个模型 ID 的加载分支。
- 管理平台补入商店预览记录，OSS 删除保护同时检查发布包与预览引用，使用和发布工具相同的数据库发布锁，防止误删封面/头像/试听。
- 生成器禁止重写已有版本的发布计划。模型或媒体有变化时用新版本、新内容哈希路径；运行时接口不兼容时升级 runtimeVersion，不能将任意作者代码作为下载资源执行。

## 用户测试与当前边界

解锁手机打开星夜 → 发现 → 搜索 Fiona、Mizuki 或 Ramune → 点资料、试听 → 登录后点击下载 → 确认大小与流量 → 看进度、等待校验 → 进入会话。其他页面选择这些角色时也有下载提示，不能绕过校验进入缺模型的页面。重启后同账号不用重新下载。

本版支持跨 App 页面继续下载、取消、失败重试、空间不足提示和版本隔离；建议下载时保持 App 打开。尚未支持杀掉 App 后继续传输或断点续传；重试申请新链接。已下载资源可以离线恢复，新的 AI 对话仍需要云端网络。账号隔离会让另一账号另行取得资源，不代表丢失前一账号的缓存。

其余角色迁到 OSS 可沿同一策略和发布流程进行，不再改运行时加载实现。新平台、未知渲染/脚本能力、Unity 引擎升级仍需兼容性验证；通用数据协议不能保证不同引擎版本的 AssetBundle 无需重建。只有取得相应再分发授权的角色才适合正式公开市场发布，本次发布用途为用户授权的私人开发验证。
