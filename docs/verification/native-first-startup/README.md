# 原生首页先于角色加载 · v0.49.0 / build 70

2026-09-30。用户反馈 App 启动长时间停在加载页，希望先进入 App，角色随后准备。此次只改原生启动编排和准备中的首页，不更改角色资源、动画、渲染质量或真实 AI 实现。

## 根因与决策

旧链路把整屏品牌页的退出绑定在 `finishInitialPreparation`：Unity 初始化 → sceneReady → 选角与相机配置 → 至少三个稳定渲染帧 → 对话窗口淡入完成，最后才退出启动页。主动问候在页面可见后才发起，真实 AI 网络请求不是这里的阻塞项。

现在分开处理两个条件：

1. **原生首页就绪**：本地账号、角色名册与会话状态读好，SwiftUI 首页排版提交后即可退出品牌页。品牌开场从最短 1.2 秒缩为 0.42 秒，退出淡化从 0.55 秒缩为 0.22 秒；减少动态效果模式保留更短的过渡。
2. **角色可见**：品牌页退出、首页绘制后才启动 Unity，原来的稳定首帧检查和不透明 Metal 窗口交接继续保留。完成后平滑淡入角色，不显示半准备好的相机或角色。

准备中的首页采用内置角色封面、圆形头像与名字、已有本地消息的末条预览和小型加载提示，底部菜单可用。没有历史记录时不制造聊天内容；发送和模型交互等控件在真实会话就绪后出现。整个 App 不再被一个覆盖所有页面的加载层锁住。

Unity 的嵌入式启动仍要求主线程，因此没有擅自搬到后台线程。通过 `scheduleRuntimeStart` 的前台状态、页面、presentation 与取消检查，处理初始化期间切菜单、切后台和恢复。用户已离开首页时，迟到的 ready 事件不能自动打开旧对话。保留的会话恢复也不重播品牌开场。

按项目约定检索了启动性能相关技能，没有引入额外依赖。本轮采用 [Apple：Reducing your app’s launch time](https://developer.apple.com/documentation/xcode/reducing-your-app-s-launch-time) 的原则：首个可用界面只等待必要工作，把扩展初始化与首次页面显示分开衡量。

## 实测与边界

设备：本机 iPhone 17 / iOS 26.4 模拟器，Debug 宿主；未人工延迟的进程重启各一次。不是多轮冷启动分位数、真机性能结论，也不包含点击图标至 iOS 创建 scene 之前的系统、动态库加载耗时。

旧版 build 69：`viewer_open` 至 `viewer_visible` **6.224 秒**。此前品牌页仍未消失，随后还要完成窗口及品牌页退出动画。旧版没有统一的 scene 起点埋点，不能拿这个数与新版算精确改善百分比。

新版 build 70 新增 `LaunchTrace`，从 `sceneConnected` 的单调时钟起算：

| 阶段 | 场景连接后的耗时 |
| --- | ---: |
| 原生数据与页面准备完成 | 0.373 秒 |
| 品牌页退出，原生首页显示 | **0.681 秒** |
| 开始嵌入式 Unity 初始化 | 0.771 秒 |
| Unity 同步初始化调用返回 | 1.359 秒 |
| 收到 Unity sceneReady | 3.861 秒 |
| 角色稳定首帧完成 | 6.913 秒 |
| 角色对话淡入完成 | 7.429 秒 |

这里优化的是首页被加载页遮住的时间。3D 本身仍需数秒，尚未做资源拆包、纹理解码或着色器预热优化；本次 Unity 同步初始化段约 0.588 秒，主线程仍可能短暂停顿，不能据此宣称所有启动卡顿已消除。

- Simulator Debug 与 iphoneos Release 构建成功，Release `codesign --verify --deep --strict` 通过。
- `StartupCompositionTests` 三项通过，87.131 秒：故意延迟角色就绪时原生首页与菜单已出现；最终构图稳定、前后台恢复不重置；加载中切发现与消息、回首页可正常完成。
- 加强“迟到 ready”单项后再次通过，31.082 秒。原先立即切走可能在 Unity 的 `Start()` 前暂停，测到的是“尚未发出 ready 就取消”。测试先给真实首帧足够时间排入延迟队列，再离开；trace 记录 ready 在 **16.724 秒**到达，用户当时仍在消息页，直到用户回首页才准备并显示角色。没有把一个未覆盖目标时序的通过结果当作充分证据。

- **通过 Wi-Fi 安装到 iPhone 17**，随后用 CoreDevice 读回名称「星夜」、版本 **0.49.0**、构建 **70**。没有为测速自动启动真机并生成付费问候；用户可直接打开已更新的 App。
