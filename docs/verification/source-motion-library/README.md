# 16 角色原作片段库与 10 组动作实验验收

版本：StarryNight **0.94.0 / 125**；当前发布名册 16 个角色，XCP **3.4.0**。结构与可执行边界见[原作片段库与通用动作标准](../../character-standard/10-source-motion-library.md)。本轮不重新生成图片、音色或角色对话，不为动画验证调用付费 AI。

## 交付与入口

会话中的浮动开发者图标有三个独立入口：

- **角色表现**：保留作者原菜单、表情、手势、姿态与部件选项。
- **原作片段库**：全来源扫描后可绑定的独立片段，分肢体、表情、部件，可按原文件名搜索。标明静态保持、循环、一次播放和部分通道适配；可恢复默认。
- **动作实验**：10 组宿主添加的身体与表情组合，仅手动预览。点头、开心、思考、害羞、不满、低落、惊讶、问好、鼓励、摇头；开关只影响这个附加层。

新增组合不自动介入正式 AI 对话。`preview:false` 返回 `HOST_MOTION_DEVELOPER_ONLY`，原作 AI 表情映射仍保持原来的 427 项审核选项。后续推广自动调用需要先通过用户的观感验收。

## 新增组合的通用实现

16 个角色均通过 12 个必要上身关节映射检查；未来角色按真实 Humanoid 映射与能力接入，不依赖名字猜测或角色白名单。骨轴从角色中性坐标和实际胸、臂、腕方向校准，解决镜像与肘轴差异。

每组动作使用五次 smoothstep，安排预备、躯干、头颈、双臂和收尾的错峰时序；结束及取消都平滑释放。时长 3.6–4.4 秒，最大单个附加关节偏移约 38°。足部、根、手指、相机和用户取景状态不写入。原作姿态、原作片段和手动位置操作优先。

表情从真实原作 shape/静态脸部样本匹配，排除朗读 viseme。16 × 10 组合都有配套表情；个别缺乏明确情绪时借用原作近似表达，并在界面明示“近似配合”。不声称所有作者都原生制作了这十种情绪。

## 处理过的关键问题

1. **静态片段首帧等于默认。** 一两帧的作者滑杆/开关片段必须保持末帧目标；采样首帧会导致按钮成功但脸部没有改变。补末帧检查并全库重跑。
2. **巨大原动画数据超源包预算。** Mao 的原数据需要无损 gzip；单文件解压上限 128 MiB，总源包预算维持 256 MiB。只收敛完全恒定的重复 Transform 样本，不降质量。
3. **脚本序列化与恢复时序。** `SourceMotionPreviewRestore` 单独 `.cs/.meta`，每帧在 Animator 之前还原，在其之后叠加；补序列化与解绑检查，防止非零默认 shape、衣装或节点状态残留。
4. **把原作变化误算成附加层卡顿。** Hikarun 原作基线本身最大单帧约 4.516°，组合后约 4.640°。测试分别记录作者、附加与组合变化，脚部只比较同一作者帧，避免将原作步态判成实验移动脚。未擅自重写作者曲线。
5. **原生目录仍只接受 schema 1/2。** 新包 performance@3 在 Unity 正常，但 iOS 将表现目录视为不存在。扩展读取至 1/2/3，并用实际 UI 测试确认原菜单、库和实验三个入口。
6. **本机上传工具执行失败。** macOS 版 Go 上传工具在帮助模式也以 SIGKILL/137 退出，未确认系统根因；改用现有 Linux 上传工具在云端运行，不关闭安全软件、不绕过密钥管理。模型包保持私有。
7. **模拟器方向请求没有改变界面。** 失败时 Unity 根控制器仍允许横屏（mask 26），状态停留在竖屏。一次宿主通知生命周期试改未解决，已撤销。关闭并重启该模拟器后，原设置测试完整通过；保留 DEBUG 方向诊断与原失败日志，不能仅凭恢复通过就声称已彻底确认根因。
8. **云端外网上传受带宽影响。** 使用同地域 OSS 内网 endpoint 完成资产写入；只覆盖上传进程环境，不修改生产公共 endpoint 或客户端预签名下载地址。官方依据：[OSS 同地域内部访问](https://www.alibabacloud.com/help/en/oss/user-guide/access-and-network-overview)。
