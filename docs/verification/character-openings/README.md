## 验证中发现的实际问题

1. 数值测量正确不代表 SwiftUI 最终排版正确：前景图高于横幅时，外框默认居中再次偏移图片；用明确左上对齐修复头饰裁切，最终截图已确认。
2. 豆日向的旧 `portraitWidthScale=1.4` 触发 Bounds 全等判定失败；新头部范围识别接受仅横向扩展。测试补入真实作者参数，防止仅测默认值时漏掉。
3. 原先 12% 面部占高的新增审查门槛在草莓某窄视口得到 11.99%，属于宽头饰与放大余量的实际约束；门槛定为 11%，能检出修复前豆日向约 9% 的远景，并由逐角色截图判断视觉效果。没有放宽安全区或缩放断言。
4. 包内 PCM 已有时长但消息元数据延后到播完才写入；现创建消息和开始回放前就提供准确时长，旧包内消息可补读目录。
5. 初轮录音检查失败来自子控件 accessibility ID 被父视图覆盖、未激活音频场景的测试夹具和键盘自动纠正空格；分别修正后重跑通过，原失败记录保留。

系统仍产生一条已有的 UIHostingController 子视图运行时警告，未影响本轮测试；不把成功构建描述为零警告。
