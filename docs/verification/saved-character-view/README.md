# 长按取景与保存方案 · 0.43.0 / 64

## 行为

- 一秒长按仍有小幅弹性、渐强震动和独立的到时反馈。到时打开位于原聊天区域中心的小卡；触发长按的同一串触摸不会顺便旋转角色。
- iOS 26+ 使用 `glassEffect(.regular)` 的原生 Liquid Glass，旧系统用磨砂材质；减少透明时实色。原聊天内容淡出，相机/舞台不为面板重新取景，底栏与面板仍可点击。
- 面板外单指转动、双指捏合与移动。松手保留草稿；关闭、换页或后台恢复已提交方案。关闭按钮明确，卡外不作关闭手势，避免操作模型时误退。
- 恢复默认会清除方案选择但保留方案列表；保存自动生成“取景 n”，可直接选择、删除。可存12项；原位或重复状态不重复保存。只有保存成功的角色视图进入账号档案。
- `CharacterRecord.viewLibrary` 为可选 v1 数据，账号+角色隔离，旧档案没有字段时正常读入。保存失败显示实际存储错误并恢复旧记录；关闭时从已落盘的库恢复，避免迟到的保存回执保留未保存草稿。

## 屏幕与原作边界

默认继续使用原有半身会话构图；约束对象是头部与上半身的静态人像包围体，腿部仍可以位于画面外。用户调整只影响角色根变换，不改变作者骨骼、动作、资产或相机。角色大幅原作姿势的动态包围体不在此次静态取景约束范围内。

使用相机视场、深度、长宽比和实际窗口安全区，求八个角点在透视投影中的可行范围。左右±180°、上下±20°；通常缩放0.78–1.28，侧身或屏幕较窄时按可容纳上限自适应缩小上下限。归一化位移外层最大±0.45，实际可移动范围进一步由四边投影限制。验证的人像高度保持至少安全区的30%。目标与弹簧中间姿态都检查，不能只检查最后一帧。

保存的请求值与当前屏幕约束结果独立，启动临时尺寸或屏幕旋转不会覆盖方案；静止时缓存适配上限，不逐帧重复二分计算。命中测试与QA头部坐标使用实际已变换的角色。

## 验证与关键问题

- Unity 两个原作模型 × 五类手机视口（375×667、393×852、402×874、440×956、852×393），不同角度、尺度、位移及过渡检查 **56,615** 个断言通过，见 [runtime-review.json](runtime-review.json)。包含松手保持、关闭撤销、恢复默认、临时视口恢复后重现方案、原作骨骼和相机不变。不是设备FPS测量。
- 保存档案的10项实际读写、旧格式解码、账号/角色隔离、恢复默认及删除检查通过，iPhone17模拟器UI运行4.565秒；日志 `Character-View-v043-1.log`。
- 首次运行用固定缩放比例判断“不能太小”不能表达不同角度下的实际视觉大小；改用自适应上下限并验证投影高度与四边安全范围。
- 第一轮玻璃面板已出现，但根视图AX identifier覆盖了内部按钮，自动化无法定位。移除根标识、保留各按钮标识并扩展按钮触区。
- 第二轮真实单指调整/保存/切换/重启已执行，重启后的长按命中暴露原网格检测仍用未变换坐标。修正为检测实际显示的根变换；启动视口也发现约束结果回写意图的风险，改为请求/已约束结果分离并加入回归。
- 第二轮双指实际调整成功；自动化将包含 `serializedVersion` 字符串的 Unity Rect 当纯数值字典读取失败。按数值字段读取后继续断言原投影边界，没有放宽边界。

第三轮双指流程21.530秒通过；重启后点击头部的复测继续失败，进一步核对发现导入 SkinnedMeshRenderer 的 local/world bounds 与当前烘焙包围盒不一致。取消旧 Renderer 包围盒预排除，改用实际 CPU BakeMesh(false) 三角形，头坐标统一局部空间避免重复缩放，并将缩放/旋转后重新命中加入 Unity 多尺寸检查。

第四轮双指21.756秒通过。重新打开取景时还暴露出：保存后的头部可能进入聊天渐变区，底层TouchSurface不再是直接命中视图。将长按观察移到会话父视图，排除面板、底栏、身份胶囊及输入/声音控件；短滑超过12pt仍让消息滚动。QA就绪条件改为真实父级长按识别器可用，后续必须继续以实际触摸成功打开面板作验收，不能只看就绪标记。
