# 横竖屏与窗口适配验证 · 0.12.0 / build 21

2026-09-28。本轮改动包含原生布局与方向权限，以及低姿态受限取景的镜头俯角修正。复用现有 Unity 全屏渲染、角色/姿势包围盒和相机弹簧；XCP / XEP 源包及运行接口不变。设计说明见[横屏与可变窗口方案](../../design/2026-09-28-responsive-landscape.md)。

## 交付范围

- iPhone 17 支持竖屏和左右横屏；iPad 保留全部方向。实际宽窗口使用左角色、右侧半透明渐变聊天，窄窗口保留竖向构图。
- 键盘避让、输入草稿跨方向保留、显式收键盘入口；短窗口收紧辅助说明和推荐话题，保留主要操作。
- 取景/外观/姿势/空间使用横屏侧栏，关闭和保存固定可点；音乐、工具、资料、记忆、历史、账号、关于共用自适应弹层容器。
- 模型按可见区域平滑取景，触摸与拖动保持正确坐标；旋转不写入用户取景/姿势参数，不重建引擎。
- 首页改为宽窗口双列、窄窗口单列，登录提供并列表单；加载/错误页可在矮窗口滚动到返回按钮；所有应用滚动区域隐藏指示条。

## 实际问题与处理

1. 原 iPhone 在 AppDelegate 和生成的 Info.plist 都仅允许竖屏，现已同时开放左右横屏。首次更新后旧模拟器仍停在竖屏；在不删除 App 数据的前提下重启模拟器，同一方向配置随后正常。未通过测试专用强制旋转来绕过实际系统行为。
2. 原横屏只在键盘出现时临时侧排聊天，底部面板仍占据大半模型区域。改为按当前窗口尺寸选择统一布局，聊天、编辑侧栏和模型区域使用同一几何规则。
3. 把取景工具的关闭区从滚动内容移到固定顶部时，SwiftUI 外层 accessibilityIdentifier 覆盖了子按钮标识；通过显式 contain 语义保留独立可操作元素，并保证取消/完成有 44pt 点击区域。
4. iPhone 曾出现首条回复时的 SwiftUI/辅助功能快照停顿，后续串行专项也复现，不能归因于并行驱动模拟器。保留未符号化栈和失败结果；将上限 60 条的实时聊天窗口改为完整高度测量的 VStack，避开动态短视口、流式内容与 lazy 高度估计同时变化。相同首条侧躺指令随后通过，另重跑双端完整流程；不声称已证明系统内部根因。资料弹层键盘出现后底层按钮会被辅助功能屏蔽，因此输入框以真实可点击区域检查，模型以独立完整镜头采样和截图检查，不再等待不可见按钮的遥测。
5. 资料面板的系统键盘最初没有参与模型可见区计算；补齐后，iPhone 侧躺截图又暴露镜头降到地板下面。脸部投影坐标虽通过检查，人物实际上被地板挡住。最终按目标区域增加镜头俯角，并给俯角加入与位置/距离相同的解析弹簧。新增地板上方约束、八角点和过渡轨迹验证，并重新审查实际截图。保留 before 图片，不将此前的流程 PASS 当成视觉验收。内部 framingProtocol 升至 7，framingMotionRevision 升至 2，要求重新导出 Unity；XCP / XEP 不变。
6. iPhone 横屏侧栏中，独立键盘附件条与导航栏挤占表单高度；“完成输入”改放导航标题位置，取消/保存仍在，新增输入框位于导航栏下方且键盘上方、可实际点击的双方向断言。最终 11b 图片来自 Acceptance 主流程或随后同版的资料专项，17 图片来自资料专项；完整聊天采样来自 Acceptance 主流程，并在开始下一测试前归档。
7. 原三角色动作回归只接受最后一条事件名等于 state，新增场景系统的 environmentConfigured 回执会覆盖它，即使动作和镜头已收稳也超时。改为等待真实角色、场景稳定、动作计数与取景恢复，保留距离/大小/角度断言；没有降低动作完成要求。
8. iPad 的 test-without-building 选择两个用例却只报告执行一个；没有把命令成功当成新增专项通过。针对 iPad 重新编译并单独执行资料专项，以实际用例开始/结束和耗时为凭据，results.json 明确每项证据归属。
9. macOS Swift 几何测试需显式导入 CoreGraphics；没有将缺少扩展方法的解释器报错误当成 iOS 构建失败。补齐导入后相同生产布局代码通过 294 条检查。

## 使用与边界

Mac 上打开 ios/CharacterPrototype.xcworkspace，CharacterHost scheme，选 iPhone 17 或 iPad Pro 11 英寸 M4 模拟器运行；旋转 Simulator 即可体验，竖屏仍保留原底部渐变聊天。用户设备需关闭系统方向锁才能自动旋转。

按用户外出期间的安排，本轮不连接手机、不安装真机。版本号 0.12.0 / 21 为当前模拟器版本，Unity 已重导出至 framingProtocol 7；后续真机仍需重新生成/编译匹配当前角色与场景的 device 工程。本轮未测真机持续 60/120 FPS、温度或真实键盘外设。

复现主流程：XCTest 的 LandscapeFlowTests/testConversationKeyboardPosturesAndRotatingEditors；登录/舞台流程：LandscapeFlowTests/testLandscapeHomeLoginAndExplorer。几何检查把 AdaptiveViewerLayout.swift 与 scripts/tests/AdaptiveLayoutTests.swift 合并后用系统 Swift 解释器运行，测试的是实际生产计算器。
