# 栩屿 v0.4 · 对话取景验收

本轮将模型查看改为适合聊天的受限取景。仅使用真实 Unity 引擎与 iOS 模拟器，不更新真机。

## 交付规则

- 右上角「取景」：对话近景／全身互动，大小 90%–110%，左右各 20°。支持滑块及精确端点，角度可一键正面。
- 位置自动居中，固定柔和俯角。拖拽和双指不操控镜头，也不应误触头部；头部轻触仍会摇头。
- 按角色保存。完成提交，取消或下拉关闭撤销预览；恢复推荐也是先预览后提交。
- 大动作临时全身，结束恢复个人取景。键盘和横竖屏适配不覆盖偏好。
- 新增逐动作包围盒，构建时 30 Hz 烘焙，运行时读取；新增动作必须同时生成取景数据。

## 已处理问题

1. 静止模型的包围盒不足以覆盖 Luma 挥手，第一次独立采样出现 x=-0.13 出界。没有放宽断言，改成逐动作包围盒后全部通过。
2. Unity 新验证脚本导入缓存未纳入程序集；验证类移入已有 BuildIos.cs 后编译恢复。一次 CLI 超时实际已完成写入，通过读取源码确认后继续，未重复修改。
3. 首次原生构建正确拒绝旧 v3 引擎。新版导出成功后再完成完整构建。
4. 首轮 XCTest 滑块请求最左端实际停在 -18°；增加用户可用的明确端点快捷选择，修正后完整流程通过。首次失败保存在 `.local/checks/Framing-Phone-1.xcresult`。
5. iPad 初次功能通过后，截图显示竖屏角色偏小；改为竖屏上下分区并加入宽高比断言，最终新布局通过。中间一轮触发原有 15 tick 加载保护，增加至 30 tick 后通过；底层冷启动迟滞原因尚未完整定位，超时出口另做受控验证。
6. 键盘空状态说明曾被压缩，改为单行提示。SwiftUI 父容器 ID 传播使子元素测试查找失败，改用实际可见文案并保留几何位置断言。
7. Luma 自动化普通 `.tap()` 首次成功、后续一次没有触发头部事件。失败录像中坐标仍在头部。补测采用明确 0.12 秒短按（运行时上限 0.4 秒），真实 headTapCount 增加后继续验证键盘与回复，最终通过；没有删除命中断言或注入假动作。Unity 逐帧读取触摸可能受极短自动化事件影响，这只是推测，尚未证明该次漏触根因；未因此修改运行时触摸规则。

完整结果、原始 bundle 路径和限制见 [acceptance.json](acceptance.json)。保留所有失败记录，后续仍需在真机上复验不同轻触速度、冷启动和长时性能。

## 验证边界

投影测试覆盖烘焙网格采样，未把运行时头发次级动力学纳入数学证明。近景有意允许下半身出画。当前结果验证功能与构图，不构成真机 60/120 FPS 承诺；本轮未重做语音模型性能基准。

源码校验未发现手写代码空白错误。Unity 官方序列化输出的空 `m_Name: ` 字段会触发普通 Git 尾空格检查；保持 Editor 生成格式，没有手改场景 YAML。
