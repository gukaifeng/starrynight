# 0.96 角色姿态、表现入口与下载管理

StarryNight 0.96.0 / 127 修复原作加法动画转换导致的待机横倒与躯干折叠，补齐独立开发者角色表现入口，并增加按角色删除已下载资源的管理页面。原始 VRChat 包、作者片段与控制选项保留；没有调用图片生成、对话或音色生成接口。

## 姿态根因与修复

Hikarun 的原作 Breathing 层每 2.5 秒呼吸后进入约 1 秒空状态。源 Humanoid 动画经采样成为绝对 Generic Transform 曲线，旧转换仍按 Additive 层播放；特别是空状态回写骨架默认旋转，导致参考姿态被再次叠加。旧测试中髋部偏转达到 87.72 度，头部移动约角色高度的 35.9%，表现为人物横倒、躯干折叠。问题位于宿主动画转换，不能归因于模型骨骼坏了。

`PortableAvatarControllerBuilder` 为加法用途单独构建相对曲线及 BlendTree，旋转相对首帧、位置扣首帧、缩放除首帧；每个加法图的所有骨路径在空状态与部分片段中也有明确的零运动锚点。Override 图、手动片段库仍使用原绝对动画。当前名册中 Hikarun、Koharu、Ramune 使用加法图，公共修复覆盖它们，并回归其余角色。

不能只设置 Additive reference pose 元数据：这不能修正当前 Generic 曲线。仅把呼吸曲线改为相对曲线也不够，空状态仍需锚点。重建后必须保存实际 prefab 的 controller 引用并验证 `layerCount > 0`；无效 controller 不播放动画会产生错误的“安全”结果。

`AvatarConversationPoseReview` 对名册全部 16 角色运行 443 个待机/AI 自动表现用例：每个角色待机 10 秒，Hikarun 30 秒；每个 `ai.automatic` 控件执行 2 秒。检查有限值、相对髋部旋转、按模型高度归一化的头部位移与躯干直立方向。

| Hikarun 待机指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 最大髋部偏转 | 87.720741° | 0.391671° |
| 最大头部位移 / 模型高度 | 0.35931045 | 0.00035532 |
| 最低直立方向点积 | 0.0452069 | 0.9999956 |
| 全名册检查失败数 | 1 / 443 | 0 / 443 |

私有证据：`.local/checks/pose-v096-before.json`、`pose-v096-all-after.json` 及对应日志。它们是 Editor CPU 骨骼求值，不是实际设备 FPS，也不代表穷举所有原作特殊姿势、服装与控制组合。

## 开发者表现页面

应用级开发者页面原先缺少实时 `performanceState` 时，“角色表现”入口只试图打开会话，不能打开目录，某些调用路径没有有效跳转。因此现在独立展示角色表现与原作片段目录，并明确提供“进入预览”；已有会话使用真实状态执行表现。资源未同步时提供同步提示，不把缺失状态当作无响应按钮。

`CharacterResourcesAndDeveloperTests` 在原生生产 UI 中逐个打开 16 个角色的表现目录。首组选项可能全为 slider，实际 Unity 预览测试同时支持 slider 和按钮；slider 检查真实参数变化，不能依赖 XCTest 指定的拖动比例与物理 thumb 位置完全一致。

`Pose-v096-r5.xcresult` 在真实 Unity iPhone 17 模拟器中通过 13 个内置角色的会话进入、表现页打开、按钮/滑杆驱动参数、恢复默认与页面关闭检查。Hikarun 额外保留连续待机截图，跨原作呼吸/空状态周期保持直立。此前测试先因错误假定第一组一定有按钮、随后因 XCTest 滑杆实际值偏离请求比例而失败；核对运行事件确认参数已改变后修正测试，未放宽产品动画安全阈值。

## 角色资源管理

入口：我的 → 设置 → 存储与缓存 → 角色资源。显示当前账户、本平台每个下载角色的模型、媒体、旧版本和未完成下载的合计字节数、就绪状态或下载进度，支持二次确认删除。不把随 App 内置的 13 角色显示为可释放的独立下载；它们由 App 更新管理。

删除顺序：取消并等待该角色下载 → 阻止新下载/恢复与会话打开 → 清理保留会话的运行状态 → 等待 Unity 原生异步加载结束 → 切换到其他已加载或内置角色 → 销毁对象并卸载 Bundle → 收到桥接确认 → 移走并删除该账户/角色/平台的全部下载目录 → 注销对应封面、首次问候、背景等本地注册。运行资源未能释放时保留磁盘数据并提示重试，不先删文件后留下持有旧资源的 Unity 对象。

删除不会清空聊天、记忆、订阅或账户资料。重新进入角色时走既有校验下载流程。目录键包含账户、角色和平台；文件扫描跳过内部符号链接，删除拒绝角色目录本身为符号链接。其他角色、其他账户与其他平台不会被删除。

实际云端复测还发现旧安装检查的迟到结果：恢复上次角色期间离开对话页后，旧升级提示仍会弹到发现页之上，遮住搜索和卡片。`ViewerCoordinator` 为下载检查加入请求标识，在导航、账户切换、请求登录和角色选择时使旧请求失效；异步恢复完成后再次核对账户与请求，避免旧任务打开弹窗或会话。该问题不能仅靠测试多等几秒掩盖。

`CharacterResourceChecks` 在隔离的 iOS 文件目录执行 14 项检查，包括旧版本和 partial 统计、账户/平台隔离、目录移除、重复删除、恢复指针、重新安装布局、符号链接拒绝，以及聊天数据字节不变。`Native-Resources-v096-r2.xcresult` 的 3 项测试通过，另包含全名册目录与管理入口/空态 UI。

`DownloadManager-v096-r6.xcresult` 使用私有合成账户与实际 OSS 下载，147.804 秒通过：Fiona、Mizuki、Ramune 的新包分别加载并打开可操作的表现页；在我的/存储与缓存中显示真实占用，取消删除保留 Ramune，确认删除后完成当前运行角色的卸载及文件删除，管理列表移除该项，再次下载成功进入会话并重新计入资源占用。测试未启用在线 AI，保留了三角色画面与删除后的管理页截图在私有 xcresult 中。

早期集成测试错误地要求登录后一定出现聊天输入框，未考虑最后角色需要升级下载；随后实际截图证明迟到的 Ramune 弹窗阻挡发现页，修复上方的过期请求问题后通过。所有未通过/中断记录仍留在私有目录，未把它们作为已通过验证。当前 13 内置与 3 下载角色都已在实际 Unity 模拟器打开可操作的表现页面。

## 构建与设备

三个下载角色（Fiona、Mizuki、Ramune）分别重建 ios / ios-simulator 自包含 Bundle 并发布不可变 release 3，旧 release 保留。54 项对象使用现有服务端官方 OSS SDK 工具验证，16 个商店目录与 6 个平台 release 原子更新。正常 TLS 校验的公共 API 返回两平台上述角色的 release_version 全部为 3；私有记录 `.local/checks/oss-v096-before.json`、`oss-v096-after.json`。服务器 API/AI 进程与数据结构没有变更。

Unity 真机与模拟器导出均通过角色目录/集合完整性检查；0.96.0 / 127 的主要修复版本成功安装到 iPhone 17。第一次安装 60 秒超时，延长安装等待后成功；随后远程启动被手机锁屏拒绝。之后在 OSS 集成验证中补充了上述迟到弹窗请求校验，最终代码再次通过已签名 Release 构建（`host-device-20261003-113928.log`），但最终重新安装在建立设备隧道后 60 秒超时（`install-v096-final.json`）。因此手机上先前安装已确认，最后这项补充修复安装尚未确认；不能把最终签名包准备就绪描述为最终版本已经安装。

用户已要求手机不可用时继续模拟器验证，故没有等待手机、要求再次解锁或反复尝试连接。最终完整代码通过上述真实 Unity 模拟器验证，Hikarun 在连续呼吸/空状态周期与首次问候表情间保持正常直立。本轮没有在手机上运行全角色姿态或 FPS 测试。

修复方法已写入项目技能 `vrchat-character-import/references/natural-idle.md`，供之后的模型导入复用。
