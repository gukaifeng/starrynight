# 「我的」页面与昵称、称呼分离

日期：2026-10-03。此次修改仅涉及客户端账户界面和验证工具，服务端协议、角色资源和用户已有数据不变。

## 设计结果

- 页面保留深色月白主题，以头像、昵称和少量细分线建立层次，移除原先统计区与工具区的大块容器。页面本身有不透明底色，避免下层角色画面透出。
- 个人资料头部为 64 pt 圆形头像、22 pt 昵称、10.5 pt 星夜号。星夜号使用低对比度等宽数字，保持完整显示，但降低视觉权重；设置图标无圆形底板，点击区域仍为 44 pt。
- 订阅、关注、角色、聊过四项统一为数字在上、说明在下。个人简介、菜单和辅助说明分别使用 13、14、11 pt，避免所有文字竞争同一层级。
- 资料区下方单独设置「AI 对我的称呼」入口，显示当前全局默认称呼，并说明「仅用于聊天，与昵称独立」。存储、隐私、帮助继续使用原有功能入口。
- 昵称编辑字段明确标注「昵称」，注册页也改用「昵称」，避免将账号资料与角色称呼混为一谈。简体中文、繁体中文和英文补齐新增说明。

## 数据边界与兼容性

| 内容 | 权威字段或来源 | 修改入口与用途 |
| --- | --- | --- |
| 用户昵称 | 账户 `user.displayName`，对应服务端资料 `display_name` | 点击头像／昵称进入账户，再编辑资料；用于个人资料展示 |
| 星夜号 | 账户 `user.publicNumber` | 自动分配、当前不可编辑；沿用现有 `xy100000001` 起始编号规则 |
| AI 默认称呼 | `CompanionStore.defaultNickname`，账户设置 `default_nickname` | 「AI 对我的称呼」；用于没有专属称呼的角色 |
| 角色专属称呼 | 各角色 `TogetherPreferences.nickname` | 同一称呼页面内编辑；优先于全局默认称呼 |
| 作者名 | 作者记录 | 作者主页编辑，不再作为本地体验账号昵称的后备来源 |

昵称修改不会修改默认称呼，默认称呼修改不会改账户昵称。实际聊天仍使用「角色专属称呼 → 全局默认称呼 → 自然称呼」的原有优先级，不从用户昵称推导。资料编辑原有防抖自动保存与关闭时提交保留，无新增保存按钮。服务端原本已分别存储这些字段，故无需迁移或重置现有数据。

## 验证与问题处理

使用 iPhone 17 模拟器运行原生 SwiftUI 界面夹具，共 5 项测试全部通过，0 失败：

1. 账户资料自动保存、星夜号不可修改、系统照片选择入口。
2. 全局称呼持久化、角色专属称呼优先、清空专属称呼后继承默认称呼。
3. 将 AI 称呼设为 `Sky`、账户昵称改为 `Nova` 后，两者互不覆盖，重新打开仍正确。
4. 英文布局、游客页面与登录入口可用。
5. 账户、设置、自己创建的角色及作者子页面导航保留，作者改名不影响账户昵称。
