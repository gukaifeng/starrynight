## 关键处理

1. **先通用能力，再分批验证。** 新的控制图、菜单、滑杆、材质与物理数据不写进角色专属 UI。旧 XCP 继续读旧路径，新包以 required capability 选择新执行器；所有已发布角色纳入回归。
2. **避免一次加载全部角色。** 原先场景包含全部模型实例；现在默认实例随初始场景，其他编译 Prefab 按需加载，最多两个实例驻留。测试连续切换五次，覆盖新旧角色和初始角色被淘汰后重新加载。
3. **Unity YAML 的陷阱。** YAML 1.1 会把 `ON/OFF` 状态名读成布尔值，数字形式 mask 丢前导零；采用专用 SafeLoader 和精确字段读取。可达图剪枝去除历史孤儿节点，真实缺动画仍失败。
4. **手势误改全身。** Humanoid 手指片段的采样曾写入 Hips，导致模型沉入地面。按原作肌肉曲线的实际作用域生成轨道，手势保持指骨范围；只包含 Animator 参数的动画不采样全身。
5. **默认姿态与衣袖。** 无原作站姿时明确使用宿主站立适配；近景检查发现大衣袖包住腕部后，调整中性手臂角度，保留源 mesh 与动画不变。
6. **lilToon Editor 导入。** 上游 assembly 不自动引用，材质初始化采用明确的已知方法签名。Unity 在场景/缩略图完成后曾于 URP shader reload 原生崩溃；保留失败日志，在已有成功标记且 Editor 退出后，启动新进程执行已保存场景导出。恢复导出通过，不把原崩溃隐藏成首次成功。
7. **发现页真实崩溃。** Python 集合校验已支持真实 AI 音色标识，但 Swift 仍仅接受旧离线引擎，导致新角色集合校验触发 precondition。已同时接受旧存档标识和当前 AI 引擎，四角色切换测试重跑通过。
8. **首次 UI 测试输入丢字。** 大量并发编译时 XCTest 输入 `saved` 出现 `saed`。保持原断言，不放宽数据保留要求，待编译结束重跑；结果在下表记录。
9. **恢复与隐私。** 生成的 ViewerScene 含角色 Prefab 覆盖，不再公开跟踪；本地保留，`BuildIos.Setup` 可恢复。原包、转换模型、贴图、截图、完整采样及密钥继续留在忽略目录。
