# 导入角色待机、眨眼与衣发物理差异：静态诊断

日期：2026-10-02。用户反馈部分未接语音的角色完全静止，部分会眨眼，部分拖转时衣发有物理反应。本次核对当前发布名册中的 41 个本机 XCP 包、对应私有转换中间数据与客户端运行代码。没有重建 App、修改角色包或执行真机测试；手机已安装版本可能与本机内容不同。

这是重新导入前的诊断快照，以下“当前”统计指该次检查时的包，不代表后续修正版。30 个新角色的眨眼和衣发物理已重新导入，11 个完整对话角色保留原包；后续构建和验证状态见[本轮导入记录](2026-10-02-model-only-import-progress.md)。

后续按用户确认的“原包具备眨眼和衣发物理；待机可由宿主适配”标准完成 41 个原压缩包逐角色核查，结论为全部保留，见[原包核查与保留决定](2026-10-02-original-basic-motion-roster-review.md)。Shizuku 已确认同原包完整本体含 12 个启用物理链组件，当前提取为 0 不代表源包缺失。

## 结论

未接入语音不是静止、缺少眨眼或衣发物理的直接原因。基础待机、眼睑调度和二次运动在本地运行，分别需要自己的资产、绑定与驱动。当前角色之间的差异主要来自导入与适配完成程度；不能凭 App 中没有效果判断源角色不支持。

当前 21 个 `visualOnly` 外观预览包全部没有二次运动骨段及碰撞体。这 21 个角色在私有转换中间目录中都有非空的二次运动骨段，但预览封包流程显式清空了这些数据，同时移除了原作控制器及其动作清单。这是当前预览策略导致的能力丢失，不是源包不具备物理配置。原始数据没有因此被删除。

## 三种效果分别为何出现差异

### 待机与呼吸

批次转换优先选择作者的 `stand_still` / `Idle` 片段；没有匹配的独立站立片段时，使用明确标注的宿主站姿。宿主站姿生成的两个时间关键帧数值相同，因此播放循环仍可保持静止。作者片段名包含 Idle 也不能证明它有可见呼吸，仍需检查曲线和最终骨骼。

旧琪宝、豆日向走 `prepare_vrchat_characters.py`，额外调用 `vrchat_autonomy.append_visible_idle` 和 `configure_wind`：基于审查过的原始上身曲线增加可见呼吸，并配置局部衣发环境风。批次角色没有自动获得这套已为两位角色审查的适配。呼吸、自动眨眼、静止时环境风以及拖转惯性需分别验证。

### 自动眨眼

眨眼需要可驱动的眼睑形变或骨骼，以及时序/控制逻辑。VRChat 本身也提供模拟眼睛和眼睑的运行能力，作者还可通过动画控制器接管；参见 [VRChat Animator Tracking Control](https://creators.vrchat.com/avatars/state-behaviors/#animator-tracking-control)。把模型导入另一个宿主不会自动附带平台的模拟行为。

当前批次封包的宿主自动眨眼识别范围较保守：优先使用 Descriptor 的眼睑索引，再使用唯一的规范 `vrc.blink` / `vrc_blink` 形变。完整控制包检测到作者眨眼层时避免再叠加宿主调度；预览包已移除控制器，只能依赖可识别的眼睑绑定。非规范命名、左右独立眼睑、骨骼眼睑、控制图逻辑或眼睑与口型复用，都可能需要额外适配。

例如 Azuki 的原转换控制器包含 `BLINK` 层；预览包控制器为空，且没有宿主眨眼绑定。这说明眨眼相关源逻辑没有在当前预览交付中恢复，不能据此宣布作者没有提供眨眼能力。该源层的完整视觉行为本次未运行验证。

有宿主绑定也需验证运行优先级。`CharacterAutonomy` 会尊重当前表情、睡眠和控制图对眼睑的占用；故绑定存在不保证任意状态下持续自动眨眼。

### 拖转后的衣发摆动

源 PhysBone 等配置提供骨链、参数和碰撞关系；[官方 PhysBones 文档](https://creators.vrchat.com/common-components/physbones/)说明其适用于头发、衣物、尾巴等二次运动。星夜当前使用自己的有界弹簧近似求解器，不承诺与 VRChat 求解器数值或视觉完全一致，也不是任意布料模拟。

Unity 制作侧把 `secondary-motion.json` 的骨段与碰撞体绑定到实际 Transform。运行侧 `AvatarSecondaryMotion` 根据世界坐标中的骨段端点变化计算惯性与回弹；拖转角色可产生滞后摆动。骨段为空时没有可供求解的对象，不能仅凭 `core.secondary-motion@2` 能力声明认为物理已启用。摆动幅度还会受骨链、参数、约束与是否有实际根节点运动影响。

## 转换器后续要求

每项基础能力分别报告“源声明/检测结果 → 已转换内容 → 已交付内容 → 宿主启用状态 → 降级原因”，避免一个角色级“导入成功”掩盖效果丢失。自然待机、自动眨眼及拖转衣发物理应与声音/对话配置独立验收。

对确认有原作能力的角色优先补齐映射与驱动；缺少可独立使用的待机时再提供明确的星夜待机适配。预览降级应尽量按能力处理，不能因为某个换装、材质或控制图未适配而默认清空已经可以安全绑定的全部物理。恢复每项能力仍需做骨骼/形变、碰撞和移动端性能检查，本次没有实施这些修改。
