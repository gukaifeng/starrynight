## 自动化检查的修正

A 轮的连续滑块检查仍要求虚拟拖动恰好落在 25%；原生控件实际落在约 31.2%，按新的连续语义正确保存了这一小数，而非跳到旧档位。B 轮尝试从 Unity 诊断快照读取当前氛围值，但该快照并非原生滑块的实时数据，仍含旧值 0.5；实际测试档案已保存为 0。C 轮确认精确像素拖动容差不足。检查分别修正为：对系统拖动目标采用合理位置容差、单独断言不吸附四分之一档位、重开后值一致，并用磁盘往返检查验证精确小数。产品未为了通过检查重新引入档位。

Apple 的 [`adjust(toNormalizedSliderPosition:)` 文档](https://developer.apple.com/documentation/xcuiautomation/xcuielement/adjust%28tonormalizedsliderposition%3A%29)明确说明该调整尽力接近目标，不保证绝对精度。D 轮最终 `TEST SUCCEEDED`。A/B/C 失败记录保留，不能描述成第一轮全部通过。

结果包为 `ContinuousAtmosphere-{A,B,C,D}.xcresult`；D 轮附件中有连续滑块和横竖屏快捷回复截图。构建无 Unity 资产改动，继续复用 v14。
