客户端 StarryNight 0.101.0 / 132。云端实现位于独立 `../starrynight-server` 仓库。

## 真实原因与处理

Shinano 最近失败的直接原因是服务商规划结果 `STRUCTURE_INVALID`，不是手机断网。原始流候选重复后进入内部改写，两个角色规划结果都返回了错误层级的可选字段；第二次保留的原始 JSON 仅有根对象 extra_forbidden 错误。服务端现在独立适配可选装饰，不让它破坏有效台词，外部接口和台词内容仍严格校验。云端对真实失败样本重新校验已通过，台词完全保留，无额外付费调用。细节和部署证据见服务端 docs/reply-recovery-2026-10-03.md。

Meiyun 最近的服务端轮次均完成，其中包含预准备命中与流式即时生成；保留的完整脚本已有台词和正确的 0 起始锚点。手机不可用，无法重现原轮次逐帧状态，因此不能断言是某一帧的计时或某一个补丁所致。客户端旧显示路径取 `parts.prefix`，心理/动作说明与台词共用音频进度；后续补丁、未来锚点或顺序变化可阻挡后面的已收到台词。现在将两种责任分开：

- 已收到的台词分段立即可读，不依赖音频播放结束。
- 心理和动作描写继续按各自阶段显示，不进入 TTS。历史和已结束播放保持完整。
- 即使早期或旧版 parts 只有说明，仍直接显示独立 dialogue 的台词，翻译分段也补入同一个真实台词字段。
- 保留原始 part 索引，避免分阶段隐藏时破坏翻译缓存的 ID。
- 非 prefix 的心理/动作阶段变化也更新 revision，使布局和自动滚动观察到新增内容。

## 发送与恢复约定

发送后清空原输入；成功或失败的文字都在原气泡中。后来输入的新草稿不受失败和重发影响。失败气泡左侧为小型红色感叹号，点击给出完整原因与重发确认；重发复用原气泡、请求编号和完整请求体，不重复增加用户消息或重复记访客轮次。旧消息没有这些可选字段仍正常解码。

保存中断的请求体仅用于恢复，成功后清除，避免每条历史永久复制整份上下文。重新建立会话时，遗留 sending 状态改为可重发的失败状态；主动打断已收到合法回复的播放不会误报用户消息失败。

临时繁忙、断流、超时及可恢复格式异常最多三次传输尝试；等待旧任务释放采用更长退避。服务端已经有结果时直接重放结果和原缓存语音，未发布且已中断的请求可恢复；不改变请求 ID 来绕过重复执行保护。服务器重启恢复不主动调用模型。自动重试失败后才显示具体原因，区分设备无网络、连接超时/中断、异常数据、HTTP 状态、账户认证及服务商权限。可选表现警告只写开发记录，不显示成核心聊天失败。

服务商认证、欠费、持续故障等仍可能无法恢复，必须准确说明而不能伪称用户断网。重试有限；未收到结果的调用仍可能被服务商计费，不能保证这种调用免费。测试使用合成 SSE、真实 AVAudioEngine 与 mock 服务商，不调用付费模型。
