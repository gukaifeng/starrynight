# v0.8.0：三种入口、同一个测试账号

## 本轮交付

提供可实际操作的微信、邮箱和手机号登录界面，以及“我的账号”、退出登录与会话恢复。当前没有服务端、微信开放平台应用或验证码服务，所有入口明确标注本地测试；不发送网络请求，不打开微信，不发送短信／邮件，不请求通讯录或手机号权限。

默认选中微信，点击即可进入；邮箱 `hello@xiaoban.example`、手机号 `13800000000`、验证码 `123456` 预先填好。点击获取验证码仅回填固定演示码，并明确提示没有发送短信／邮件。错误输入有可恢复的提示和“恢复测试信息”，不会将任意输入注册为新账号。

三个入口统一映射到“小伴体验者” `XB-000001`。这是客户端演示身份，不能用于正式鉴权。

## 视觉与交互

沿用小伴的深绿 #274A43、暖白 #F7F5F0、浅玉绿 #B8D5C5、次级绿 #5B7168，避免新登录页与既有产品割裂。标题使用可随系统字号缩放的圆润字体，表单使用系统正文，账号ID使用等宽小字。品牌中的两个伙伴作为欢迎图，三种方式在同一胶囊选择栏切换，表单淡入淡出并平滑调整高度。

手机使用单列：品牌／欢迎 → 登录方式 → 默认填好的资料 → 登录；iPad使用欢迎与表单双列，横竖屏都可见。正常字号下默认登录按钮无需滚动即可点到，较大字体和键盘出现时保留可滚动空间，隐藏滚动条。遵循减少动态效果设置。

首页新增“我的账号”入口，显示同一ID、三种测试关联方式和本次登录方式。退出不会删除角色设定、记忆或聊天文件。重新进入登录页会恢复预填内容。

## 状态与资料

- `AccountStore` 是原生登录状态的唯一来源；`AppRootView` 决定显示登录还是首页。查看器的入口也检查登录状态，未登录时不启动Unity。
- 使用同一固定内部账号ID，不为邮箱、微信、手机号分别创建存档；既有本机伴侣资料直接延续。
- 持久会话仅保存测试账号ID和最后登录方式；不保存用户输入、验证码或伪造的OAuth Token。退出删除会话记录，保留伴侣资料。
- 会话损坏／账号ID不匹配时回到登录；不自动进入未知账号。
- 既有UI测试在DEBUG下使用隔离QA会话；新登录测试显式经过真实登录页。QA键值与普通用户会话分开，Release不存在UI测试绕过入口。

## 后续接服务端

继续使用服务端内部accountID，将经过服务端验证的微信身份、邮箱和手机号关联为登录凭据。微信授权回调／验证码校验、账号关联及冲突处理、真实会话和云端资料均属于后续工作；不能按客户端传入的邮箱文字或手机号自动合并真实用户。真实令牌不沿用当前演示UserDefaults方案。

本轮使用 [frontend-design](/Users/gukaifeng/.codex/skills/frontend-design/SKILL.md) 的设计方法及本机保存的 Paul Hudson `swiftui-pro` 做局部复查；复用现有品牌资产，不增加SDK或新的图片依赖。输入类型与自动填充参考 [Apple 文本输入指南](https://developer.apple.com/design/human-interface-guidelines/text-fields)和[一次性验证码类型](https://developer.apple.com/documentation/uikit/uitextcontenttype/onetimecode)。
