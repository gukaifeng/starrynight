# 星夜 0.23 · 稳定入场、一体语音气泡与头顶互动

本轮遵循新的加载偏好：更换角色时可以先展示完整、有设计感的加载动画，准备好再显示。保留同一会话跨菜单的直接恢复。范围为手机版，未增加 iPad 测试。

## 画面入场

白闪有明确的时序与视觉来源：宿主在 `modelSelected` 后就显示 Unity 窗口，外观、背景与灯光却在此后才下发；运行时先绑定默认日光房，再切换个人空间，`EnvironmentDirector.OnGUI` 绘制的浅白遮罩直接露给用户。

新的顺序：

1. 原生壳层立即出现月白星月、细椭圆轨道、柔和呼吸光与角色名字，保留底栏。没有假进度或头像加载卡。减弱动态时静止。
2. 宿主窗口临时高于 Unity 的窗口；Unity 在下面正常渲染，冷启动即使自行创建/激活窗口，也不会越过加载画面。
3. 模型选择完成后，仍在遮挡状态下应用角色外观、背景、灯光、参数、姿势和最终取景。仅此阶段空间设置使用 `immediate`，不会从默认日光房绕一圈过渡。
4. `prepareReveal` 放在全部配置之后。运行时检查环境切换、姿势与镜头已稳定，在连续三个 `WaitForEndOfFrame` 后回报 `presentationReady`。
5. 宿主核对 `presentationId`、`modelId`、`requestId` 及帧数，再进行0.42秒窗口淡入。加载画面一直留在下面，直到淡入结束。新角色入场最短0.65秒，采用单调时钟；较慢加载不会额外再等待0.65秒。

加载中取消、换角色、进入后台或过期回调不能揭开错误场景；后台暂停后继续原有确认过程。30秒前台超时仍提供可返回的错误状态。已保留的同一个角色回到首页不执行这条加载链，不重建会话、重设镜头或丢草稿。

用户实时更换空间仍用柔和过渡，但遮罩改成接近黑色的夜幕。新宿主要求 `immersionRevision: 2` 导出，构建脚本拒绝旧框架，避免原生等待旧引擎永远不会发送的事件。模型和环境包标准未变。

## 语音气泡与箭头

- AI 回复只绘制一个 `AssistantBubbleShape` 背景和轮廓，左上角圆滑抬起，收纳播放/停止与时长，再以贝塞尔曲线接入正文上边缘。语音标签不再绘制独立 Capsule。
- 保持10pt简写时长、8pt播放符号和44pt触碰高度。播放中的局部明暗呼吸与微光保留，不增加音柱；估算时长带“约”，实际合成后替换为音频时长。气泡与文字仍受整个聊天区域的透明渐隐约束。
- 双下箭头从17pt缩至13pt，不透明度由52%～90%改成28%～52%，保持原有0.95秒缓慢上下呼吸。减弱动态时固定42%。点击区域仍44×44pt，下移14pt的浮层不参与聊天和输入框布局。
- App内星月PDF改为透明页面，避免加载光晕中央出现方形底块；桌面图标仍为不透明PNG，SVG原始几何不变。

## 头部触碰

基线在 iPhone 17 模拟器复现：点击面部中央可以命中并播放 `No`；在同一角色头顶/刘海区域点击没有命中。原来的 `headRenderer` 仅含面部表面，而头发可能属于其他网格。

保留动态蒙皮网格的精确射线检测；未命中时使用由当前面部包围盒计算的紧凑椭球，主要向头顶扩展，跟随模型和动画的位置。它不包含长双马尾、胸部或整个角色包围盒。单指轻点允许0.6秒和屏幕短边2.6%的轻微移动；双指手势以及明确拖动仍取消点击候选。取景锁只阻止拖转和缩放，不阻止头部互动。

验证同时要求 `headTapped` 和实际的 `actionStarted` 增加，避免只检查触摸事件却没有摇头。四个角色都检查了这条链，初音额外检查头顶和胸部负例。

## 构建处理

首轮 Unity 导出在编辑器原生 `SRPBatcherShaderData` / URP ShaderBuildPreprocessor 保存着色器数据时发生 SIGSEGV；C# 编译、Setup 与缩略图生成已成功。保留崩溃日志，增加 `ExportPreparedSimulator` / `ExportPreparedDevice`，复用已保存场景但仍执行完整 `Validate`，通过 Unity CLI 的 `-nographics` 完成导出。此路径不能用于尚未生成场景或更新美术资源的首次构建；不关闭App内Metal、阴影或画质设置。

`-nographics` 的含义依据 [Unity 官方命令行文档](https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/command-line-arguments/editor)。最后仍必须在真正的模拟器/设备渲染界面检查，不能把无图形导出成功当作视觉验收。
