## 数据与职责

- `services/character_ai/character_scenarios.json`：版本化角色覆盖与场景定义。`profile` 覆盖原始对话设定，`scenarios` 绑定到角色 ID；不修改用户提供的模型档案。
- `profiles.py`：先装载原有人设，再应用覆盖。`profile_revision` 和场景完整内容进入现有预生成缓存指纹，因此旧人设候选不再被新会话采用；已发生的聊天和用户确认的记忆不清空。
- `roleplay.py`：角色语言、场景白名单、当前场景上下文与英文检查。跨角色使用场景 ID 被拒绝。未选择场景时显式标记日常状态，防止旧故事自行继续。
- `public_profiles.py`：只公开简介、喜好、语气、语种、版本及场景的 ID/标题/简介/分类/图标；`premise`、`progression`、`tension`、秘密、完整提示词仍只在测试检查工具可见。
- 本机服务部署脚本同步新数据文件。App 内置同一份公开资料，联网资料版本不低于内置版本才接受，避免新包被旧服务覆盖回旧简介。

只有当前选中的场景进入规划上下文，不把同一角色的所有剧情正文一起发送。现有 API 的 `scene` 增加 `story_id`、`story_revision`，不改变桥接或模型资源协议。旧客户端没有这些键时继续日常模式；三个旧故事 ID 仍接受。

## 语言与声音

青柠和望的固定语言为英语，普通聊天、首次见面、再次进入、待机、手势反应、剧情与智能回复共用语言约束。中文输入仍能理解，回复用更简单的英语解释，不附中文翻译。用户界面及剧情选择说明仍为中文。

规则在规划系统消息末尾再次声明，优先于既有中文样例。收到混入中文的可见台词或心声时，在原有有界修订预算内重写，未通过的草稿不进入聊天记录或 TTS，不增加无上限重试。

现有音色 ID 保留；TTS 和 ASR 的 `language_hints` 按角色取 `en` / `zh`。没有重新付费设计音色。厂商依据：

- [Qwen-Audio-TTS HTTP API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api) 的目标语言参数。
- [Fun-ASR-Realtime 客户端事件](https://help.aliyun.com/zh/model-studio/fun-asr-client-events) 的识别语言参数，只设置一个语言值。

服务端和 Swift 客户端均支持最多 12 词、96 字符的英语第一人称心声，并继续剔除回复策略等控制文字。英文切分按词边界，估计语音时长按词数。原模型动作说明目前是中文；英语角色继续执行动作、显示英文心声，但不拼接中文素材旁白，也不为翻译旁白新增一次模型调用。

智能回复保留快速模型和一组预生成机制。新增语种约束及场景上下文，未选择的分支仍不进历史；修复 `story` 触发不接受智能回复缓存的问题，剧情里的选择也能接续已准备的答案。候选不能凭空宣称用户的职业、住处和经历；这是生成约束，不声称小模型已经能完美识别所有不当假设。

## App 入口与续聊

发现页可按“恋爱 / 英语 / 剧情”筛选，也可搜索角色或剧情名字。公开简介随人设更新。

进入角色会话 → 点击左上角色胶囊 → **相处与剧情** → **故事**。这里仅显示该角色的专属场景，英语角色标 `ENGLISH ONLY`。选择后所有后续请求携带场景标识；“回到日常”取消当前生成与旧智能候选，再切回普通相处，保留输入草稿、聊天和故事记录。再次选择已有场景发送继续情境的意图，不重复发送首次开场要求；显式重开才增加 revision。

用户和 AI 的新剧情消息都附本机 `storyID`。故事里的虚构事件不自动成为长期用户事实。进展由实际对话承接，当前没有另建长期章节摘要数据库；很久以前的具体剧情细节仍受既有上下文窗口和确认记忆的限制。

## 调整与回退

可只修改 `character_scenarios.json` 中一个角色的 `profile` 或情境，并递增修订号；重启本机 AI 服务、重新生成公开资料即可。删除某角色的覆盖即可恢复其基础设定与通用故事。若移除已发布场景，应先保留 ID 的兼容映射，避免用户的 activeStoryID 变为不可用；不能直接删除原始模型或聊天库。公共投影生成命令：`python3 scripts/generate_character_public_profiles.py`。
