# 二次元立绘角色与近景陪伴

## 目标与美术选择

这一版以角色本身的轮廓、脸部、衣服层次和细腻待机为重点。选用不同于早期 Vita、Shino、Fumiriya 的新角色，让手机里的角色具备近景立绘的亲近感，同时保持真正的三维视差、阴影、互动和视线响应。吸引力通过神态、服装和有节奏的动作表达，不用夸张身体摆动代替自然度。

候选经过原作者来源、原始预览和技术数据筛选。优先接入名古屋工业大学的 Uka（显示名优可），并为用户的个人原型准备 Nitral 的 Velara（维拉）、Onyx（安宁）。Uka 的衣料层次、袖口、领饰和发束是实际三维结构；后两款为成熟风格的女性 VRoid 衍生模型，有较细的脸部、虹彩、眼镜与头发材质。不能把素材来源或表面细节数量等同于已经达到最终商业美术品质，最终以 App 内实际渲染验收。

| --- | --- | --- |
| 优可 / Uka | 锁定源实际 77,909 三角面、302 骨骼、216 morph；手机渲染 76,757 三角面，原始主要纹理 4096² | 完整衣料结构、柔和发束、面部与手部表情 |
| 维拉 / Velara | 38,884 三角面，24 材质，57 面部 morph | 小麦肤色、黑色短发、眼镜、暖色近景 |

## 集成和视觉约束

每个角色沿用独立角色包、集合、动作、语音、背景、作者归属和头像缓存，不能把新模型当成旧模型的共享换皮。角色第一次显示时就应使用稳定的会话取景，保留头顶空间，不在招呼、资料页或弹窗开合时重新缩放。已保存取景必须在角色切换后恢复。

静态轮廓要先通过原始材质与正常姿态审核，再加入待机。待机由轻微呼吸、重心上的缓慢上身调整、自然眨眼和有边界的发梢惯性组成；脚部和骨盆保持可解释的支撑关系，不让人物像整体漂浮的广告牌。头发、衣料受到的微风和惯性必须限幅，并继续使用头部、肩部、身体碰撞约束。不同角色的动作节奏和发型响应分别配置。

照明沿用可调整主光和阴影，脸部明暗、衣料折叠、发丝高光应服从同一光源关系。二次元材质可以使用风格化明暗层次，但不能用完全发光的表面掩盖几何，也不能把轮廓光铺满脸部。原图精度应配合移动端 mipmap、ASTC 与合理材质数量；不因为下载了 4K 纹理就声明画质或帧率已经达标。

VRM 1 角色的骨骼 bind/rest 旋转并非单位四元数。动作适配必须在源和目标骨骼基底之间转换，不能复制早期 VRM 0 的归一化假设。原始 MToon 1 的法线、阴影色、MatCap、轮廓和透明部件需要保留明确的对应关系。Uka 为 PMX 源，应沿用受控离线转换，而不是在 App 中引入整套编辑器依赖。

会话顶部胶囊只增加头像周围的内边距，保持圆形头像、文字层级、透明度和触摸区域的一致性；不要靠继续放大头像解决拥挤。

`IllustrationPortraitTests` 通过现有真实 UI 路径执行，未新增测试专用模型点击或状态伪造入口：

- 通过取景面板给优可设置非默认角度和大小，切到其他角色，确认相互隔离；经消息页回到优可，确认保存的取景恢复且资料页不改变它。

## 已知准备阶段错误处理

原作者 GitHub 压缩包下载在约 59 MB 时发生传输不完整，改为固定提交的逐文件原始下载并验证 Git blob 哈希后完成，不采用损坏压缩包。部分 VIPE 的公开 IPFS 预览地址返回 403 或 TLS 错误，缺乏足够可核对的视觉证据，因此没有只凭集合许可标签就选入。

## 转换中已解决的工程问题

- Uka 的原始 302 骨骼超出单个 skin 的 256 骨骼约束。保留完整骨架层级，但每个 renderer 仅上传实际加权的关节；Face/Hair/Body 分别为 16/112/89，无需删掉表情或头发控制骨。
- Uka 的袖子采用独立 IK 代理骨。移动端不运行 MMD IK，因此离线烘焙与手臂一致的 FK 轨道，避免抬手时手穿出僵硬的袖子。独立世界空间检查的最大袖口偏差为 0.0361 mm。
- 三个默认透明度为零的源表情贴层保持隐藏，避免 Toon cutout 把它们变成不透明的面部覆盖。
- Uka 的纹理只经 Unity TextureImporter 生成 ASTC 与 mipmap，GLB 去掉重复的内嵌 RGBA 纹理副本；标准模型数据从约 96 MB 降为约 7.5 MB，原始 4K PNG 细节保留。
- VRM 眼镜镜片使用透明深度关闭材质，眼线与发片使用 cutout，避免镜片挡住眼睛。
- 上肢动画与眼皮端点通过独立内容测试检查；发现的挥手手腕尖峰和片尾未闭合眨眼已修正，最终 3 项内容测试 PASS，具体数值见上面的验证记录。
