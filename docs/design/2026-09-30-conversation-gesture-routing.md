# v0.54.1：聊天区域与角色旋转的手势分流

## 用户可见规则

没有打开右上角位置编辑时，聊天区域也可以作为角色的临时旋转区：

| 初始落指位置 | 初始拖动方向 | 结果 |
|---|---|---|
| 消息之间、短气泡旁边等空白 | 任意单指方向 | 小幅旋转角色，松手平滑回到保存姿态 |
| 用户或 AI 消息气泡 | 明显横向 | 临时旋转角色，聊天列表保持位置 |
| 用户或 AI 消息气泡 | 纵向或偏纵向斜滑 | 原生聊天滚动，角色不转 |
| 播放、回到最近等按钮 | 点按 | 按钮原有操作 |
| 输入框 | 输入、选择和编辑 | 保留文本输入行为 |

依据最初落点与第一段有效位移决定归属，一次拖动中途不重新分流。横向开始后改成上下仍在转角色；竖向开始后改成左右仍由聊天处理。从空白开始越过气泡，也不会突然变成滚聊天。

临时旋转保持左右 ±18°、上下 ±8°，不保存偏转，不增加移动和缩放；第二根手指加入取消临时旋转并回弹。位置编辑保持原有自由水平旋转、±80° 俯仰和双指变换。

## 实现与关键取舍

1. `ConversationHitRegions` 在消息的全宽行容器**以内**测量真实气泡和按钮，用 `companionPanel` 坐标传到 UIKit。否则短气泡旁边的空白也会被误算成消息。滚动、键盘和布局变化随实际几何更新，不依赖固定屏幕坐标。顶部几乎完全透明的内容沿用原来的穿透阈值；播放按钮的 44 pt 点击区域优先保留。
2. 空白命中直接交给角色触摸层。消息命中仍留在聊天层；临时旋转识别器挂在二者共同的父视图，能观察最初的消息触摸。
3. 沿用 7 pt 起动阈值；消息上的 `abs(dx) > 1.2 * abs(dy)` 才认为横向。对角线附近优先聊天，减少翻记录时误转。判为竖向即让旋转识别器失败，交给 `UIScrollView` 保持原生滚动、惯性和回弹。
4. 用 UIKit 的动态失败依赖，让聊天滚动只等待这段方向判定；不替换滚动视图 delegate，不在拖动中反复关闭滚动，也不手工模拟聊天偏移。参考 Apple 的 [动态识别失败依赖](https://developer.apple.com/documentation/uikit/uigesturerecognizerdelegate/gesturerecognizer(_:shouldberequiredtofailby:)) 与 [require(toFail:)](https://developer.apple.com/documentation/uikit/uigesturerecognizer/require(tofail:))。
5. 原生到 Unity 的 `previewRotate` 增加可选布尔字段 `previewFromConversation`。只有已经分流到角色的聊天手势才设置该字段，使聊天空白即使不正对模型网格也能旋转；直接触摸场景仍要求命中模型。令牌、输入有效性、编辑模式隔离和角色切换校验保留。缺字段默认 `false`，旧调用行为不变。
6. 交互导出版本升至 11，通过 Unity CLI 分别真实导出模拟器和手机构建，构建守卫要求版本 11，避免只升级 Swift 后仍运行旧 Unity 判断。

## 测试中的问题与处理

- 自动测试禁止付费 AI 后会显示提示条。首轮测试取到的最后一条消息几何部分落在裁剪区外，实际触到的是提示区域。测试改为先关闭提示，等待聊天回到底部，再验证落点位于聊天视口。没有移除或掩盖真实产品提示。
- 双指回归暴露共同父视图上的识别器在失败后可能被 UIKit 立即重置，并把第二指作为新的 `touchesBegan` 交过来；只检查识别器自身的已跟踪手指会漏掉仍按着的第一指。通过临时调试轨迹确认后，改为同时检查 `UIEvent.allTouches` 中本窗口尚未结束的手指，阻止重新识别。测试样本还明确两指落稳再移动，排除事件插值提前移动的歧义；另留“已经开始旋转才加第二指”的取消测试。
- 更新了旧的“空聊天区域始终不旋转”断言，它与本次空白穿透要求冲突。新测试直接区分气泡、空白和按钮，并检查真实聊天内容的位置与 Unity 旋转计数。
