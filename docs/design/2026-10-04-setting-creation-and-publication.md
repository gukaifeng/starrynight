# 星夜角色与设定平台：产品及创作设计

日期：2026-10-04。状态：完整设计提案，尚未实现。本文补全创建设定、草稿、公开资料与私有指令、发现双入口、发布及对话体验。[服务端技术方案](https://github.com/gukaifeng/starrynight-server/blob/main/docs/design/2026-10-04-setting-platform-technical-design.md)位于独立服务端仓库。

承接[角色、设定与对话实例分离](2026-10-04-character-setting-separation.md)及[发现双入口与固定属性匹配](2026-10-04-discovery-characters-and-settings.md)。后续冲突时，采用本文关于创建入口、保密、发布生命周期的明确约定。本轮只读审查及写设计文档，不修改业务代码、角色包、数据库或部署，不调用付费 AI。

## 1. 产品边界与主要决策

1. 底部中间的加号改为“创建设定”。不再让普通用户从这里修改固定人物、复制模型或重新指定声线。专业角色制作保留为独立作者/管理流程。
2. 角色负责固定人物与表现资源；设定负责一起玩什么；对话实例负责某个用户这次已经经历了什么。三者分别版本化。
3. 设定有公开资料与私有运行内容。公开发布意味着其他人可以发现和使用，不意味着可以查看真实提示词。
4. 编辑中的草稿、可使用的发布版本、是否对其他人公开是三个独立概念。“私有”不是未完成，“草稿”也不等于已经可以对话。
5. 用户可以只浏览人物、只浏览设定、先选人物后选设定、先选设定后选人物。未选择任何对象时不强制进入配对流程。
6. 身高是作者填写的固定剧情资料，单位厘米。用于资料、剧情与匹配，不从模型推算，不关联取景或显示尺寸。
7. App 界面语言、设定对话语言、用户输入语言分别处理。继续复用现有气泡和灵感接话的小翻译按钮。
8. 第一版完成私人创作与公开发布的整个闭环，采用单作者编辑。多人同时协同、交易分成及导出私有源稿不是这一版的必要范围。

## 2. 导航与发现

底部导航沿用当前结构，中央加号只换其工作内容。点击进入创作工作区：有近期草稿时先显示“继续编辑”，同时提供“新建设定”；第一次没有草稿直接新建。离开编辑器自动保存，不出现每次都要求确认保存的弹窗；只有明确删除草稿、撤回公开或处理覆盖冲突才确认。

“我的”增加“我的设定”，按草稿、仅自己使用、公开作品组织；保留设定收藏与角色订阅各自的含义。作者主页分别列人物与设定作品。作者关注仍关注作者，不能把收藏设定算成订阅角色。

新用户保留默认角色及其默认兼容设定的直接相处入口，已使用用户恢复上次实例。没有订阅任何角色的现有空态仍引导发现/创建；创建设定不会自动复制或订阅一个人物。作者制作的新设定可以在选择页使用，不要求先收藏才能进入。

发现保留角色/设定两个入口及各自搜索、筛选和滚动位置。没有选中对象时显示整个可访问目录；有选中对象时进入明确的“为 X 选择…”页面，顶部可以清除选择回到自由浏览，不把筛选上下文永久套在发现页。

| 路径 | 行为 |
| --- | --- |
| 自由浏览 | 可随时看人物资料、设定资料及作者作品，不需要配对 |
| 先人物 | 人物详情 → 兼容设定 → 这次相处 → 开始/继续 |
| 先设定 | 设定详情 → 符合条件的人物 → 这次相处 → 开始/继续 |
| 创作测试 | 草稿 → 作者选择测试人物 → 独立试聊 → 返回继续编辑 |
| 已有相处 | 启动/消息/最近记录直接恢复实例，不重新选一遍 |

角色卡仍保持紧凑人物网格；设定卡强调情景与玩法。发现卡片不增加独立作者栏、精选栏目或人物标签堆叠；作者与完整条件进入资料页。条件匹配的三态、硬条件/软偏好和统一服务端解析沿用上一份补充方案。

## 3. 创作页的视觉与交互

沿用夜底、月白和克制的彩色流光。令牌草案：夜底 #0B0D14、卡面 #141824、月白 #E9E9F1、次字 #969CAD、流光蓝 #8ED7EC、淡樱 #DBA6C8；实现复用当前 Theme，不覆盖用户主题。中文/SF 正文字体负责长篇编辑；章节标题用克制的圆润字重；保存状态使用小号稳定字体。

页面的特征是“同一设定的两面”：公开预览使用封面与简介，私有指令使用带锁标识的编辑卡。只在这层关系上强调视觉，不给每个输入框增加霓虹、动画或装饰。

~~~text
‹  创建设定                     草稿
      已保存至本机 · 已同步

公开资料       运行设定       预览与使用
─────────────────────────────────
名称 / 一句话简介 / 封面
用户将体验什么
开始前需要知道什么

此处内容会展示在发现页与设定资料页。

         仅自己使用     发布到发现
~~~

编辑器提供三个顶层区域，通过同一页面容器切换：公开资料、运行设定、预览与使用。运行设定按场景、目标、语言、兼容条件、开场、补充规则分组，可折叠。普通用户先看到基本字段，高级选项按需展开，不要求按固定顺序填完。

长篇内容使用独立全屏编辑子页，有字段标题、用途提示、字数/预算提示、撤销重做和搜索；返回原位置。小字段留在主表单。所有子页使用统一导航，不叠多层弹窗；减少动态效果时停用装饰动画。

用户可以从空白、关系型、任务型、沙盒型的结构模板开始。结构模板提供字段与示例，不自动填入真实经历，不调用 AI 生成，也不把示例算作已经完成的设定。封面先选已有且允许使用的图片；将来接图片生成需另有明确动作与费用提示。

## 4. 公开资料与私有内容

| 层 | 内容 | 浏览/使用者能否看到 | 是否进入 AI 输入 |
| --- | --- | --- | --- |
| 公开资料 | 名称、简介、封面、玩法介绍、适用说明、作者及版本 | 公开版本可见；私人版本仅作者可见 | 不自动当成指令；必要的约定另存结构化运行字段 |
| 运行规则中的公开约定 | 语言、初始关系摘要、允许参数、适用条件、功能边界 | 可读摘要可见 | 服务端解析为可信配置 |
| 私有运行内容 | 场景细节、剧情秘密、行为要求、目标推进、知识、开场模板和例子 | 仅作者、获授权审查人员可看源稿 | 编译后按需要发送给模型 |
| 用户实例数据 | 真实聊天、称呼、记忆、关系与学习进度 | 仅实例用户；作者不因作品归属而获得 | 按实例权限及作用域注入 |

公开资料和私有正文用不同对象、存储与接口，不做“先返回全量、前端隐藏”。公开索引、分享卡、媒体包、翻译请求、普通开发检查与错误信息均不能夹带私有正文。

创作者在两个区域顶部看到常驻的短说明：

- 公开资料：“给别人看的介绍。会出现在发现页和资料页，请不要放剧情秘密或真实提示词。”
- 运行设定：“用于角色实际对话，不向其他使用者展示源稿；服务器会发送必要内容给 AI 服务。”
- 对话数据：“发布设定不会分享你与角色的聊天，也不会让你看到其他用户的聊天。”

公开简介可与实际提示词措辞不同，但不能承诺不存在的玩法或隐瞒必要条件。语言、限制、可选参数等公开约定由结构化运行字段生成摘要，避免两份手写说明不一致。公共介绍文字本身不能改变人物、权限或运行规则。

保密目标是阻止源稿通过产品接口、下载包或管理越权被获取，并降低模型复述源稿的风险。不能承诺模型推理永远无法暴露或让人推测出任何设定。密码、API Key、账户秘密等不放进提示词；权限检查由服务端完成。依据 [OWASP 的 System Prompt Leakage 说明](https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/)。

## 5. 格式化编辑与自由度

公开信息是独立介绍。实际运行内容采用有类型的字段和有稳定 ID 的内容块，允许每个内容块写较长文本。普通用户用表单和选项，高级作者可以增加补充规则、事实、剧情阶段、条件和示例，仍不直接提交整个 System Message。

| 分组 | 核心字段 | 自由度与约束 |
| --- | --- | --- |
| 情景 | 地点、时代/时间规则、事件起点、用户临时身份、初始关系 | 可写丰富故事；不得重写角色固定生平和身份 |
| 目标 | 关系/任务/沙盒，长期方向，当下目标，推进/暂停条件 | 支持混合方向；不靠一句指令直接篡改关系结果 |
| 语言 | 默认语言、允许语言、心理描写语言规则、混用范围 | 可全英文或按任务混用；检查实际发声能力 |
| 任务规则 | 学习领域、水平、纠错方式、解释深度、知识范围 | 不把模拟角色说成具有未经确认的专业资质 |
| 匹配 | 固定人物属性的硬条件、软偏好、必需能力 | 字段/操作符/值及 AND/OR/NOT；不让 AI 猜硬条件 |
| 用户参数 | 名称、类型、默认值、范围、进入时可选、变更方式 | 可设话题、难度；不能改角色名字、性格、年龄或声线 |
| 开场 | 三组首次候选、心理/情绪、开场引导、返回/待机倾向 | 原文语言与规则一致；实际音频按人物组合准备 |
| 世界与故事 | 固定事实、剧情阶段、秘密及披露条件、可用事件 | 稳定块 ID；披露条件只能引用获准的实例状态 |
| 行为规则 | 鼓励/避免的交流方式、节奏、长度范围、丰富例子 | 足够长的文本块；不能覆盖平台输出/动作协议 |
| 表演偏好 | 情绪/风格/拟声偏好、角色实际动作能力要求 | 只用语义标准；没有相应组件就回退，不制造能力 |
| 媒体 | 可选情景背景与音乐引用 | 只选获授权资源；不复制模型，不写任意外部执行地址 |

平台负责每句可见心声、情绪、动作表演、非发音片段、句子边界和连续组合去重的统一协议。作者可增强表现，不能取消这些必需字段，也不能让心理旁白进入语音。

预留 typed block 的命名空间和 schema 版本。未知的可选扩展保留往返；未知的必需能力阻止发布/进入并说明。不得用一个无限的“其他 Prompt”字段绕开字段边界；高级补充规则仍有用途、优先级、长度及合法变量限制。

变量仅允许注册的人物、用户已授权资料、设定参数和实例状态。作者可引用人物名称、剧情身高和允许的称呼，不执行脚本、网络请求、模板函数或任意读取其他人的记忆。姓名/职业等固定人物项由运行时填入，不需要每个作者复制人设。

## 6. 草稿与恢复

草稿属于用户内容，不能放在可清理缓存目录，也不能与大模型资源缓存一起删除。每次字段变化写入本机持久化队列，短事务提交；云端同步单独合并发送。返回、切字段、后台和账号切换时补一次提交，但恢复不依赖 iOS 的退出回调。

显示准确状态：“保存中”“已保存至本机”“已同步”“待联网同步”“需要处理另一台设备的修改”。本机保存成功才能显示已保存，网络失败不撤销本机内容。写盘失败保留内存和保护副本，停止误报成功，并提供明确恢复动作。

未登录也可编辑本机草稿；首次登录后由用户选择关联到该账号。云端同步、试聊和发布需要已鉴权账号。离线可编辑、浏览已缓存的公开资料，联网后继续同步；离线不会假装发布成功。

跨设备采用版本检查和三方合并：上次同步基线、本机版本、服务器版本。不同字段可以合并；同一长文本双方都改时保留两份，让用户选择或手动合并，不按时间戳默默覆盖。列表内容块使用稳定 ID，删除和移动都参与冲突检测。

支持多个草稿、复制自己的草稿、恢复近期检查点、命名、删除及从已发布版本继续编辑。删除有确认与墓碑，离线旧设备重连不能复活已删除草稿。切账号不自动上传上一账号的内容；匿名草稿和已登录草稿分区。

中国输入法的候选组合文本作为 raw edit buffer 保留，语义校验等待提交完成；输入到一半的数值/条件也允许存草稿。保存草稿不要求字段完整，发布/启用才要求完整。

已提交到磁盘的内容在正常返回、系统回收和手动划掉后恢复；突然断电/进程在一次提交完成前中断，恢复到最后的持久化检查点。实现必须测量输入到本机提交的延迟，并测试最后输入后的不同终止时点，不能声称只靠内存或自动退出保存就能做到零丢失。

## 7. 启用、公开、更新与撤回

默认选择“仅自己使用”。启用私有版本前完成结构、兼容、变量、预算和必要资源检查，产生不可变版本；只有作者能创建使用它的对话。

公开流程：保存当前草稿 → 预览公开资料 → 检查规则、资源权利及适用人物 → 提交这一份精确内容 → 审查/验证完成 → 原子发布 → 进入发现。测试环境可由明确授权管理员处理审查；实际没有完成人工审查时，界面不能写“人工审核通过”。

发布时冻结内容；之后编辑生成新的草稿，不直接修改正在使用的版本。提交后继续编辑，不改变已经提交的那一份。拒绝或资源处理失败返回准确可修复项，草稿保留。

| 操作 | 发现可见性 | 已有使用者 |
| --- | --- | --- |
| 保存草稿 | 不可见 | 不影响现有版本 |
| 启用私有版本 | 仅作者可见 | 仅作者可开启/继续 |
| 发布公开版本 | 所有人可浏览公开投影 | 可选择人物创建实例 |
| 发布新版本 | 新选择默认用新版本 | 已有实例保持原版本，明确升级才改变 |
| 从发现撤下 | 不再给新用户发现/新开；详情提示撤下 | 既有实例可继续钉住版本 |
| 改为私有/撤销使用权 | 非作者不可再使用 | 保留用户聊天记录；停止新的推理，并提示换设定或联系作者 |
| 作者删除 | 停止公开与使用 | 按撤销规则处理；不连带删除他人的聊天 |

撤下与改为私有必须是两个明确操作，确认页解释影响。已经下载/听到的公开图片、开场和消息无法远程抹掉；访问撤销阻止后续服务，不能声称能收回所有已交付副本。

设定收藏不赋予源稿查看或永久使用权。复制/派生别人的设定仅在作者显式允许分享源稿时开放；默认保密设定不能做“复制一份”来变相获取。未来授权派生保留作者、许可和来源版本。

## 8. 预览、试聊与质量

公开预览是实际普通用户所见的资料投影，不能混入作者注释。作者另外可以查看完整分层输入和编译检查；普通用户只看公开资料与允许参数。

试聊使用隔离的作者测试实例，绑定精确草稿快照；不写正式聊天、恋爱进度、用户全局记忆或其他人的实例。编辑后产生新测试快照，不在已经生成一半的回复中替换设定。

无付费调用的检查包括格式、逻辑、预算、兼容人数、变量与资源。真正试聊、音频试听生成和 AI 辅助创作都由用户明确操作触发，并受后台任务预算控制；浏览、保存和发布基础检查不能自动为全部人物生成内容。

首次开场三个候选分别带完整心理/情绪/表演元数据。开场文字可包含安全的注册变量；原文是设定语言，不通过 App 中文界面强行改写。已准备的组合使用现成音频，尚未准备的组合在选择阶段预热，界面区分“设定可用”与“当前声线开场已就绪”。

作者保存草稿并不自动把草稿喂给模型。公共设定的更新不能把作者试聊消息伪装成消费者真实历史。除明确选中的首次开场外，固定场景缓存仍使用上下文生成；未使用候选不进入历史。

## 9. 多语言与翻译

界面延用简中、繁中、英文和系统回退规则。设定内容语言独立于界面；全英文设定的心理、场景描述、台词、开场和灵感接话都遵循自己的语言规则。

复用当前 ReplyTranslation、MessageTranslation、TranslatableReplyContent 及灵感接话翻译交互。根据实际片段语言与 App 语言差异显示小按钮，不能简单把“不是中文”当作唯一条件。混用语言也按片段判断。

译文保留片段 ID、心理/旁白/台词类别、顺序、字体及非发音边界；点击原文/译文切换不改变语音、实例语言或历史原文。用户点击翻译后的灵感建议仍发送原始语言的候选，绑定原建议 ID，而不是让译文误命中另一缓存。

翻译缓存增加账号、实例/代次、源消息或建议、原文摘要、目标语言与翻译协议版本。已有原文和音频缓存继续可读。设定详情可翻译公开介绍；翻译服务不收到隐藏提示词，作者自己的源稿翻译为另一个显式编辑动作，不自动进行。

## 10. 对话、记忆和低延迟

同一人物可有多个设定，每个组合也可有多个实例。相同人物、版本、设定、规范化参数已有实例时优先“继续相处”，明确新开才重新随机首次开场。换独立情景不复制其他实例的恋爱/学习记忆。

每条相处记录保存精确版本；消息页按人物汇总、资料卡内选具体相处。隐藏只隐藏所选实例，重置明确范围并二次确认。模型下载/删除仍按角色资源处理，与删除设定或聊天不同。

开场、返回、待机、晃动、捏/扯、三条灵感建议及各一组回复统一采用实例键、上下文快照与已就绪音频。选择页预热即将进入的组合；不能为了新市场预热整个角色×设定矩阵。模型、骨骼、音色引用与标准表演继续复用。

预缓存首音 500ms 内、普通回复争取约 1s 到首音继续作为待测目标。必须分别记录本机命中、服务器命中、无缓存、配置失效、下载及生成阶段，不能把“有文本候选”算成可秒播缓存。

## 11. 之前方案欠缺并在此补全的事项

| 缺口 | 本轮约定 |
| --- | --- |
| 创建仍在复制人物 | 中央加号只创建设定；人物固定定义独立 |
| 私有/公开与草稿混淆 | 草稿、发布修订、访问可见性分别管理 |
| 编辑退出才保存 | 每次编辑持久化，本机先于云端，支持跨设备冲突 |
| 公共介绍可能包含源稿 | 物理/接口分离、白名单投影、作者明确提示 |
| 格式化会限制高级作者 | 类型化长文本块、阶段/条件/示例及高级规则 |
| 浏览和配对耦合 | 自由浏览独立，配对上下文可清除 |
| 更新会改已有故事 | 不可变修订、实例快照、明确升级 |
| 撤下和改私有含义不清 | 停止新发现与撤销后续使用分别处理 |
| 翻译可能破坏缓存与格式 | 原文候选 ID、结构片段与实例级翻译缓存 |
| 发布引发大量 AI 费用 | 无付费基础验证，有限组合预热与任务预算 |
| 调试入口会泄露第三方设定 | 角色检查、设定源稿、用户记忆分别授权 |
| 原有包与对话会丢 | 明确迁移默认实例、保留旧资源和音频 |

## 12. 实施顺序与验收

先实现定义合约、公开/私有权限、草稿持久化和服务器版本；随后改实例与提示词编译、迁移现有历史；再接创作/发现/发布/管理；最后完成开场预热、翻译与性能验证。服务端技术方案给出表、接口、目录及迁移依赖。

必须验证：

- 未登录、离线、返回、切菜单、系统回收、划掉、磁盘不足后的草稿恢复与诚实保存状态。
- 两设备同时修改长文本、条件块的移动/删除、旧响应及切账号不会覆盖或串稿。
- 公共列表/详情/搜索/分享/导出/资源包/翻译/错误/开发检查均不泄露私有源稿。
- 作者只能编辑自己的设定，作品使用者不能访问源稿；作者不能读取使用者聊天。
- 草稿可存不完整值，启用/发布要求完整；公开介绍与参数摘要一致。
- 两条选择路径和自由浏览一致，兼容未知值不当作通过。
- 发布的精确版本和提交后继续编辑的草稿相互独立；私有化立即撤销后续推理。
- 全英文心理/台词/开场/灵感接话及结构翻译正确；译文不改变缓存选择或原始语音。
- 同角色多设定不串历史，标准动作、固定声音和模型复用不退化。
- 完整记录开场/缓存/普通回复的首音与生成耗时，按真实设备分别报告。

本轮完成产品、架构与技术设计及文档校验，没有执行上述业务验收，没有修改或安装 App。
