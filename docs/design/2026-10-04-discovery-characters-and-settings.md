# 发现双入口与固定属性匹配：设计补充

日期：2026-10-04。状态：设计草案，尚未实现。承接[角色、设定与对话实例分离](2026-10-04-character-setting-separation.md)。本轮只做代码审查、规则技术核对及文档设计；不修改 UI 实现、角色数据、数据库或云端服务，不调用图片、音色或对话生成 API。

创建设定、草稿、公开资料与私有源稿，以及自由浏览和发布撤回的完整补充见[设定平台产品设计](2026-10-04-setting-creation-and-publication.md)。

## 1. 产品关系

发现分为「角色」「设定」两个同级入口，保留现有底部“发现”，不增加新的底部导航。默认打开角色，之后保留用户上次的入口、搜索、筛选和滚动位置。

- 角色入口：浏览固定人物 → 看人物资料 → 选择兼容设定 → 配置允许参数 → 开始/继续相处。
- 设定入口：浏览目的与情景 → 看设定资料 → 选择符合条件的角色 → 配置允许参数 → 开始/继续相处。
- 两条路径使用同一组合解析、下载准备和实例选择流程。先选的对象固定在下一页顶部，提供“更换”，更换时重新校验另一项，不带着过期选择进入。

首次启动默认人物的自动进入、首页继续上次实例、消息页继续既有记录仍保留；发现双入口不要求每次打开 App 重新选择人物与玩法。

设定模板仍是有版本的定义；动态变化的是用户允许选择的参数与实例进度。用户不能在进入时改写作者的硬条件、人物固定属性或平台协议。

## 2. 页面布局与视觉

以现有深色“月白”与彩色流光为基础。草案色彩：夜底 `#0B0D14`、卡面 `#141824`、月白 `#E9E9F1`、次字 `#969CAD`、流光蓝 `#8ED7EC`、淡樱 `#DBA6C8`；正式实现使用现有 Theme 令牌和用户主题，不写成第二套固定主题。字体沿用系统中文/SF 字体，标题与角色名克制使用圆润字重，基础信息使用稳定的正文与数字样式。

页面结构：小标题 → 角色/设定入口 → 当前入口搜索 → 收起式筛选与排序 → 内容。减少多排分类、横幅和操作栏。延续用户要求，不恢复“精选”、每个角色的标签堆叠或发现页独立作者栏。

```text
发现                         筛选
       角色       设定
╭────────────────────────────╮
│ 搜角色、职业或人物特点       │
╰────────────────────────────╯

╭────────╮ ╭────────╮ ╭────────╮
│ 人物封面│ │ 人物封面│ │ 人物封面│
│ 名字 ♀ ↓│ │ 名字 ♂ ✓│ │ 名字   │
│年龄·身高│ │年龄·身高│ │基础信息│
╰────────╯ ╰────────╯ ╰────────╯
```

角色区使用紧凑自适应网格：默认字号时优先约 3 列，宽度不足/大字号时减少列数，不固定所有设备为 3 列。人物优先完整显示头发和头部装饰，封面充满容器。卡片统一行数与高度：名字及性别符号、年龄/身高简行、可选一句固定人物介绍。缺项收敛显示，不把技术状态或条件明细塞满卡片。

性别符号紧随名字，下载/进度符号独占名字行的尾端固定小区域，二者不争用位置；下载状态变化不撑大卡片。男性 `♂`、女性 `♀`；其他/未设定使用明确文字，避免一个含义不统一的符号。符号有辅助功能读法，不只靠颜色传达性别。

设定区采用紧凑纵向卡片，侧边小情景图，正文突出名称、具体能做什么、语言与关键要求，必要时两行简介。同屏应能读懂多个玩法。封面表现情景；使用人物示例图时明确为示例，不暗示只能绑定图中人物。作者进入资料页显示。

```text
       角色       设定
╭────────────────────────────╮
│ 搜学习、恋爱或故事情景       │
╰────────────────────────────╯

╭────────────────────────────╮
│ 情景图  商务英语练习         │
│         在面试、会议中自然接话│
│         英语 · 可选练习水平   │
╰────────────────────────────╯
╭────────────────────────────╮
│ 情景图  雨夜重逢             │
│         从一次偶遇慢慢了解彼此│
│         查看适用人物条件      │
╰────────────────────────────╯
```

同一“选好组合”摘要作为两条路径的共同视觉元素：小人物头像、人物名及设定名并列，轻微流光连接；其余装饰保持安静。列表转详情、替换候选与条件状态过渡使用克制的淡入，不让筛选引发全页闪白，遵循减少动态效果设置。资料与选择采用同一导航容器内的子页面，避免连续叠加多层弹窗。

## 3. 基础资料与数据定义

详情页：封面/模型预览 → 头像、姓名、性别与订阅 → 一句人物介绍 → 基础资料 → 声线试听 → 性格与固定背景 → 作者 → 选择设定。卡片不展示完整 Prompt、私有调教或剧情秘密。

第一版重点字段：性别、固定虚构年龄、人物身高、物种、原本职业、固定性格、语气/声线特征、世界观与模型画风、经验证的语言和模型能力。后几类在资料页分组，卡片只保留最有辨识度的基础信息。未设定时显示“未设定”或省略，不伪造数字填满排版。

身高就是作者设定的剧情属性：`identity.height_cm`，统一用厘米保存和显示。它用于人物介绍、剧情生成及设定的数值限制；缺失时保留“未设定”，不从模型测量或推算，也不为它增加显示/取景方面的实现。

该值对用户和设定只读，随人物定义的发布修订保存。设定可以要求 150–175cm 的人物，但不能把一个原本 180cm 的人物改成 170cm 来让它通过；需要改变人物资料时由角色作者发布新修订。当前没有为已有 16 个角色填入推测值。

年龄、性别、职业也来自发布的人物定义，不从外貌或声音推断。年龄条件不能替代既有角色玩法边界。英语、模拟面试等属于玩法，不塞进固定职业标题。当前公开信息中有“英语伙伴”“慢热恋爱”等混入职业，迁移时分开。

## 4. 固定属性注册表

为所有可供限制的固定属性建立版本化注册表，字段定义包括：稳定路径、值类型、单位、枚举/标签词表、已知状态、来源、可使用的操作符、公开/作者权限及修订。所有人物固定项都可按其类型注册扩展，不只硬编码性别和身高。

| 类型 | 示例 | 可用条件 |
| --- | --- | --- |
| 枚举 | 性别、物种、模型画风、世界类别 | 等于、属于集合、不属于集合 |
| 数值 | 年龄、剧情身高 | 大于/小于、闭区间、等于 |
| 标签集合 | 性格、语气、声线特征、语言、动作能力 | 全部包含、至少包含一项、不包含 |
| 标识引用 | 角色 ID、作者、资源版本、明确职业分类 | 白名单、黑名单、等于 |
| 文本事实 | 固定职业描述、某项结构化背景 | 精确/受控分类匹配；需要语义条件时先制定固定标签 |
| 自定义属性 | 特定世界的种族、设定作者与角色作者约定的特征 | 使用命名空间、有类型、带版本注册 |

“慢热”“温柔”等以固定标签 ID 存储，中文/英文名称只是本地化显示。不能让“很温柔”与“温柔”因自然语言写法不同被随意当成两种属性；作者确认分类结果，模型不能运行时改标签。

全部固定项可扩展为约束字段，不等于将完整私有 Prompt 和角色秘密公开给第三方。角色作者声明对设定作者开放的字段；私有原文不能作为任意公共探针，必要的匹配改用已授权特征或适配记录。公开理由也不能泄露秘密。字段规则不指向原始文件路径、签名 URL 或密钥。

明确排除动态状态：当前表情、衣摆正在摆动、用户缩放、是否已下载、当前音量、用户恋爱进度和临时语言，不是角色固定属性。下载/权限/实例阶段由独立状态处理，不混入人物定义。

## 5. 创作者规则及边界

两类条件：

- **必须符合**：创作者决定的硬限制，用户不能在选角色时绕过；不满足不能开始。
- **优先推荐**：排序偏好，不排除其他满足硬条件的角色，例如更倾向温柔声线。

编辑器提供字段、比较方式和值，支持“同时符合”“符合任意一组”“排除”。创作者不用写代码。规则以有类型的条件树保存，产生可读说明；不采用一段自然语言让 AI 临时猜是否匹配。

示例（说明规则结构，不是任何现有角色的核定资料）：

```json
{
  "required": {
    "all": [
      {"field": "identity.gender", "op": "in", "value": ["female"]},
      {"field": "identity.height_cm", "op": "between", "value": [150, 175]},
      {"field": "capabilities.spoken_languages", "op": "contains_all", "value": ["en"]}
    ]
  },
  "preferred": [
    {"field": "personality.traits", "op": "contains_any", "value": ["gentle", "patient"]}
  ]
}
```

年龄、范围、单位、集合与操作符在发布时检查；未知字段、矛盾区间、不同版本的未支持必需规则拒绝发布/解析，不静默忽略。设定允许选择语言等参数时，可将条件绑定到该参数，例如要求角色支持选中的语言，参数改变立即重验。

作者要求还要与角色自身允许范围、平台协议、发布/访问状态共同检查。作者不能通过模板强行赋予角色新的固定身份、声线、模型动作或下载权限。正文私自声明“忽略上述限制”不能覆盖结构化规则；私人派生也不能冒用原模板 ID 取消硬条件。

## 6. 匹配结果及排序

属性表达三态：已知且符合、已知且不符、未知。NOT 未知仍是未知，不能把“性别未知”因不是已知男性就当成女性；OR 的另一分支确实成立时可按逻辑通过。最终必须得到确定的 true 才可进入。

匹配结果分为：符合、不符合、资料不足。例：女/150–175cm，人物身高为 180cm → 不符合；身高未设定 → 资料不足。后者提示“身高尚未设定，暂不能确认适用”，不编造“身高不符合”。资料缺失的旧角色仍可进入不依赖该项的设定。

“未下载”“需要登录”“当前版本未交付”“资源准备中”是进入状态，不是匹配失败。两层状态分别返回；未下载但符合的角色正常出现在候选中，可在选定后下载。

普通用户默认看确定符合的候选；详情可查看不符合/资料不足的说明。已确定另一项时，列表不以假装灰掉/滑走方式放过硬限制。理由只暴露已允许公开的字段。示例说明：“需要支持英语发声”“该人物身高不在要求范围”。

确定符合后再排序：适配记录的优先级、软偏好、用户明确偏好、已有资源/最近使用。已下载是便利因素，不应永久压过更适合的人物。展示“更适合/可使用”等解释，不伪造未校准的“匹配率 98%”。两条入口共享同一判断函数。

## 7. 服务端规则方案

推荐 CEL 作为服务器表达式执行内核，有类型规则树作为星夜的作者界面和可迁移内容格式。CEL 官方用于结构化过滤/验证；Go 实现支持预编译和重复求值。当前主库为 [cel-expr/cel-go](https://github.com/cel-expr/cel-go)，模块路径 `cel.dev/cel-go`；旧 google 路径已转兼容库。依据：[CEL 官方](https://cel.dev/)。这里只做选型，没有安装到服务端工程。

先验证规则树与注册表，再生成受控 CEL 表达式，不直接放任用户提供任意表达式。只暴露固定角色快照与允许参数，不提供文件、网络、运行脚本或用户私有记忆。限制条件深度、数量、数组长度和求值预算；区分求值异常与不匹配。已编译程序按规则版本缓存。

常用性别、身高、语言等条件可用安全、固定操作符先做 PG 预筛，剩余条件使用同一规则树精确判定。不接受拼接 SQL。当前 16 项无需全组合预存；未来使用注册字段索引和游标分页，不每次加载全部模型或调用 AI 匹配。

缓存依据属性注册修订、角色定义/能力修订、设定及规则修订、参数摘要；访问检查按当前用户另做，不能跨账号缓存私人访问结果。兼容缓存不包含每秒变化的时钟、取景或表情。

候选列表、详情解释、作者预览及最终开始都用同一服务端判断。客户端可以用缓存展示预览，最终创建实例再次校验，保存精确角色/设定修订、规则修订、参数及结果快照。列表点击后内容更新、下架或权限变化时重新解析，不用旧列表票据自动开始。

## 8. 两条开始流程

角色资料主按钮“选择设定”；设定资料主按钮“选择角色”。选择页显示先选对象的小摘要、兼容候选、搜索与必要筛选；返回保留浏览位置。切换先选对象时清掉不再兼容的第二项，说明需重选。

选好后共同进入“这次相处”配置页，紧凑显示人物、设定、主要目的、语言及少量允许参数。改变参数可改变匹配结果，须就地显示并禁用不满足的开始按钮，不能在最后发请求才突然失败。

同人物、同设定、同规范化参数已有实例时默认“继续相处”，另提供“新开一段相处”；有同组合但不同参数的旧实例时让用户明确选择，不自动覆盖旧记录。新建实例才使用首次开场，继续实例使用对应返回逻辑。

尚未下载时显示真实预计新增大小与“下载并开始”；已下载使用“开始相处/继续相处”。准备状态区分下载、校验、开场资源和就绪，支持取消与失败继续；资源就绪才切会话，保持已选组合。匹配检查不依赖下载，避免先下载大模型才发现不能用。

只需要新设定小资源时复用已有模型；换设定不重新导入 Unity 模型、不归零用户取景。声音/表演预热使用上一份方案的实例缓存键，不把另一设定的开场当成同角色通用开场。

## 9. 搜索、筛选、资料与作者工具

角色区搜索人物名称、固定职业、公开生平与属性；筛选性别、年龄、身高、画风、声线、语言能力，以及“只看已下载/已订阅”。设定区搜索名称、目标与公开情节；筛选玩法、语言、难度和收藏。无需在卡片中铺满所有筛选标签。

两个入口独立保存查询；可用轻量提示引导去另一入口看相关结果，不混排不同卡片。存在选中对象时，只在它的兼容候选中搜索，标题明确“为…选设定/为…选角色”。无结果时区分用户筛选过严与作者无适用对象，提供清除个人筛选/换先选项；不能替用户放宽作者硬条件。

角色详情完整展示公开基础属性与来源；设定详情展示能做什么、初始关系、语言规则、必要条件、允许参数、适用人数和作者。全文提示词与秘密仍属开发检查/作者权限。试听分别为固定人物声线试听与已有适配组合的示例开场；未准备示例时不在浏览期间自动付费生成。

作者编辑器实时显示当前可访问的已发布角色中“符合/不符/资料不足”数量、具体公开原因及组合参数预览。普通发布默认要求至少一个符合对象；面向未上架人物的定向模板先保留草稿，未来有角色匹配再发布。计数不暴露私人角色。

已发布模板硬条件不能被原地随意放宽；创建新修订或私人派生，不冒充旧模板。实例钉住所用版本，既有进展不因最新条件变化被突然清空。撤回资源/权限属于另一个必须即时执行的可用性检查。

## 10. 版本、迁移与验收

角色新核心声明基础属性及注册表修订；旧包通过服务端权威元数据补齐，保持未知，不因加身高字段就重导全部模型。字段作者来源与确认记录保留；确认资料产生新修订。当前没有新增固定身高或年龄值。

迁移先去掉职业/性格数据中混入的玩法内容，再补属性注册、规则与双向列表接口，然后做客户端双入口及开始流程。新字段、注册表、规则语义按版本协商；未知的必需条件不能被旧客户端自行解释为允许。

后续验收至少包括：

- 两条路径对于相同人物、设定、参数返回相同结果。
- 身高区间边界、单位换算、未知/NOT/OR、标签集合、矛盾规则和自定义字段。
- 不下载模型就能筛选；未下载可符合，已下载也可不符合。
- 用户不能改硬条件；能力声明、平台边界、私有访问、下架和版本变化均最终重验。
- 不同账号结果不泄露私有人物或秘密；元数据/能力更新后不使用旧匹配缓存。
- 大字号、长名字、性别符号、卡片下载状态、减少动态效果与滚动位置保留。
- 完全相同组合继续已有实例；不同参数不覆盖旧实例；新建、续聊与开场缓存保持正确。
- 两个入口搜索不混用语义；零适配和资料不足都有明确下一步。

本轮验证仅为设计与现有代码关系的审查，尚没有实现后的 UI、规则库、下载或手机效果验证。正式实现沿用上一份分阶段迁移，不在本轮部署。
