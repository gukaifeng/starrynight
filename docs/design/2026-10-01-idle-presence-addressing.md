# 待机搭话与两级称呼 · 0.71

星夜 / StarryNight，2026-10-01。App 0.71.0（98）。修改现有 AI 对话与原生设置，不修改模型、动作资源或音色。

## 待机时关心用户

待机主动发言的重心从无关的角色自我分享，调整为关心安静中的用户：在做什么、是不是正忙、是否在想事情、想继续聊还是静静相伴。允许少量俏皮试探，以及对刚才话题是否合适的轻微不确定；不把沉默归因为用户嫌弃角色，不要求证明感情，不反复催回复。

`services/character_ai/idle_presence.py` 提供 18 个**生成意图**，不存可直接朗读的台词。每次仍调用现有百炼角色模型，根据角色性格、剧情、关系、最近聊天与称呼创作：

| 分组 | 生成角度 |
| --- | --- |
| 好奇近况 | 此刻在做什么；注意力被什么吸引；是不是在想事情；眼下的一件小事；有话还没找到开头 |
| 体谅节奏 | 是否腾不开手；是否想歇一会；现在是否方便聊天；继续聊天还是先安静 |
| 安静陪伴 | 表达愿意陪着，不要求解释沉默 |
| 接上联系 | 是否想继续未完话题；愿不愿意分享此刻心情 |
| 轻松打趣 | 俏皮确认还在不在；把走神比作明确的想象 |
| 亲近感 | 想听到对方接话，同时保留用户空间 |
| 偶尔不确定 | 刚才话题是否合口味；是否讲得太细；是否误会了对方语气 |

前两组权重较高。不重复最近 4 个角度，也不连续选择同一分组；记录最多 6 个已使用角度。未收到回应时排除委屈、不确定及更强的索取关注角度；已提过忙碌时优先体谅、安静陪伴。匹配到最近用户消息明确要求安静时，不生成、不消费待机语音候选。当前对安静/忙碌的确定性识别是中英常见表达的轻量规则，不是完整语义理解。

原有触发节奏保留：用户已实际发过消息后，客户端安静约 150–240 秒才尝试；输入、录音、播放、生成及角色设置界面期间不抢话。服务端仍有间隔与未回应次数上限。没有合适内容时允许安静，角色不会因为加入这些角度而无休止发问。青柠、望等固定英语角色仍用英语。

## 实时、缓存与动作共用语义

实时回复、提前生成的 idle 候选和并发表演都收到同一份 `idle_context`。文字生成请求末尾的 `<app_event>` 也显式附上当前角度，避免它只埋在大段状态 JSON 中，导致模型继续自述旧故事。

准备和查看测试检查器不推进角度历史。候选脚本带可选 `idle_angle`，只有真实发布到会话后才写入 `idle_presence`；缓存命中必须使用候选自己生成时的角度，不能误记为触发时重新抽出的角度。清空角色聊天会清除此角度历史。所有状态仍按账号、角色隔离。

继续使用现有每场景 1 组预缓存，用后补一组；未完成候选可被接管。策略修订号进入缓存指纹，使旧策略的未发出台词失效。没有新增付费模型、额外的意图分类调用或硬编码备用台词。角度轮换与现有内容新颖性检查一起工作，不承诺概率模型永远不重复。

## 称呼规则与入口

优先级：**当前账号＋当前角色的专属称呼 > 当前账号的全局默认称呼 > 自然第二人称**。

- 全局：我的 → 设置 → AI 对我的称呼。
- 专属：会话左上角色胶囊 → 相处与剧情 → 相处 → 专属称呼。
- 专属留空或点击“使用全局默认”即可继承；全局、专属均留空时不强制昵称。
- 页面返回或外层关闭时通过现有关闭协议保存；单独点击全局输入框的完成也保存。页面显示当前生效值。称呼统一去除首尾空白、合并换行/连续空白，最多 20 个 Swift 字符；不在中文输入法组合过程中截断文字。
- 已有 `TogetherPreferences.nickname` 保留为专属称呼，不丢失旧设置。历史消息及旧音频不会被改写。

全局默认值以可选 `CompanionArchive.defaultNicknames[accountID]` 存储，兼容缺少此字段的 schema-2 旧档案。游客可使用；仅注册新账号时可以随既有游客资料迁移，已有账号独立。写入复用异步串行持久化队列，云端批量导入复用回滚机制。

Go 账户服务的 `/v1/me/settings` 使用既有扩展 JSON 文档，增加客户端已知字段 `default_nickname`；专属称呼继续随 `/v1/characters/{id}/preferences` 的 `experiences.preferences.nickname` 同步。清空用空字符串明确同步，不需要删表或更改 API 主版本。未知字段合并、离线待同步及冲突规则沿用原实现。当前仍为本机 Go 服务联调，不是公网服务上线。

所有 AI 请求统一发送解析后的 `preferences.nickname`，另附 `nicknameSource=character/account/natural` 用于检查。普通聊天、初见、回访、待机、手势、剧情、智能回复及预缓存使用同一组装函数；ASR 昵称热词也使用实际称呼。提示词明确旧历史昵称不能覆盖当前选择，称呼是数据、不改变角色语言规则，不要求每句反复点名。

改称呼会改变既有候选缓存指纹；回到会话时清除旧智能回复展示并预热新上下文。测试检查器同时展示全局值、专属值、实际值、来源及完整待机规则，便于定位“改了但还叫旧名字”的问题。

## 调整与回退

可调整 `idle_presence.ANGLES` 的意图/权重并递增 `REVISION`，不影响模型资源。删除待机接入时应保留可选脚本字段的宽容解析；已有消息无需重写。全局称呼为可选新增字段，旧档案仍可读；撤销入口不等于删除用户数据。验证、失败修正和安装状态见 [验证记录](../verification/idle-address/README.md)。
