# 情感陪伴表情与动作库 v3

## 选择 48 组的依据

这不是“行业规定的最佳数量”。按星夜当前的陪伴、关系、学习与日常对话场景，先形成八类、每类六组，共 48 个可识别的基础组合。数量之外，必须同时满足语义匹配、不同姿态轮廓、节奏差异、角色适配、语音时机与自然恢复。以后新增场景可增量增加 ID；不要求所有模型有相同的原作表情形变。

语义和语音节奏需要同时考虑，这与 [Speech-driven Animation with Meaningful Behaviors](https://arxiv.org/abs/1708.01640) 对有意义的会话动作及语音同步的研究方向一致。本实现没有使用论文的 DBN、训练数据或动捕；48 组及其参数是本项目的产品设计和宿主编排，不能把研究当作这些具体组合的品质证明。

## 幅度与时序

各部位分别设计幅度，不统一乘一个倍数。头颈合计俯仰限制 -18…24°、转向 -26…26°、侧倾 -17…17°；肩臂外展、前抬与前臂屈曲分别编排，前臂屈曲最高 72°。胸与脊柱分担躯干变化。每个关节仍按角色中性骨轴和左右外展方向转换，不复制另一角色的局部 Euler 轴。

每组 4.2–6 秒。短预备、躯干先动、头部跟随、肩臂跟随、较长收尾，均用五次 smoothstep 的 C2 曲线。点头、摇头与挥手用多段脉冲，不用逐帧随机噪声；左右手臂不完全对称。较轻的组合也有可辨认肩臂变化，开心、挥手、鼓励等有更明显轮廓。实际效果须通过画面与用户检查。

脸部复用角色已校准的十类原作表情基底，按组合调整权重；喜悦、灵感、吃醋等部分组合有分阶段表情交接。不凭空制造 morph，不写讲话 viseme。缺少可靠语义时仍显示近似配合或中性回退。48 个组合不等于每个角色有 48 个独立原作脸部资产。

## 语音联动与实验边界

浮动开发者图标 → 动作实验；提供搜索、八类筛选、播放、结束预览与两个独立开关：

- 身体与表情组合：沿用原有本机偏好。关掉只撤除宿主叠加层。
- 随语音联动 · 实验：默认关闭，用户可打开。取现有 AI 选中原作表情的 `ai.intent`，在真正进入 `state.speaking` 后选配组合；不增加 AI 请求，不改变语音等待路径。未播放语音的 cue 只保存当前语义，不提前做动作。

同语义多候选时避免立即重复上一组合。语音结束、取消、离开或切角色会释放自动动作并丢掉队列。仅一个最新待播组合，不积压。手动预览优先于自动联动，原作整身姿态、独立源片段和模型操作优先于宿主叠加。

只动校准上身关节和已有脸部形变，不写相机、角色根、腿脚和手指。走跑、接触拥抱、手摸脸、坐卧等需要接触/足底 IK 的动作不冒充现有通用上身能力。任意换装的碰撞须另检查。

## 统一数据与兼容

唯一目录为 `unity/CharacterRuntime/Assets/Resources/HostEmotionGestures.json`。Unity 用 `HostEmotionGestureLibrary` 读取，开发版原生工程直接打包同一文件，不维护另一份名称、数量或时长列表。条目带固定 ID、分类、表情基底、匹配意图、时长、节奏参数和 13 个解剖角度参数。

v2 校准的十类脸部与骨轴可承载 v3 编排，旧 OSS release 4 无需重发角色包，宿主在 App 更新。新增模型符合现有 Humanoid 映射即可复用，不设角色 ID 白名单；映射不完整时明示不支持，不猜骨名。

标记 `HOST-EMOTION-EXPERIMENT v3`，事件 `host.motion.*`，状态来源 `starrynight.host-emotion.v3.experiment`。新增本机键仅 `hostEmotionMotionSpeechLinked.v3`；不写服务器，不改原始模型。关闭实验或独立回退本次提交即可撤销，颜色定制、语音、原作表现和 OSS 下载不依赖它。

验证结果见 [v3 验证记录](../verification/host-emotion-motion-v3/README.md)，本设计不代替实际通过记录。
