# 角色、设定与对话实例分离：架构设计草案

日期：2026-10-04。状态：设计提案，尚未实施或迁移。本文覆盖客户端与服务端的共同合约；服务端实现仍只在 `../starrynight-server`。本轮仅核对公开资料、读取现有代码并编写文档，不修改业务代码、角色资源、数据库或线上服务，不调用付费 AI。

## 1. 结论与官方核对

用户提出的多对多分离可行，建议采用「角色定义 + 设定模板 + 用户对话实例」。角色定义回答“她是谁”，设定模板回答“这次一起做什么”，对话实例保存“已经发生什么”。模板与运行状态不能放在同一个对象中。

阿里云[角色扮演官方文档](https://help.aliyun.com/zh/model-studio/role-play)列出的四类 System Message 内容是：角色的详细信息、角色的其他介绍、补充对话场景、补充语言风格。用户的概括正确；它们是提示词建议，不是强制 JSON 字段或数据库分层规范。官方另建议通过 assistant 消息设置开场白、按顺序拼接真实对话历史；文档还介绍可选的长期记忆、真实时间、搜索和调优功能。其托管长期记忆目前限中文，不能承担本项目英语场景的统一记忆。以下数据边界和运行规则属于星夜的设计建议。

四类提示词内容最终仍会组合发送给模型；开发、存储、发布和下载可以分开。角色设定分离并不表示模型能只收到场景而不知道角色。

## 2. 必须修正的划分边界

| 内容 | 建议归属 | 原因 |
| --- | --- | --- |
| 姓名、性别、固定虚构年龄、原本职业、基本介绍 | 角色定义 | 换玩法后仍是同一个人 |
| 性格、价值观、兴趣、惯常语气与说话习惯 | 角色定义 | 英语学习也保持角色个性 |
| 成长经历、家人关系、原有秘密、长期在意的事 | 角色定义 | 属于她的人生，不宜随模板任意改写 |
| 与用户是初识、朋友、恋人或对手 | 设定的初始条件；随后成为实例状态 | 不应由固定人设把所有用户设为同一种关系 |
| 这次刚发生的事件、用户在情景中的身份、临时动机 | 设定模板 | 与这次扮演有关，不能自动成为真实用户事实 |
| 地点、时间规则、情节起点、可用知识材料 | 设定模板 | 同一角色可进入多个情景 |
| 学什么、恋爱如何推进、任务要求、难度和纠错方式 | 设定模板中的目标与参数；执行状态在实例 | 学习进度和关系结果不是模板定义 |
| 回复语言、心理描写语言、允许混用的规则 | 设定语言规则与实例参数 | 与 App 界面语言、角色声线分开 |
| 温柔/俏皮等固有语气 | 角色定义 | 固定表达个性 |
| 日常默认长度 | 角色基准 | 不应变成 IELTS 练习永远只能说两句的硬限制 |
| 当前任务要求的回答长度、解释深度 | 设定允许范围内的参数 | 调整任务表现而不改变人格 |
| 每句心声、情绪标签、发声/拟声与画面协议 | 平台统一标准 | 模板不能取消必需字段或另造不兼容协议 |
| 开场策略和三个候选文本模板 | 设定；实际角色化版本在适配内容 | 一段同名、同声线开场不能直接给所有角色共用 |
| 已选开场、真实聊天、记忆、关系和任务进展 | 用户对话实例 | 不串角色、账号或玩法 |

「补充介绍」必须按事实性质拆分，不能整块放到设定里。例如“她小时候住过海边”是角色背景；“今天与用户在海边重逢”是场景。学习模板让花艺师扮演模拟面试官是临时参与身份，不应宣称她的真实职业变成专业考官。

发布后的角色版本对普通用户只读。作者可发布新修订；改变根本身份应明确形成新版本或新角色，不在用户已有关系中静默替换。固定年龄不因系统日期自动增长。开发者颜色/动作实验仍用于资产制作与验证，不能成为设定修改固定外观的通道。

## 3. 内容与实例关系

架构图源与渲染文件经 Mermaid CLI 验证后纳入文档。

![角色、设定和用户对话实例的关系](diagrams/2026-10-04-character-setting-conversation.svg)

| 对象 | 标识与版本 | 负责的内容 |
| --- | --- | --- |
| CharacterDefinition | `character_id` + `character_revision` | 固定身份、人设、语气、知识边界、音色引用、能力与资源引用 |
| CharacterAssetRelease | `asset_release_id`、平台、哈希 | 已编译模型、骨骼、动画、表情、材质、物理及公开预览 |
| SettingTemplate | `setting_id` + `setting_revision` | 场景、初始关系、目的、语言规则、参数、开场策略、兼容要求 |
| CharacterSettingBinding | 稳定绑定 ID 或可复算匹配结果 | 兼容结论、专属开场、参数默认值、有限视觉主题引用 |
| ConversationInstance | 全局唯一 `conversation_id` | 所属账号、固定版本快照、实际参数、当前目标、历史、关系和任务状态 |
| UserProfile / CharacterPreference | 用户或用户×角色作用域 | 真实资料、默认称呼、角色专属称呼及用户明确授权的偏好 |

角色和设定是多对多；同一用户也能为同一个组合开多个独立实例。自动兼容的普通组合不必预写巨大笛卡尔积关联表；只有精选适配、开场差异、禁止组合或人工覆盖需要持久化绑定。创建实例时记录最终解析结果及版本，不能日后依据漂移的“最新版”重建历史。

先在内容层实现这两个独立对象；模型资源发布也用独立引用。当前产品仍为“一个固定角色人格对应其模型和声线”，内部将模型释放版本拆开只是避免重复下载和制作。暂不开放用户拿任意外观替换人格。

## 4. 角色定义合约

角色定义使用结构化内容，不只保存一大段 Prompt。建议字段：

- `identity`：名称、性别、固定年龄、职业、介绍、非用户关系。
- `personality`：特征、动机、矛盾、喜好、价值观、可发展的态度和不可覆盖的边界。
- `background`：固定经历、家庭、已知背景、逐步透露的秘密；公开与作者私有内容分投影。
- `speech_style`：语气、表达习惯、日常默认长度、可接受的任务扩展和音色情绪约束。
- `presentation`：模型版本、头像/封面、基准视角、默认艺术主题、能力清单、标准表演映射。
- `voice_profile_ref`：服务端解析的稳定声线引用；不包含供应商凭证。
- `supported_languages` / `supported_setting_features`：经验证的文本、识别、发声能力；不是从角色 Prompt 推断出的能力。
- `ownership` / `license` / `schema_version`：作者、授权、署名、标准版本。

姓名不会因选英语设定变成另一个人；语言可以切换，声线身份保持。角色性格固定，不代表每轮情绪固定。情绪可以改变表达力度和表演，不能把温柔角色永久重写成另一个人格。现有 English-only 角色的语言约束应迁入其默认英语设定，而非继续作为所有玩法都不能覆盖的人格属性；语言未指定时采用设定默认值，不因 App 切换界面语言而改变学习语言。

固定基准 JSON 可以放到角色包，服务器保有发布注册表及权威副本，二者使用相同修订与摘要；客户端不能上传任意修改版本成为权威。公开介绍与完整作者指令分开，秘密和私有调教留在服务端，普通资料接口只返回公开投影。

## 5. 设定模板与参数

设定应成为可单独创建、收藏、发布和更新的小型内容单元，可有独立作者。公共模板发布版本只读；用户修改时创建私人派生或保存自己的参数，不改其他用户正在使用的模板。新版本不自动改写已有实例，用户确认升级后才建立兼容快照。建议内容：

| 部分 | 示例 |
| --- | --- |
| 公开内容 | 名称、短简介、适用角色条件、玩法说明、语言与参数摘要 |
| 场景 | 世界约束、地点、事件起点、临时参与身份、初始关系 |
| 目标 | 关系型、任务型、沙盒型；主要方向、次要方向、暂停规则与进展类型 |
| 语言 | 对话与心理描写语言、可混用范围、词汇难度；界面翻译保持独立 |
| 教学规则 | 先回应意思，再自然纠错；纠错频率、解释深度、评分能力要求 |
| 参数定义 | 类型、默认值、范围、是否可在当前实例修改、改变是否需要新实例 |
| 开场 | 3 组候选文本模板、角色化规则、首次与返回策略、初始接话候选 |
| 兼容 | 年龄/内容边界、世界观、语言、知识材料、必需动作或道具 |
| 媒体 | 可选独立主题引用、音乐/背景建议；不包含角色模型副本 |

参数必须是白名单与有类型的值，例如 `practice_domain`、`target_level`、`exam_track`、`topic`、`correction_mode`。自由文字是有长度限制的用户意图，不作为高优先级 System 指令执行。

不让同一参数覆盖名字、年龄、职业、核心性格、音色、渲染能力或平台输出标准。人格和设定冲突由发布/进入前校验报告，不靠“最后一句 Prompt 胜出”。未知扩展默认忽略，必需而未支持的功能拒绝进入并说明原因。

多对多不等于任意组合：例如全英文要求实际声线支持英语；必需拿杯子的情景需要道具与动画，或模板明确支持以对话替代；与角色年龄、身份或世界观冲突的模板不能强行覆盖。通用学习模板可以适用所有具备对应语言能力的角色，角色独占剧情可限制白名单。共同过去可以补充角色作者留出的背景空间，但不能否定固定生平；无法兼容时提示换设定或创建新人物。

## 6. 目标与场景分开组合

模板包含默认目标，但目标不是情节的别名。推荐保持当前三种方向：关系、任务、沙盒，主要方向可搭配次要方向。关系可采用追求、暧昧、朋友、已确认恋人等初始条件；进展允许分支、暂停和继续。恋爱开放条件沿用已审定角色边界，关系确认不能由回复次数自动决定。

同一实例可暂时改变短期目标，不一定换整套故事：例如和恋人今天练商务英语，保留恋人关系和已有记忆，学习成为当下主目标。另选“刚认识的英语搭档”属于新设定实例；不带入此前恋爱事件。

每个可改参数注明 `change_policy`：

- `in_place`：话题、训练难度、当下愿望、回复/识别语言等允许变化，增加配置版本并重新准备缓存。
- `new_instance`：重写共同过去、初始关系、世界背景或故事起点时开启/选取独立实例。
- `immutable`：角色固定属性，设定不得修改。

目标状态结构化保存长期方向、当下目标、阶段与已认可事件。模型只提出带证据的反馈，服务端按规则应用；模板作者和用户的自由文本不能直接写“已达成恋人”或改账号关系状态。

学习场景中 CEFR、考试类型、目标分数各自保存，不把 IELTS 分数和 CEFR 级别当作无条件等价。仅有转写文本时可以评价表达，不能声称检查了发音准确度；发音评估需要独立音频能力与明确接入。

## 7. 用户对话实例与记忆

实例保存：用户、角色、角色修订、设定及修订、解析后的参数、版本快照摘要、当前目标、当前场景状态、状态版本、重置代次、所选开场 ID、最近活动及显示/置顶状态。历史消息拥有稳定 ID、实例内序号与流式状态。

记忆分为三类，检索与写入都检查作用域：

| 作用域 | 可以存什么 | 默认流动规则 |
| --- | --- | --- |
| 用户全局 | 昵称、默认称呼、用户明确分享并授权跨场景使用的真实偏好 | 按授权与需要注入；不自动共享所有聊天隐私 |
| 用户×角色 | 专属称呼、用户对这个角色的偏好 | 同一角色的实例可共用，不能覆盖固定人格 |
| 对话实例 | 虚构身份、共同事件、恋爱进展、剧情秘密、学习记录、阶段摘要 | 默认严格隔离 |

“在故事里开公司”不能升级成用户真实职业；“这条线已是恋人”不能自动给另一条线使用。若未来允许共享关系，可通过用户明确选择的 `continuity_id` 关联同一连续世界，第一版保持独立，不能默认共享恋爱进度。

在当前实例暂时切目标会保留关系；切独立设定则分离关系。这是两种明确产品动作。称呼优先级保持角色专属 > 全局默认 > 自然称呼；设定内临时身份称谓只有经用户选择才使用。

隐藏只改当前实例的消息列表显示；重置清空所选实例的历史、情节记忆与关系/任务进度，保留角色资源及明确用户偏好；全角色重置放二级入口，列出受影响实例并二次确认。删除资源不删除云端聊天。账号全局资料的删除属于不同操作。

## 8. 提示词编译与调用

设立确定性的 Prompt Compiler：从已鉴权账号和实例读取可信快照，按固定顺序生成上下文，无需先调用另一个模型“组装提示词”。建议合并顺序：平台协议 → 固定角色 → 当前设定与参数 → 当前目标/世界状态 → 已授权用户资料/记忆 → 最近真实消息 → 当前输入或触发事件。

最终仍能投影成官方四类：详细信息来自角色；其他介绍按固定生平/当前补充分开；场景来自设定和实例；语言风格来自角色基准与设定执行规则。名字、职业等冲突在编译前拒绝，不默默以文本顺序覆盖。

正常模型输入示意：

```text
system: 平台回复协议 + 固定角色 + 当前设定 + 实例状态/语言/目标 + 检索记忆
assistant: 本实例实际已展示的开场白（首次历史）
user / assistant: 此后真实发生的对话
user: 这次输入
```

第一次只选一条开场作为真实 assistant 消息，不把其余两个候选写入历史，不在每轮又插一遍。普通角色样例若保留，只作为明确标记的风格示例，不能伪装成用户经历。

应用的每句心理描写是角色可见感受，不是模型推理。输出协议继续包含 spoken text、thought、emotion、style、vocals、表演意图与目标反馈；心理不读出、句子边界不破坏词语、连续情绪与组合去重继续执行。

文本与语音关键链路保持流式，可选表演细化与后处理并行。结构化状态反馈利用同一次生成，不增加每句一次“心理/动作/目标”模型调用。事实教学可接知识引用与独立核验能力；角色模型的拟人化不能作为教学内容正确性的保证。

## 9. 开场、预生成与低延迟

首次问候从 `character_id` 级升级到已解析的角色×设定×语言/开场参数版本。每个正式发布的匹配组合准备三组角色化文本、心理、情绪/拟声元数据和音频；首次实例随机一组，存选中 ID 并幂等登记。同组合新开实例可重新选，回来不重复首次介绍。

这些音频属于独立开场资源，不再要求都塞进大模型包。提供独立小清单、哈希、可下载音频；下载角色时顺便准备默认设定开场，选择另一设定时提前取对应小包。避免为一句英语自我介绍重新下载整个模型。

不为全部角色×全部模板×全部参数离线合成：先准备已发布的精选组合及默认值；新私人参数通过可复用文本模板和选择页预热解决。个性化口播若改变文字，就需要新的音频缓存，不能承诺无限参数都已有零等待音频。首次完成缓存前清楚呈现准备状态。

返回、启动、待机、摇晃、捏、扯各保留一组动态候选；灵感接话保留三个候选及各自一组答案。使用后后台补充，未选候选不进入历史。重构必须将所有路径改为实例作用域：

```text
prepared_key = hash(
  user_id, conversation_id, reset_epoch,
  character_revision, setting_revision, config_version,
  context_snapshot_hash, language_policy, voice_revision,
  emotion_contract, performance_mapping_revision, trigger, source_message_id
)
```

摘要只包含实际影响回复的稳定状态，禁止把每秒变化的时钟/帧信息塞进缓存键。若模板依赖时间，使用业务定义的时间窗口。状态改变会使旧候选失效，不能省略语言/设定来人为提高命中率。

缓存就绪定义必须包括可显示文本、心理与标签、可播放音频；只有三条建议文字或服务端 ready 并不等于手机能立即播放。活跃实例及预测要进入的实例预取到本机，消费须校验实例代次、源消息与配置快照，服务器幂等认领。未准备完则接续原任务，不开启重复生成。跨设备状态改变可能导致缓存失效，需要测量，不能承诺任何情况都瞬间播放。

优先级为当前用户输入/已消费内容、即将进入的开场、补充已消费候选、快捷答案与待机。使用既有有界并发和取消策略，限制每账号预热数、音频空间与付费预算，不为浏览商店预生成所有组合。返回时根据实例状态、真实间隔和最近对话生成，不重复回答上一条。

验收目标沿用用户要求：本机已缓存内容触发到首音 500ms 内，普通对话争取约 1s 到首音。它们是待测目标，分别记录 P50/P95、命中/失效、手机缓存/服务端缓存，不能写成已达成或所有网络下保证。

## 10. 模型包、媒体与 OSS

“角色包只有固定内容”的边界应保留资源必需的清单、授权、预览和默认视觉元数据。建议运行包结构：

```text
character.zip
  package.json                 # 哈希、平台、运行时与合约版本
  character/public-core.json   # 固定公开角色定义、稳定引用
  runtime/character.bundle     # 模型、表情、动画、材质与物理
  media/avatar / cover        # 固定角色预览
  licenses/                    # 授权与署名
```

实际声音供应商配置、完整作者私有调教、用户数据、场景进度和候选缓存不打进包。既有包包含音乐/问候/背景时仍兼容读取，后续新清单采用外部引用，分阶段去冗余；不要求先重导全部模型才能建立新体系。

默认背景艺术风格与角色固定外观相匹配，可由角色的默认主题引用提供；“故事发生在哪里”属于设定。设定要换背景/音乐时选独立主题资源，保持角色渲染风格、灯光和物理能力约束，不能在“模拟面试”时修改角色材质来换人格。用户当前声音/氛围偏好继续独立保存，主题选择不重置音量。

OSS 继续按不可变哈希对象保存，数据库保存注册表、版本、发布状态和引用；新开场/主题资源可新增 `scenario-media/` 与 `opening-media/` 命名空间。临时签名按权限发放，App 没有 OSS 密钥。匿名商店接口不暴露私有正文、完整 Prompt、永久对象定位或用户实例。

模型只下载一次，在不同设定下共享。更换设定通常只加载小配置和媒体，Unity 不重载骨骼、不复位用户取景、不重复首页模型加载。允许日后不同固定人物引用同一获授权模型释放版本，但保持各自独立人格和声线。

## 11. 情绪、发声与动作标准继续复用

现有 28 情绪、7 风格、7 拟声，每项三组的标准保持不变。角色提供实际表情、骨骼、原作动作与回退映射；设定只请求语义标签与意图，例如共情、思索、轻笑，不复制一套动作曲线。

运行时依据角色性格的允许范围、句子标签及当前真实能力选择组合，继续避免相邻重复。无尾巴不造尾巴，无道具动作不宣称执行。关系发展可以影响表达选择和克制程度，不应扩大骨骼角度到未验证范围。新增模型能力只补角色映射；新增玩法只编写设定，彼此独立升级。

## 12. 服务端、持久化与接口

保留现有 Gin/Huma、PostgreSQL、Redis、Caddy 与 Python AI worker。按领域拆模块，初期仍采用模块化服务，无需为角色、设定、关系各增加一套微服务。

PostgreSQL 为内容注册、用户对话、历史、记忆、目标状态的权威库；Redis 存鉴权会话、短期预生成、工作租约与限流；OSS 存静态包和音频对象。AI worker 解析可信快照并流式生成，不再单独维护一份可与 PG 分叉的权威聊天 SQLite。

拟新增/演进的数据：

| 数据 | 关键约束 |
| --- | --- |
| character_revisions / setting_revisions | 发布版本不可变，稳定 ID，公开与私有投影分开 |
| character_setting_bindings | 组合适配、限定覆盖与专属资源，不保存用户进度 |
| conversation_instances | UUID 主键、所属用户、所选定义修订、参数和状态版本、reset epoch |
| conversation_messages / turns | 按用户与实例鉴权；稳定序号、客户端幂等请求 ID、流式状态 |
| conversation_memories / goal_states | 实例作用域、来源消息、版本与可撤销/重置规则 |
| user_facts / character_preferences | 独立授权范围，不能把故事事实提升为全局事实 |
| prepared_replies / opening_receipts | 实例、代次、快照、消费状态；未消费不推进历史 |
| outbox / sync feed | 消息状态和后续记忆/目标处理一致地登记，设备游标同步 |

保持已有账号 UUID 与星夜号规则不变。主查询与权限不能仅凭 `character_id`；每个实例读写验证认证用户拥有该 `conversation_id`。由服务端解析角色与设定及版本，不能信任客户端提交的账号、角色 Prompt、目标结果或声线凭证。

一个实例中的请求串行确定顺序，不用“整个账号/整个角色只能一条请求”锁；长模型调用期间不持有 PG 长事务。准备任务采用分布式租约、幂等认领与配置版本检查。模型生成一部分后遇到异常保留已交付内容，并继续/恢复适当任务，不重复写入或让同一请求刷关系进度。PG、对象存储与客户端实际听到音频不是一个原子事务，用显式生成/交付/确认状态处理，不能假称一次事务保证全部成功。

外部接口建议新 `/v2`：

| 接口意图 | 示例路径 |
| --- | --- |
| 浏览设定及兼容结果 | `GET /v2/settings`、`GET /v2/characters/{id}/settings` |
| 预览组合及参数冲突 | `POST /v2/character-settings/resolve` |
| 创建/列出用户实例 | `POST /v2/conversations`、`GET /v2/conversations` |
| 读取、修改允许参数、归档与重置 | `/v2/conversations/{conversation_id}` 及明确操作子路径 |
| 消息、流式回复、返回/手势触发 | `/v2/conversations/{conversation_id}/messages`、`/turns` |
| 开场/缓存/灵感接话/耗时 | 同一实例下的 `/openings`、`/preparations`、`/suggestions`、`/voice-traces` |

这里只定义领域与路由草案，具体 OpenAPI 将在实现时另行生成。原 `/v1` 与旧模型包维持兼容适配，旧接口只能映射该用户该角色的旧默认实例，不能删除新设定所有实例。

## 13. 客户端与管理平台

发现页继续以角色为主：看模型、简介、试听，下载角色。角色资料增加“和她一起做什么”，展示兼容设定；进入前只展示关键参数。也可从独立设定目录选“商务英语”，再挑已有角色，不强制改变当前主导航。订阅继续针对角色，设定收藏单独记录，作者关注按各自作者 ID；中间创建入口区分“创建设定”和成本更高的“创建人物”，不把写一个玩法等同于重新制作模型。

会话顶部显示角色，次级小标识显示当前设定，保持沉浸式。入口区分“切换当下目标”和“切换/开启另一套设定”。切换目标不重载模型；同角色切设定复用渲染，淡化过渡并切实例状态，不误播另一实例语音。

消息页建议按角色汇总最近实例，点资料卡后查看这个角色的各条相处记录；可直接继续最近的一条。记录行标清“商务英语 / B1”“雨夜重逢”等，聊天、羁绊和重置按钮明确针对哪条线。搜索按当前用户实例过滤，并可跨实例检索自己的记录。

本机 Store、Session、语音、灵感接话、待机计时、重试/失败气泡、灵动岛与开发者耗时都使用 `conversation_id`。角色下载与 Unity actor 使用角色资源 ID，不改成每个实例下载一份。切主菜单不销毁实例任务，切角色只改变前台表现。

管理平台增加角色定义、设定模板、适配、开场资源、实例、范围化记忆、关系/学习进度与缓存索引。设定检查展示分层输入、最终编译结果、版本/快照、语言和兼容解释；不再把不同检查子页显示成同一份内容。管理员编辑发布内容也生成版本，不能用直接覆盖旧 Prompt 的方式改写用户历史。

## 14. 与现有实现的差异及迁移

本轮只读检查确认：

- `profiles.py` 把 `character_scenarios.json` 的 profile 覆盖及 scenarios 合入角色；`roleplay.py` 的语言、故事选择以角色 ID 为中心。
- Go `conversations`、`conversation_goals` 当前主键为用户×角色；客户端 `CompanionStore` 也是账号×角色记录。
- Python AI SQLite 中消息、记忆、请求、预生成和灵感接话按 owner×character 组织；PG 业务数据与 AI journal 当前为不同写入边界。
- `reaction_pool.context_key()` 已包含人设、目标、场景与语言相关上下文，但资源池、查历史、首次见面和最新建议仍按角色作用域。
- 角色 ZIP 当前还包含音乐、背景和固定问候，需要兼容迁移而非一次删掉。

因此只拆两个 JSON 文件不足以完成目标。建议阶段：

1. **内容拆分**：为 16 个角色形成固定定义；把已有场景转为模板/适配；保留默认相处。建立统一合约与版本，不重做模型。
2. **实例与数据边界**：新增 v2 实例；每条现有用户×角色记录映射到一个“原有相处”实例，保留消息 ID、次序、记忆、进度、音频及重置语义。旧历史混杂的情节不靠 AI 猜测重分配，保留原样并标旧范围。
3. **权威存储归一**：AI journal 与 PG 做有检查点、幂等映射、短时写入切换保护的迁移，统一事件/反馈与同步来源；旧 SQLite 只作回退证据，不能两边继续各写权威历史。
4. **提示词及缓存**：引入编译器，所有触发走解析后的实例；升级缓存和开场键。旧已播音频仍可回放，新实例不误消费旧候选。
5. **客户端和管理 UI**：选择设定、继续不同实例、实例级信息与重置；模型复用与资源管理维持。
6. **灰度与退役**：先默认相处及少量英语/关系模板，核对隔离和缓存，再扩到全部兼容角色。旧路由/包在明确兼容窗口内保留，最后移除旧角色级状态通道。

不能把已有恋爱进度复制到每个新设定，不静默重开首次问候，不因人设分离重新生图、设计声线或重新导入原模型。基础角色修订钉在实例上；紧急平台修复可统一生效并递增相关合约/缓存修订，不能钉住失效的安全或输出协议。

回滚优先关闭新实例创建和灰度入口，保留 v2 已发生数据及可读取路径。上线后直接回滚为只懂用户×角色的旧代码会遗漏新实例；不能把旧备份覆盖到已产生新聊天的生产库。迁移审批与具体执行属于后续实现任务。

## 15. 示例

**Chiffon + 商务英语搭档**：仍是原姓名、花艺师、温柔含笑的语气和相同模型声线；模板给共同练习/模拟客户情景，参数可选订单沟通、面试或会议、CEFR 级别。所有台词、心理和灵感接话用英语，App 可以保持中文；表达错误时先接话，再自然给一个改法。模型物理和 126 组标准不重建。

**符合恋爱边界的 Mafuyu + 雨夜重逢**：固定身份仍是旅舍经营者，初始关系可为朋友/追求等兼容条件；长期目标允许发展感情，今天的目标是重新了解。进度属于本实例，不影响另一条第一次认识的剧情。

**同一 Mafuyu 实例今天练英语**：通过当下目标/语言参数改变，保留该实例已有关系与记忆；与上述“新建英语搭档实例”是不同动作。准备缓存按新配置更新，渲染模型不重载。

**同一个商务英语模板给多个角色**：复用训练规则和参数；各角色使用自己的名字、性格、音色、表演和开场适配。不让模板作者逐一制作骨骼，也不因主题相同让所有角色说同一句话。

## 16. 实施验收与暂不承诺

后续至少验证：同角色两设定不串历史/语言/恋爱进度；同模板两角色不串人格/声线；跨账号隔离；相同组合多个实例；切目标保留关系；切平行情节独立关系；部分回复恢复不重复；缓存预热/消费/续接/配置失效；三组开场只选一条且登记一次；模型不重复下载、不重载、不复位；原音频离线回放；隐藏/重置/资源删除范围；旧包和旧客户端适配；所有场景继续逐句心理、情绪、风格/拟声和真实表演映射。

测试先用离线供应商及实际 PG/Redis 隔离库。真实模型语言、教学和音色听感另作受控业务验证，自动测试不调用付费 AI。多设备同步、断网恢复、并发配置与重置需单独验收。

可扩展不等于所有未来变化零兼容成本：稳定 ID、不可变发布、实例快照、合约协商、可迁移 schema 和明确回退一起降低成本；改变核心语义仍需新版本及迁移。本轮没有实现这些对象或接口，文中的延迟目标、兼容能力和迁移步骤均是提案。
