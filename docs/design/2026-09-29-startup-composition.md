# 星夜 0.24 · 独立启动开场与首帧最终取景

本轮只调整手机版的启动、角色入场和气泡留白；不改角色模型、动作资源、取景偏好、角色协议或已有账号资料。

## 角色出现时直接使用最终取景

上一版的渲染确认已经等待了外观、背景、姿势、镜头稳定，但宿主在揭开窗口之后又发送 `session.enter`。角色规则把该事件映射为招手，招手要求全身构图，因此发生“先拉远招手，再拉近聊天”。这不是资源尚未加载完成，也不能通过延长淡入解决。

取消宿主入场时自动发送的 `session.enter`，保留协议本身。依旧先应用该角色保存的取景，再等待三个稳定渲染帧，最后只对窗口透明度做淡入；不动画改变相机距离、位置或视角。自然待机、注视用户、轻触头部以及用户通过聊天主动触发的动作继续有效；主动的大动作仍可按既有规则暂时调整构图。

## App 启动与进入角色是两种场景

| 场景 | 呈现 | 结束条件 |
| --- | --- | --- |
| 进程冷启动 | 全屏月白星月标志、星夜字标与“每一句，都有回声”；没有角色名、轨道或底栏 | 品牌开场与初始内容准备均完成 |
| App 内实际换角色 | 已有的细星轨、呼吸光与角色名字，保留底栏 | 对应角色通过 `presentationReady`，满足最短展示时间 |
| 同一角色跨菜单、后台恢复 | 直接恢复驻留会话 | 不重新播放启动或角色入场动画 |

系统静态 LaunchScreen 使用同色 `LaunchNight`（#101114），避免启动动画前出现浅色背景。`SceneDelegate` 先提交一个独立的原生窗口，层级为普通窗口 +3，高于原生角色加载窗口与 Unity。80ms 后再创建账号/目录/会话协调器并开始引擎初始化，让品牌动画先完成首次提交。

`AppStartupController` 使用 UIKit + Core Animation：标志轻微聚拢、字标与副文案顺次淡入，正常开场约1.2秒；等待时接续3.6秒一轮的呼吸、光晕与沿矢量轮廓掠过的流光。循环动画在首次提交时就排入图层时间线，不依赖主线程的开场完成回调，Unity 同步初始化期间由系统图层合成继续播放。采用现有矢量PDF，不增加位图序列、外部动画库或网络资源。机制参考 [Apple Core Animation 指南](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/CoreAnimation_guide/Introduction/Introduction.html)。

加载与开场同时进行。内容早就绪时只等待开场剩余部分；开场结束但内容未就绪时继续呼吸，不显示假进度，也不反复重播开场。角色场景通过渲染确认并完成其下层窗口淡入后，通知启动窗口用0.55秒退出，释放窗口与回调，再恢复当前页面的辅助功能访问。首次启动只出现品牌开场，避免再叠一遍角色加载动画。

空关注账号或测试中的非聊天首屏不需要等待 Unity。角色准备失败或前台超时也结束启动遮罩，显示已有可返回的错误状态。进入后台暂停品牌图层时间，回来续播；完成后的后台恢复不再创建启动窗口。启用“减弱动态”时不播放聚拢、呼吸和流光，仅短淡入淡出。

这一版改善等待期间的可见反馈与连续性，不宣称模型解析、Unity 初始化或冷启动总耗时已显著降低；未用模拟器录像推断真机帧率。

## 气泡正文上下留白

继续使用单个连续轮廓与左上语音区域。轮廓正文肩部位于23pt，正文起点从44pt移至35pt：正文上方留白由21pt降为12pt，与底部12pt对齐。播放图形和简写时长保持原位置与小尺寸，44pt触碰区向上延展，不压入正文，也不新增单独语音气泡。

验证包括四角色首次构图与3秒后相机一致、初始场景的连续相机采样、冷启动等待/后台恢复、角色切换动画、语音按钮实际播放与停止，以及收紧布局后仍保有44pt触碰高度。结果见 [本轮验证](../verification/startup-composition/README.md)。
