# 小伴 · 沉浸式聊天（0.6.1 / build9）

## 设计决策

用户明确要求角色成为页面主体，聊天在底部半透明渐变。保留现有品牌色：暖白 #F7F5F0、墨绿 #274A43、次级绿 #5B7168、浅玉 #B8D5C5、浅桃 #E7BCAD。标题使用系统圆体 medium（21pt），正文系统字体16pt，状态10–12pt；保留已有中文系统字体。

删除原有“上方角色、下方大卡片”的分区：Unity 场景延伸到整个页面，原生控件覆盖其上。下方聊天宽度最多700pt，常规高度最多320pt／屏高34%，手机和平板都贴近底部；长对话在该区域内回看，不显示滚动条。唯一视觉重点是角色实体穿过聊天渐变仍然可见。

最初全屏截图显示脸偏低，因此对话近景按纵横比上移构图，横屏减少上移量；全身动作平滑撤掉上移，不跟踪逐帧头部动画，避免镜头随呼吸晃动。仍保持原有有限大小和角度设置，未恢复自由拖拽和缩放。

底部从完全透明过渡到82%暖白，气泡与输入栏保留独立半透明底，兼顾静夜背景可读性。顶部轻渐变保护导航文字。减少透明度辅助设置下提高局部底色，不改变功能。不会为制造玻璃感叠加全屏实时模糊。

## 实现与验证边界

- UIKit 只绘制渐变，不截获裸露角色区域触控；SwiftUI 仅占聊天底部范围。
- 竖屏键盘推高并压缩聊天区域，不缩小Unity视口或让相机跳变。iPad横屏大键盘出现时聊天移到右下方，避免输入栏横跨嘴部；收键盘后回到底部居中。
- 定制／取景面板打开时暂时隐藏聊天，把角色预览完整放在编辑器上方；关闭、取消、下拉收起时恢复全屏聊天。避免身形、衣物和全身取景被面板挡住。
- 原生向 Unity 发送 immersive 标记；导出 framingProtocol 升到2，构建门禁拒绝混入旧视口实现。
- 本轮验证针对全屏背景、头部点按、键盘、消息、静夜和iPad旋转。结果及实际截图另存 docs/verification/immersive-chat。
- 本次改变构图与UI，不把模型资源质量或持续120FPS视作新验收结果。
