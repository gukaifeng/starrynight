# 按住说话交互修复 · 0.72

2026-10-01，星夜 / StarryNight。源码版本 0.72.0（99）。本轮修改原生录音交互与显示，不更换百炼 ASR、角色或音色。

## 操作约定

- 按下立即显示录音反馈，初始手指持续控制本次录音；离开输入框不等于结束。
- 上滑进入可见编辑区域时，区域提高亮度、显示“松开，编辑文字”，给一次轻触反馈。此时仍录音，不展开键盘。边缘保留 16 pt 退出余量，避免小幅抖动反复亮灭和震动。
- 滑回区域外，恢复“松开发送”；只有手指真正松开才确认操作。
- 在编辑区域松开，立即以现有识别文字打开编辑器。最终识别结果可以补全文字，但用户一旦修改，任何迟到结果都不能覆盖修改。取消或发送会停止余下 ASR 工作。
- 其他位置松开，等待最终结果后只发送一次；若最终结果已提前到达，则在松手时发送。识别失败或超时保留文字供确认，不自动发送不完整结果。
- 系统取消触摸不会发送消息；当前页面仍在时，已识别文字保留为编辑草稿。离开会话或 App 进入后台沿用现有停止录音规则。键盘输入草稿独立保留。

## 原因与实现

| 原问题 | 处理 |
| --- | --- |
| `translation.height < -64` 时立即结束录音、切换编辑器，移除了原手势视图 | `VoiceHoldSurface` 使用连续 UIKit 手势保留最初触摸；编辑区只切换 armed 状态，结束事件决定编辑/发送 |
| `VoiceInputDraft.accept` 不区分用户松手和服务端完成，提前完成会直接发送、关闭 | `VoiceCaptureState` 分开维护触摸阶段、识别是否完成、编辑意图和人工修改；Observable 包装供 SwiftUI 使用 |
| 任意 `speech.error` 都关闭语音界面，恢复文字也可能随之消失 | 删除泛化关闭监听，录音失败统一走 `onCaptureRecovery`；按住时保持界面，松手后进入确认 |
| 同时处理音频中断开始与结束，结束通知也会清状态 | 仅对中断开始处理停止 |
| 音频引擎创建仍发生在主线程 | `MicrophonePCM` 的创建硬件、启动、停止、释放均由同一音频队列处理；界面先响应按下 |
| 浮层与宿主坐标可能不同，横屏/侧栏容易错判 | 编辑区域用不接收触摸的 UIKit 锚点，和手指通过同一个 UIWindow 转换坐标；不假设 SwiftUI global 就是窗口坐标 |
| 录音时 UI 层级、话题和装饰层影响输入 | 输入层级固定；话题占位保持；透明装饰不截获触摸；录音期间禁止聊天滚动与辅助弹窗、模型反应抢占 |

开始后的部分结果、最终结果、错误、松手，允许不同先后顺序。旧请求仍由 CloudSpeech 的 generation 标识失效；状态机额外保证重复完成、重复松手、取消后结果不能再次发送。

## 视觉与性能设计

使用 `frontend-design` 技能，沿用默认月白及其他主题的颜色。原拱形面板改为圆角深色玻璃卡片：顶端轻量状态、细声纹、固定高度实时文字、底部完整的编辑落点。轮廓使用很淡的主题渐变；高亮只作用于编辑落点，不做突兀的大幅位移。横屏使用紧凑尺寸，编辑器继续适配键盘剩余高度。

切换到语音模式时预先挂载录音卡片，按下主要执行 0.18 秒淡入；隐藏时不发布控制命中区域、不拦截聊天、也不进入辅助功能导航。实时文字最多两行且区域高度固定。波形自己观察输入音量，不以音量刷新整个聊天树。编辑 hover 只在进入/退出时发布状态，手指的每个 move 不重复重建 UI。减少动态效果时缩短为淡入；减少透明度时使用实色表面。

这属于减少主线程工作、固定手势生命周期的实现改进，尚未完成新版本真机帧时间测量，不能据此宣称持续 60/120 帧。
