# 角色主动问候 · v0.27.0

> 历史设计。后续用户要求「已经说过就不再说」，当前自动触发规则已由[会话再进入与默认音乐](2026-09-29-conversation-entry-audio.md)替代；下文的每次返回问候仅保留作为设计历史，不代表当前行为。

让进入对话成为角色先开口的相遇。已登录和游客共用同一套规则；若用户主动取消全部关注，仍保留原有空状态，只有真正进入角色会话才问候。

## 场景与文案

| 场景 | 判断 | 本地文案示例 |
| --- | --- | --- |
| 首次启动、初次相遇 | 当前账户从未与任何角色相遇 | 你好，我是初音未来。欢迎来到星夜，很高兴认识你。今天想聊些什么？ |
| 初次认识另一个角色 | 该角色没有历史消息或问候记录 | 你好，我是Luma。这是我们第一次见面，你希望我怎么称呼你？ |
| 启动App、回到熟悉角色 | 角色已有历史 | 晚上好，又见面了。今天过得怎么样？ |
| 返回已有会话 | 从消息或其他菜单回到角色 | 回来啦，我们接着聊。 |
| 再次选择熟悉角色 | 从发现或创建入口选择已有关系的角色 | 又来找我啦。上次的话题想接着聊，还是说点新鲜事？ |
| App从后台回来 | 会话曾经显示，且确实进入过后台 | 回来啦。刚才的话，还想接着说吗？ |

早上／中午／下午／晚上使用本地时区。仅有助手问候、用户还没开口的关系不假装已有具体话题。离开至少三天时可提及几天没见，以最新真实活动时间判断；时钟倒退不产生虚假的长时间离开。文案应用定制名称、活泼或理性性格、温暖语气与简洁偏好，多次返回轮换短句，避免相邻问候完全一致。目前来自本地模板，不宣称已接入在线推理或能理解任意历史主题。

## 触发与生命周期

- `ConversationEntry` 表达一次进入，携带唯一ID、进入原因、账号和角色。首次打开与驻留角色恢复均在窗口交接完成后交付；启动时还须等独立启动动画退出。
- `greetVisibleConversation` 要求App活跃、会话可见、目标账号和角色匹配。取消加载、切换菜单时清除待交付进入；退出页面沿用既有语音任务取消机制，不让旧角色延迟开口。
- 每个进入ID只保存一次。SwiftUI重绘、重复就绪回调、已经在首页时重复点击首页、打开和关闭资料卡均不算新进入。真正去别的菜单再回到会话仍问候，不设置会吞掉用户明确要求的时间冷却。
- 从发现直接去定制时，先等资料／定制关闭；配置保存保留这次待问候，使角色用新名字和偏好开口。用户主动发送或录音优先，清除未交付的问候。
- 区分系统临时失活与真正进入后台。权限面板和控制中心造成的失活不会凭空追加重逢问候；`sceneDidEnterBackground` 标记后，激活时才创建后台返回场景。先置为非活跃再收束转场，防止同步完成回调在后台误发问候。

## 数据和声音

`CharacterRecord.greeting` 是可选的关系记录，包含问候次数、最后时间、最后文本和进入ID。`CompanionMessage.proactiveScene` 是可选字符串，旧存档无需重建；旧的正常消息同样视为认识过，游客转新账号沿用现有资料迁移。所有字段继续使用现有账号＋角色实例隔离，问候不调用 `countGuestTurn`。

`DialogueProviding.greeting` 单独接收场景上下文，为后续在线问候保留入口。消息保存成功后才朗读，使用角色已有声音与速度；静音不被主动问候覆盖。复用 `LocalSpeech` 的取消、缓存、实际时长、口型与头像波纹。

主动问候只发送现有 `expression.request` 表情事件和说话状态，不发送 `session.enter` 或 `dialogue.greeting`。这两个事件在现有角色包中会触发全身招手及取景拉远，不能为了开口重新引入用户已经要求删除的入场变焦。Unity、模型包和导出版本无需变化。

## 依据

按用户约定先通过 find-skills 和 skills.sh 检索。阅读并采用 [AvdLee Swift Concurrency skill](https://github.com/AvdLee/Swift-Concurrency-Agent-Skill/blob/main/skills/swift-concurrency/SKILL.md) 的界面状态隔离、任务所有权及取消原则；本项目已显式使用 Swift 6 和主执行器维护会话状态，没有增加并发逃逸标记或新运行时依赖。检索结果保留在 `.local/checks/greeting-skill-search.txt`，未安装额外全局插件。

场景激活和后台区分参考 [Apple UISceneDelegate](https://developer.apple.com/documentation/uikit/uiscenedelegate) 与 [sceneDidBecomeActive](https://developer.apple.com/documentation/uikit/uiscenedelegate/scenedidbecomeactive(_:))，实际交付时机仍由本App窗口转场完成回调决定，避免把“激活”直接当成“已显示”。
