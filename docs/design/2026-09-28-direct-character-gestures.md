# 小伴 · 直接操控角色（0.6.2 / build10）

## 用户意图

日常在模型上直接操作，不必先开控制界面；控制低调、不过度强调，精细调整面板仍保留。沿用沉浸式聊天的全屏3D和底部渐变。

## 交互

- 单指左右轻拖：改变朝向，左右各20°；使用原有相机构图平滑，不加入惯性甩动。
- 双指张开／合拢：调整大小90%–110%。边界上继续拖／捏不会累计超限量，因此反向动作立即响应。
- 单指短按头部：摇头。短边1.8%的位移阈值区分点按与拖动，纵向滑动也取消点按候选。
- 第二根手指加入后，该次序列直到全部松开都不能触发头部动作或重新单指旋转。三指和系统取消终止当前操作；中断时提交已达到的有效构图。
- 不增加聊天页常驻操纵按钮和参数HUD；仅在保留的取景面板与无障碍说明里解释手势。取景面板的恢复推荐、景别及精细数值仍可使用。
- 日常手势松开后自动保存当前角色的取景。面板打开时读取同一值，取消面板预览回到手势后的构图；重启／重新进入恢复。写入失败使用现有本地保存错误提示，不虚报保存成功。

## 工程决策

在Unity已有输入路径中识别单／双指，保持SwiftUI聊天输入、滚动和按钮自己的触摸归属。模型不需要新增控制覆盖层；DEBUG只暴露未被聊天遮挡的区域位置给XCTest，用于把两根手指实际放到Unity区域。

每帧计算留在Unity，手势结束只回传一次framingGestureEnded并保存一次。原生按presentationId和modelId丢弃过期结果；保存后不向引擎重复发送configureFraming，避免下一次触摸被自身回执打断。

精细取景／外观编辑时显式关闭背景手势，完成、取消和下拉关闭后恢复。新构建要求framingProtocol3，防止原生界面误连旧的禁用拖拽版本。

## 验证计划

使用XCTest真实拖动／双指手势及Unity实际事件断言：边界、边界反向、手势与触头分离、消息滚动隔离、精细面板读取和取消、手势记忆恢复、iPad旋转后的手势。结果归档docs/verification/direct-gestures。
