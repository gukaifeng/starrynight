# 0.47 可见待机与分组默认

用户反馈：衣发与待机运动过轻、单次眨眼太快，表现面板缺少明显的默认入口。本轮目标是增强实际可见变化，同时保留原作数据、脚部稳定、表情优先级及各分类的独立性。

## 运动决策

1. 在原作呼吸基础上单独生成 App 待机：琪宝的 Chest/Head 相对首帧旋转幅度为原来的4倍，豆日向为3倍。使用四元数短弧缩放，避免欧拉角越过180度时翻转；髋部平移/旋转和下肢运动不放大，原2.5秒周期不变。不是把整个人根节点左右摆动。
2. GLB 中保留原作 VRC 动画与 `Source_Idle`；实际 `Idle` 和静态姿势用的 `App_VisibleBreath` 明确是 App 幅度适配。原始ZIP、源采样和原作表情/动作保持原样。坐/蹲等静态姿势仍有呼吸，睡眠循环不叠加，默认待机不叠加两遍。
3. 头发风力角度预算由2.2度提高到7.5度，衣物由0.65度提高到3.2度，响应系数分别为0.9/0.85。维持原骨链长度、5/7/10度的逐链限制和身体碰撞约束；只有水平气流，仍有1.4秒渐入。导入检查与运行时共用最大预算常量8/4度，避免“数据能生成但运行时被静默裁小”。
4. 两角色单次眨眼都改为闭眼0.16秒、停留0.035秒、睁眼0.26秒，总计0.455秒。间隔数组和初次等待设置不改；这次调整的是一次眨眼的过程。保留平滑曲线、手动表情及睡眠优先级。

## 默认入口

原引擎已支持 `performance.reset` 携带分组，但原生面板仅暴露了无文字的全局按钮。

- 每个分类网格首项固定显示「默认表情」「默认待机」「默认手势」「默认耳朵」「默认尾巴」或「默认穿搭」。切换分类回到网格开头，使入口可见。
- 默认通过引擎回执选中，不以“没有选择任何选项”简单判断：穿搭等分类包含原作 `defaultOn` 配件，默认并不等于全部关闭。
- 分组复位只发对应 group，不改变其他分组、相机和保存的位置；表情淡出后自动眨眼恢复。
- 顶部保留有文字的「全部默认」，用于一次恢复全部原作默认选择。操作沿用当前平滑混合，等待回执时禁用重复请求。

## 验证和版本

App 0.47.0 / build 68，当前两角色包2.2.0；接口仍为可选 `core.autonomy@1` 与已有 `performance.reset`，角色ID和账户会话数据不变。导出戳 `autonomyRevision:2`，旧 Unity 产物不能被新宿主误用。

验证包含短弧放大数学、原作曲线逐通道保留、实际Unity导入后的角度、每条风骨链边界、表情/姿势独立复位以及模拟器UI实际操作。60/120 Hz数值步进不等于真机FPS实测。结果见[本轮验收](../verification/idle-refinement/README.md)。

参考 Unity 的 [AnimationBlendMode.Additive](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AnimationBlendMode.Additive.html) 和 [AnimationState.weight](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AnimationState-weight.html)：本轮在转换阶段生成所需幅度，运行时混合权重仍保持0～1，不依赖超范围混合权重。
