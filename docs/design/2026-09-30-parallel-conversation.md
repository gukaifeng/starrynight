# 0.64 · 核心对话优先、并发表演与轻捏轻扯

目标版本：星夜 0.64.0 / build 90。用户要求进一步缩短等待，台词、语音和心声先行，动作和表情允许稍晚接入；同时将临时双指反馈收窄为 ±5%，区分「捏」与「扯」，修复初次只能缩小的问题。

## 定位和决策

原链路首段 PCM 实测约 7–8 秒，其中 TTS 首包只占约 0.5–0.6 秒。主要等待在包含完整能力目录、深层 JSON 和大量表演字段的角色规划；手机收到 `segment.audio.ready` 后还会等待声音播放排空，再继续处理下一条 SSE，导致稍晚的动作一起排队。只调播放器缓冲不能解决这两个问题。

保留 Qwen-Plus-Character 和现有音色。先采用私有紧凑 DTO，省略默认值、重复字段、内部路由 ID；扩展为完整标准后再做结构校验、去重和存档。固定 schema／人设前缀排在动态状态之前，并按阿里官方角色模型协议启用隔离的 session cache header。缓存命中取决于服务商，不能保证每次命中。BGE 在服务启动时后台预热，不让用户首轮承担本地模型加载，不发付费向量请求。

最终拆为以下任务，不为每个身体部位各发一次大模型请求：

| 任务 | 开始条件 | 是否阻止开口 |
| --- | --- | --- |
| 核心角色规划 | 收到本轮上下文 | 是：台词、语气、分段心声必须先校验完成 |
| 可选表演规划 | 与核心规划同时开始；有实际可用资源 | 否：默认 8 秒超时，仅一次请求 |
| 基础多组表现解析 | 核心情绪已就绪 | 本地数据解析，无额外模型调用 |
| TTS | 核心台词通过校验 | 首包即推送；最多 3 个 beat 并行合成，按原顺序交付 |
| PCM 播放 | 手机收到音频 | 独立队列；接收其他事件不等待播放完毕 |
| 表情、动作与口型 | 实际动作可用／PCM 输出 | 分组更新，口型继续跟随真实输出音量 |

TTS 有文本依赖，不能在不知道台词时并行猜音频。核心需要的心声与语气保留在同一结构化结果，避免再次等待第二个描述模型。记忆建议和少量状态变化仍由核心同轮输出；不宣称所有任务都完全无依赖。

## 兼容、取消和费用

- 增量能力通过 `parallel-v1` 协商，公开 timeline-v2 结构仍兼容。旧传输模式和旧存档可继续使用；模式字段不加入幂等身份。
- 初始回复已有完整台词、心声和分段 parts。迟到表演只更新当前 message_id 的动作，不在已经读过的气泡开头补内容，不重新朗读。晚到的同组过期阶段合并，不瞬间闪过多个旧动作。
- 表演候选仍要通过已安装目录、语音兼容、冲突、冷却和强度等检查；原生按组保留并恢复原状态。迟到耳朵／手部更新不取消其他组尚未播放的下一阶段；同组后续自动阶段也保留，必要时顺延以保持至少 1200ms 间隔。
- 每轮表演额外最多一次角色模型调用，不自动付费修复可选动作格式。核心沿用原有有界内部修订；多段 TTS 是调整启动时机，不额外复制台词调用。失败的可选表演保持自动基础表现，用户对话继续。
- 异步任务归属当前话轮，取消后 cancel + gather/join；音频生成队列每段最多 16 个事件、最多 3 段并发，手机音频队列最多 128 项。切角色／新轮次继续校验 token、账户和消息 ID，防旧动作或声音错配。
- API Key、账号、原始音频和付费调用原始报告保持本机。测试检查页能查看完整核心与表演提示、实际请求和逐环节耗时。

## 捏／扯修复

旧代码把持久位置编辑器的完整模型包围框限制用于临时缩放反馈。立绘已经贴合或裁切视口时，上限被裁到 1；因此从初始状态张开两指无效果，先缩小后才看似能变大。临时反馈现在固定为当前保存视图的 0.95–1.05，移除这层动态裁剪，位置编辑仍保留原范围限制。双指平移不作用于角色，松手平滑归位，不覆盖用户保存的视图。

反应阈值从 0.055 调整到 0.025，保持 0.22 秒持续判定、手指未松开即可触发与共用 20 秒冷却。pinch_in 语义为轻捏，pinch_out 为轻扯。提示和发布前语义审查同时拒绝「真的变大／缩小／拉近」、错误旋转说法及反向捏／扯，不增加预写台词。

## 实测时延

本机同一服务商、两种相同测试输入、独立测试会话测得以下首段 PCM 到达时间；这不是手机扬声器开口计时，也不是 P50/P95 统计。

| 场景 | 本轮修改前 | 紧凑规划中间版本 | 核心／表演并行版本 |
| --- | ---: | ---: | ---: |
| 琪宝日常聊天 | 7.980 秒 | 3.771 秒 | 2.822 秒 |
| 豆日向轻扯反应 | 7.242 秒 | 4.496 秒 | 3.868 秒 |

并行版首份文字／分段心声分别约 2.298、3.368 秒到达。第一条的表演增量在 4.887 秒才到，而音频从 2.822 秒已开始推送，证实可选任务没有阻塞语音。第二条表演先完成，合入初始脚本。两例输出都保留多组真实表现与中段心声，轻扯台词没有变大／距离叙述。

首次仅重排缓存前缀的试验不稳定：一条改善，另一条增加到 12.086 秒，因此没有将其当作最终结论。以上最终样本很少，会受服务商排队、网络、历史长度和内部修订影响，不能承诺每次秒回。没有降低语音语速来伪造响应速度，也没有使用缓存固定回复。
