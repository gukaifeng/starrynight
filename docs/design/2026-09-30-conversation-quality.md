# 对话演绎、重逢问候与统一角色封面 · 0.55.0 / 79

## 问题与处理

用户反馈三类语气括注里只有部分被朗读。检查发现，旧代码只剥离供应商标签和 XML 标签，`dialogue.text` 中的中文括注原样交给 TTS，因而依赖供应商每次是否将其理解为指令。新增独立 `spoken_text` 边界：在真正合成前过滤语气、表情、动作类明确标注，包括中文/英文括号、方括号、嵌套括号、未闭合尾注与 Markdown 动作标注；保留普通台词括注，例如“维生素（B12）”“明天（如果有空）再聊”。心声、旁白仍从独立结构展示，永不进入语音。

Planner 同时明确要求演绎只写入结构化 `speech`，不能把“（语气平稳）”混入台词。过滤也应用于历史消息重新合成。服务端和 iOS 的语音缓存代际均增加 `spoken-v2`，避免直接播放旧的错误音频；保留已设计音色、聊天记录，按需重新合成，不批量重做历史语音、不再次设计音色。

真实联调进一步发现一个有效 JSON 内部的无效内容：`dialogue.text` 里混进了 `"speech":{"emotion":...}` 这样的控制片段，原 Pydantic 只验证它是字符串。现通过字段校验纳入既有一次格式纠正；若仍错则拒绝。旧记录不删，旧音频重播只取控制片段前的台词，坏的历史助手示例也不再喂回 Planner。

重逢原先只有一句“结合上下文自然接续”，容易被模型理解为再次回答历史最后一个用户问题。本版将进入会话作为独立事件：明确没有新用户问题，历史问题已经属于过去；提供账号/角色隔离的近期台词、最近五次问候与真实离开时长，让模型生成新的见面话题。普通回复不受这个规则干扰，用户要求复述时仍可复述。

原输入还将 `user_message` 放在长历史与能力对象之前。本版在资料之后以独立“当前这一轮”明确消息/触发场景，防止历史被误作当前问题。沿用既有 `qwen-flash-character-2026-02-26`，按[百炼角色扮演文档](https://help.aliyun.com/zh/model-studio/role-play)配置人物与语言风格；资料数据不具有覆盖系统规则的权限。不因为更改提示词便假定模型严格遵循，仍依赖结构校验、语音边界与实际动作回执。

使用 Python 标准库 `SequenceMatcher` 检查规范化文本的相似度，兼顾原句前面只添“回来啦”的情况。仅在检测到已完成输出重复时允许一次语义重写；若仍重复则不播、不写入聊天，返回可理解的提示。网络不确定失败不自动重试，原 request ID 的成功结果重放仍不产生第二次模型费用。语义重写是额外一次 Planner 请求，供应商现有的最多一次格式纠正仍独立有界。

## 原作表演接入

按项目 `vrchat-character-import` 技能、已安装 `CharacterCatalog` 和 `core.performance@1` 核对。此前仅接入 12/11 种表情及每角色三个手指姿势；近期私有诊断中，45 个 beat 只有 19 个带可执行表现，绝大多数只是脸部或手指，耳尾从未被选择。

本版琪宝 **23 种表情 + 12 种动作选择**，豆日向 **20 种表情 + 12 种动作选择**。动作包括六种手指姿势、竖耳/垂耳/动耳、三种原作尾巴表现。它们不是 12 段全身动作。坐下、躺下、衣着配件继续由用户显式控制，聊天编排不擅自修改。原 ZIP、Prefab、骨骼、形变曲线和 Unity 导出资产没有改变。

Planner 收到的能力目录增加效果与适用场景说明，要求明确表演请求优先匹配；普通情绪对话选择合适表情，问候/开心/好奇等场景可配手势或耳尾。移除结构示例对 `neutral/idle` 的无意诱导。Director 对已知语义别名做规范化，未填写表情时可依据同一 beat 的结构化语音情绪补选；不支持的拥抱等不会凭空变成已执行动作。冷却由脸部 18 秒/手势 35 秒改为 5 秒/动作 9 秒，保留变体选择与角色隔离。

原生端允许经过目录核对的耳朵、尾巴组。台词出现时先给第一拍反应，语音开始时对齐演绎；静音、无音频 beat 或语音失败仍可执行未播放的表演。短语音结束不立刻抹掉表情，每组按有限时长恢复进入前状态；眨眼/吐舌更短，普通脸部和耳尾保留几秒。用户手动选的基线不被永久清空，切角色/取消立即清理。循环动作也有恢复定时器。

保留第一帧就绪门槛、最短可辨识展示和原生/Unity 窗口交叉淡入。复用当前会话仍直接恢复，不重新加载，不改动模型终态取景或相机。

## 验证中修正的问题
