# 固定面板与渐变子页面

## 用户体验

首次打开资料、设置等入口仍使用原有面板。面板内进入作者、作者作品、关注者、定制、取景、角色设定、音乐、聊天显示、记忆、聊天资料、对话长图、一起及功能预览时，只切换同一面板中的内容，使用短暂透明度过渡。窗口尺寸、位置、顶部返回位置和背后的角色取景保持不变。系统分享与必要的确认对话仍使用系统组件。

角色资料圆头像从76pt减为52pt，名字从24pt减为20pt。订阅紧邻名字，以28pt视觉胶囊和至少44pt点击区域显示；不再占据页面右上角。作者行只介绍作者并进入作者主页，不提供关注按钮。关注操作保留在作者主页。定制角色放到简介文字下方左侧，作为30pt视觉高的小入口，不再悬在头像行右侧。

## 根因与实现

- 资料→作者原来已经使用ZStack和opacity，视觉上像叠窗的原因是头栏边距不同、子页再画实色背景。资料→定制则会叠加两层渐变背景，越深入越暗。
- `PanelPageHeader`统一返回按钮、标题、副标题和右侧操作：44pt固定头栏、横向22pt、顶部16pt、底部12pt。移除子页各自的NavigationStack和系统toolbar，避免系统导航安全区与手写头栏不一致。每页的滚动内容单独布局，不在父路由外层叠加padding。
- `softPanelPageSurface`由最外层负责背景和占满面板的布局，子页通过环境继承。会话面板保留渐变透明，发现及独立页面使用原不透明底。深层页面不改变背景明暗，也不触发UIKit重新present或相机命令。
- 真正存在的业务嵌套弹窗是聊天资料→导出长图，已改为同一ZStack的渐变子页。历史列表继续挂载，隐藏时关闭触摸和辅助访问，保留搜索条件与滚动位置；返回恢复原列表。UIKit辅助访问仍可能展平隐藏页的头栏，因此覆盖期间移除真实历史返回按钮，以等高透明占位维持列表布局，而非只依赖父视图隐藏修饰符。
- 每次进入新子页使用独立关闭请求。最深页的保存验证向上转发，返回或点面板外继续采用原保存规则，校验失败保持当前页面；过渡中旧页面清理不会覆盖下一页的保存回调。

## 验证范围

复用并增强既有真实UI流程：资料／作者／作品／关注者／署名各层返回坐标一致、订阅与关注独立；作者编辑保存及发布；所有定制页和键盘保持角色相机；聊天资料→长图两轮返回保留搜索和面板位置；长图生成与系统分享取消；一起、记忆及云功能预览。测试和安装实际结果写入`docs/verification/fade-subpages/`，未完成项目不计为通过。

本次仅原生页面呈现和导航调整，无新依赖，无Unity资源变动或重新导出，无服务端和数据迁移。

最终六个既有XCTest方法均有通过结果，共470.288秒；截图复核会话透明面板和发现实色面板。两平台原生构建与严格验签通过，手机安装、版本回读0.35.0 / 54及启动成功。失败原因与修复、测试结果、页面截图及设备凭据见[本轮验证](../verification/fade-subpages/README.md)。
