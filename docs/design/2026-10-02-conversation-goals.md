# 相处方向与目标体系

第一版统一了关系、任务、沙盒三种目标。入口是会话左上角角色资料 →
相处与剧情 → 方向。关系模式可选择初始关系、长期方向与今天的小愿望；
任务模式支持学习、英语口语、倾听、计划；随心相处没有强制结局。
方向可以保存、暂停和切换，既有聊天、记忆与其他分支不会随切换清空。
不同方向独立记录节点，同时共享熟悉、信任和亲近程度。练口语之后回到
关系模式，角色不会变成重新认识用户；任务/随心模式的亲近增量低于关系模式。

采用现有深色界面和轻量卡片。页面以“今天想走向哪里”为中心，不展示
好感分数，不用升级按钮代替关系。显示的是具体交流产生的节点。
相处页仍保留称呼、用户介绍、回应偏好与回避话题；旧关系选项移入新方向。
故事仍是可选的虚构情境，不再承担全部目标状态。

恋爱主线对明确成年、允许恋爱的人设优先开放，目前为真冬与草莓。
青柠与希默认英语任务。其余角色可使用非恋爱的关系、任务与随心模式；
未审定年龄和明确幼态的人设不因一次 UI 改动重写为成年恋人。
初始关系可有初识、追求、暧昧、恋人、朋友、师徒、宿敌、青梅竹马，
可选集合受该人设边界约束。关系确认由用户明确选择，不靠累计聊天次数。

服务端实现独立位于 `../starrynight-server`。PostgreSQL 保存配置、版本、
分支进度和幂等反馈记录。客户端本机只缓存快照；网络不可用时不虚报保存。
配置切换会停止旧方向的会话请求与准备租约。服务端缓存指纹也包含目标，
避免学习模式收到旧约会回答。返回语音、表情与动作仍走已有并行编排。
固定首次自我介绍保留，后续自动问候、待机、手势与快捷回复都收到目标上下文。

目标反馈随正常规划生成，不再额外调用一次 AI。只有真实用户/故事回合
且有原文证据才允许小幅推进，问候、待机、手势、未消费候选与暂停状态
不能刷进度。任务语言也同步作用于心声、快捷接话和语音语言提示。
共同记忆仍需用户确认；目标选择和关系节点另存，避免把虚构故事当真实经历。

扩展采用版本化配置与扩展字段，服务端拥有状态。不能承诺所有未来功能
都零兼容成本。完整协议、部署事务限制见服务端
`docs/design/conversation-goals-2026-10-02.md`。

开发期间修复了目标接口的可选重置字段、空扩展对象验证和 PG JSONB 编码。
目标页测试最初被 App 的正常 bootstrap 替换了测试根视图，导致控件消失。
已隔离仅 DEBUG 模拟器可用的目标页 fixture，正常启动和发布包不走该入口。
最终原生 UI 测试 3 项通过，涵盖三种方向、暂停、旧故事入口、账户与发现页。
AI 管线 231 项通过、4 项按原条件跳过；真实 PostgreSQL/Redis 集成、
Go 竞态、vet、构建及 OpenAPI 检查通过。测试证据保留在本机 `.local/`。

第一次小规模百炼实测发现：可选的目标反馈会被模型省略，虽有正确台词，
但进度仍为零。已将真实用户回合的规划输出改为必须包含目标反馈和原文
证据；问候、待机等回合仍使用原兼容协议。重试实测关系和英语任务各一轮，
确认进度版本从 0 到 1、2，关系积累存在，英语回复没有夹入中文。
反馈与台词同一次规划生成，不额外增加一轮目标评估调用。
