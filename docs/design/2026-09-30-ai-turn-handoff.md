# 连续对话、流清理与本机额度修复

> 后续更新（2026-09-30）：本机权限恢复后已完成相应补验、AI 网关部署和 iPhone v0.54.0（76）安装。实际通过项及尚未覆盖范围见[交付记录](../verification/device-v054/README.md)。下文保留此前阶段的失败与限制，不将历史受限结果改写为通过。

## 问题与证据

用户反馈经常收到“上一轮还在结束”和“本机设置的今日 AI 用量已用完”。原实现存在三处相关问题：

1. 服务器把同会话占用和整个 worker 的四路并发满都返回 `409 BUSY`，iOS 统一显示“上一轮还在结束”。UI 显示了正文，不代表服务器已经完成全部 TTS；新消息会撞上旧连接尚在生成语音/断开连接清理的窗口。
2. 旧 `StreamingResponse` 外层在发送时断线，并不保证关闭正停在 `yield` 的异步生成器；生成器的 `finally: busy.discard(key)` 不能作为唯一的生命周期保证。iOS 消费音频片段时会等待播放，任务取消也应在没有挂起网络读取时立即取消 URLSession 连接。
3. 每日60次是所有上游调用共享的开发限制，不是60轮用户对话；计划、旁白、TTS、ASR和声音设计都会计量。一次有声回复通常至少3次。用来约束开发测试的额度不应该限制用户正常聊天。

本次只读查看已部署数据库的聚合记录：最近25个完成的计划请求，中位耗时 **3,139 ms**、最大 **9,759 ms**；最近13个完成的旁白请求，中位 **1,237 ms**、最大 **2,752 ms**。旧链路串行等待两者后才开始语音。数据库里还有11条历史 `running` 请求；这些不是“仍在执行”的可靠证据，旧版未将中断状态落盘。

## 实现决策

### 使用者额度与开发验证分离

`Settings.enforce_conversation_limits` 默认 `false`。旧设置文件中的 `max_daily_calls / max_daily_tts_characters / max_daily_asr_seconds` 只有在显式开启该开关时才执行。现有用量数据和每次调用的原子记账继续保留，不删除计数、不把清库当修复。

付费测试开关、每次请求的合法性校验、真正的工作并发控制以及已有音色的防重复创建继续生效。日常聊天不会触发本机每日额度拦截。开发仍以免费替身回归为主，真实验证按小批次短对话执行，不运行无限重试、循环问候或无人看守的付费压测。上游自身的实际余额和服务状态不由本机额度逻辑伪装或绕过。

### 新消息接替旧请求

`TurnStreams` 按已鉴权 owner + character 管理当前上游任务，使用 AnyIO 有界内存流传输事件。新用户消息或主动重播先取消上一任务并等清理完成，再开始新的请求；正常情况下不返回“上一轮还在结束”。相同 request ID 仍执行幂等保护；闲置主动请求不能抢占用户会话。

响应显式监控客户端断线，覆盖 ASGI 2.3 和 2.4；发送错误、取消、正文生成失败、TTS异常都会关闭生产任务。嵌套的剧本和合成异步迭代器使用 `aclosing` 逐层收尾。旧任务只释放自己的占用，不能误删刚开始的新任务。清理最多等待3秒；若底层真无法结束，保留占用并报告明确的连接恢复错误，不放任两个请求并发改写同一会话。

语音识别与回复的占用分开，因此识别连接收尾不会阻止发送已经确认的文字。清除历史也会先取消相关回复任务。上游中断只更新未完成记录的状态，已经保存的文本保留；不自动重新提交可能已收费的请求。

这里沿用 Starlette / AnyIO / HTTPX，未增加自建网络框架。异步资源清理依据 [AnyIO 的取消与清理文档](https://anyio.readthedocs.io/en/stable/cancellation.html)；流连接必须正确关闭见 [HTTPX 异步流文档](https://www.python-httpx.org/async/)。原生使用 URLSession 的取消处理器，即使正在等待播放完毕也立即关闭传输。

### 正文和声音不等旁白

新 iOS 客户端发送 `X-Starry-Reply-Mode: progressive-v1`。服务端先生成、保存并发送有真实模型来源的台词和表演信息，然后让 TTS 与旁白并行。可选旁白最多等待3秒；超时直接省略，不丢失回复，也不为补旁白重试付费调用。完成后用同一消息 ID 的 `reply.script.updated` 补全已验证的旁白；客户端只更新剧本字段，不新增气泡或重启语音。

没有这个请求头的旧客户端保留原有事件顺序；旧服务端会忽略新请求头而正常处理。交付模式不加入 request ID 的内容指纹，旧请求和跨模式重试仍复用结果。缓存重播遵守 `wants_audio`。

错误文案按实际错误区分会话幂等冲突、工作并发满、上游429、超时和旧部署仍启用测试额度的情况，不再把所有 `409` 或包含 `LIMIT` 的代码误报成前一轮未结束或日额度耗尽。
