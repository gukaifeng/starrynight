# 星夜 0.25 · 消息进入角色的连续过渡与静态语音标签

本轮处理两个反馈：消息列表进入角色在加载动画结束处出现亮度跳变；未播放的语音按钮和时长仍有动效，并要求去掉“约”。保持现有品牌、取景、气泡轮廓及12pt正文留白。

## 窗口交接

原生状态机已确认Unity三帧就绪，但原实现随后对整个Unity窗口做alpha动画，同时把宿主窗口降回普通层级，完成后又替换宿主中的加载内容。场景就绪与窗口合成是两个不同的问题。基线录屏中可见加载画面经过很少的中间亮度就突然出现完整角色；单纯检查相机稳定、模型已经加载并不能覆盖这一缺陷。

新增`NativeWindowHandoff`，统一进入新角色、恢复驻留角色和返回原生页面三条路径：

- Unity窗口始终不透明，保持实时渲染；渲染完成确认、最终取景的规则不变。
- 原生窗口始终在Unity上方，窗口背景透明，只有其原生内容视图的alpha参与过渡。进入对话时淡出原生内容，返回菜单时淡入原生内容。
- 动画结束后原生窗口仍留在固定层级，其内容保持完全透明并关闭触摸/辅助功能访问。此刻不移除窗口、不改变层级、不把其alpha恢复成1，因此没有结束帧再次露出加载页或消息列表的机会。后续更新原生页面发生在透明状态下。
- 返回菜单时等原生页面完全遮住Unity，再隐藏/暂停Unity；后台中断把正在进行的过渡收束到终态。取消和错误路径显式恢复不透明、可交互的原生页面。
- 新角色过渡0.46秒，驻留角色恢复0.36秒，返回菜单0.38秒；减弱动态时缩短。触碰区域只在对话可见后恢复，透明原生窗口不能阻挡输入框、底栏或头部点击。

首次尝试只改为淡出原生内容，但仍在结束时移除/恢复窗口。最终进一步取消结束时的窗口变更，保留透明宿主；这也消除了隐藏窗口恢复alpha后，下一轮采样读到上一轮不透明presentation layer的歧义。最终代码以常驻透明宿主为准。

另在桥接层避免给同一个窗口重复绑定相同UIWindowScene；返回原生页面不再次激活正在显示的Unity窗口。窗口已是key且可见时也不重复调用showUnityWindow。

窗口层级与动画机制参考 [Apple UIWindow](https://developer.apple.com/documentation/uikit/uiwindow)。验证使用实际UI流程、显示回调的presentation layer采样和录屏画面；不把窗口alpha值等同于GPU帧率。

## 语音标签

旧实现让同一SwiftUI节点挂着`repeatForever`，再改变动画参数来停止。新实现把动效限制在“实际正在播放”的子树，使用`phaseAnimator`进行局部明暗/微光变化；未播放、合成准备中、播放完成或手动停止时使用独立的静态标签，不创建循环动画，也禁止继承该标签自身的隐式动画。减弱动态时始终静态。播放与静态两种样式使用相同几何布局和44pt触碰范围。

时长统一显示`13″`或`1′08″`，去掉“约”。计算与存储语义不改：未合成时显示内存中的估算时长，得到完整音频后显示实际时长，只有实际时长可落盘。DEBUG自动化值额外标识估算/实测来源，因此测试不再靠有没有“约”来猜测是否已经得到真实音频。

播放动画使用现有系统API，不增加动画库。参考 [Apple SwiftUI动画](https://developer.apple.com/documentation/swiftui/animations)。结果与截图见 [本轮验证](../verification/message-handoff/README.md)。
