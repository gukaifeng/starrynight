# 栩屿 v0.3：从精致模型走向可塑造的 3D 伙伴

## 产品判断与证据（2026-09-27）

目标用户不是只想看一个漂亮模型的人，而是希望角色形象精致、相处方式稳定、记得重要事情、聊天时有在场感的人。3D 精度是第一印象；持续使用取决于对话质量、记忆可信度和响应速度。以下是产品判断，不是市场成功保证。

竞品已经具备很多基础能力：[Replika](https://replika.com/) 提供角色外观、记忆和语音互动；[Nomi](https://nomi.ai/) 强调背景设定、关系与记忆；[Character.AI 的 2026 年记忆说明](https://blog.character.ai/memory/) 包括可编辑的角色／用户事实与故事记忆，[语音通话](https://blog.character.ai/introducing-character-calls/) 支持打断。仅增加聊天框或换模型不足以构成竞争力。

栩屿聚焦三个可验证的差异：**可近看、有审美的 3D 角色；用户真正能管理的人设和记忆；声音、表情与动作一致的互动。** 不把模型的推断冒充用户认可的事实，不把预设回复冒充通用智能。

## 分期与本轮交付边界

| 优先级 | 能力 | 本轮 v0.3 | 后续完成条件 |
|---|---|---|---|
| P0 | 精致角色与操控 | 保留 Luma／初音、旋转缩放、动作；增加聊天舞台与配色／氛围 | 原创或完整商业授权模型、服装／发型组合、系统性穿模验证 |
| P0 | 角色塑造 | 独立昵称、背景、性格、语气、长短偏好，保存后作用于回复 | 真实模型的角色一致性评测与版本回退 |
| P0 | 文字对话 | 可替换的本地情景库、逐字呈现、停止、重新回答、历史 | 接入流式 LLM、上下文预算、超时重试、内容与隐私控制 |
| P0 | 可控记忆 | 用户添加／编辑／删除、消息保存、按角色隔离、实际用于回忆回复 | 语义检索与冲突管理；敏感信息默认不自动记忆 |
| P0 | 听与说 | SenseVoice 识别 + MeloTTS 合成，Mac 本地推理供模拟器调用 | iOS 离线推理包、模型下载管理、真机功耗与延迟评测 |
| P0 | 具身反馈 | 音量驱动口型／光效、聊天触发安全动作、收听／思考状态 | 音素口型、注视、情绪过渡、流式可打断语音 |
| P1 | 用户控制 | 数据导出、清空聊天、删除记忆、明确本地模式 | 加密同步、账号删除、迁移与跨设备 |
| P1 | 留存 | 保存聊天与偏好，场景快捷入口 | 自定义情境、可选提醒、用户主动设置的长期目标 |
| P2 | 创作生态 | 暂不接入公共市场 | VRM 导入、许可校验、创作者工具、内容审核与分发 |

本轮不承诺“训练自己的大模型”。性格和反馈是可解释的本地配置；之后才对接真实推理服务。初音为当前演示素材，不能据此推定商业发行授权已经取得。

## 实现约束

- 原生 SwiftUI 负责档案、对话、记忆；Unity 负责角色渲染与动作，两者以版本化 JSON 命令通信。
- 对话由本地情景库生成，明确显示“本地情景对话”；用户语音先转为可编辑文字，再由用户发送。
- 本机语音采用 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)（Apache-2.0）、[SenseVoice](https://github.com/QwenAudio/SenseVoice)（MIT）、[MeloTTS](https://github.com/myshell-ai/MeloTTS)（MIT）。权重固定上游 revision，保存哈希和随附许可。依赖固定在锁文件；不执行模型仓库脚本。
- 语音服务仅监听 127.0.0.1；加载完成后识别与合成不需互联网。模拟器能访问 Mac 回环地址，真机不能使用同一个 localhost，因此此阶段不是手机离线语音交付。
- 不在日志记录聊天／录音文本；录音与生成音频不长期保存。用户资料仅写入应用沙盒；导出由用户明确操作。
- 停止／切换角色／返回／进入后台必须取消生成与语音并归零口型，过期异步结果不得进入其他角色的会话。
- 沿用高画质；120 FPS 为请求目标，不能声称达到。v0.2 模拟器实测约 34 FPS，属于未解决的性能问题。本轮必须分别报告功能验证与实际性能限制。

## 验收与下一阶段指标

本轮验证真实本机 ASR/TTS、可恢复持久化、角色隔离、记忆读写、个性化回复、停止竞态、模拟器聊天流程与 iPad 布局，保留模型浏览回归证据。结果以实际执行记录为准。

后续产品指标：首次进入到完成首次对话的时间；语音首音延迟与可打断延迟；角色设定遵循率；用户确认记忆的召回与删除一致性；7 日留存；每有效分钟成本；真机 P95/P99 帧时间、发热与耗电。先用小规模测试建立基线，再定商业目标，避免先编造数字。

## 面向市场的下一阶段实施顺序

1. **先让对话值得回来**：接真实流式模型；明确区分人设、用户确认的长期记忆和当前上下文。建立固定情景集检查角色一致性、记忆引用／遗忘、重复回复和中断恢复。当前点赞只保存反馈，简短偏好只改变配置，不宣称已经完成模型训练。
2. **把等待缩短到自然交流**：真实声学 VAD、边识别边显示、边生成边合成、用户开口即可打断。先拆开测量识别、首字、首音和播放队列，再选择端上／本地／云端分工。建议首音 P95 < 1.5 秒、打断 < 200 毫秒作为下一阶段内部目标；这是待达成指标，当前本机 TTS 明显未达标。
3. **让精致发生在近距离**：增加对话近景镜头、注视与细微表情、音素口型，扩充连续过渡动作和服装／发型。原模型查看器保留全身观察。针对每套服装建立动作穿插回归和不同镜头审图；性能用真机长时帧时、温升、耗电验证，不用目标 FPS 文案代替测量。
4. **让用户放心投入资料**：记忆引用来源、冲突修正、范围控制和一键删除，导入／导出与迁移，按需加密同步。网络失败时允许继续看角色和读历史；没有用户确认，不把推断永久记成事实。补齐大字号、辅助功能和权限拒绝路径的设备验收。
5. **再扩大可定制资产和服务规模**：原创或可商用角色、标准化骨架／VRM 导入、创作工具、资产来源与许可元数据。角色市场和云同步之后再做；同时建立每有效对话分钟成本、延迟／失败率与小规模留存基线，决定收费与容量方案。

语音技术选型优先复用已接通的 sherpa-onnx 接口；后续替换模型或迁移到 iOS 原生推理时，保持 `/health`、识别／合成适配层以及原生播放／取消契约独立。Kokoro 已在本机做过对比但更慢，未因知名度而替换现有 Melo。详见验证材料，不能推断这一结果适用于所有硬件。
