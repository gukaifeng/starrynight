# 角色公开资料、完整 AI 设定检查与原作待机审查

交付版本：星夜 0.56.0 / 82。范围是两位现役角色的公开资料、测试阶段完整设定可见性，以及原始待机能力复核；本轮没有改动模型、动画或 Unity 运行时。

## 公开资料与私有调教

角色资料页展示职业、邀请语、性格、生活背景、喜好、世界设定和说话风格。内容通过 `services/character_ai/public_profiles.py` 的显式字段白名单产生，不直接序列化完整 `PROFILES`。两位角色的公开故事分别围绕山间书屋和小镇面包房，不把系统指令、私有秘密或音色设计提示作为宣传文案。

`scripts/generate_character_public_profiles.py` 生成随 App 打包的公开 JSON；宿主生成脚本自动调用。资料页先用本机内容，即时显示，再尝试获取同结构的服务端版本。断网不会变成空白资料卡。更新角色源设定后重新生成，避免原生和服务端各自维护一份性格数据。

普通接口为 `GET /v1/characters/{id}/profile`，账户平台代理路径为 `/v1/ai/characters/{id}/profile`。目前仍使用既有连接鉴权；离线显示不需要联网。

## 测试入口与完整性

当前开发版入口：对话左上角头像/名字 → 角色资料 → 下方「AI 设定检查 · 测试」。使用现有弹窗内的渐变子页面，返回资料页不新增一层系统 sheet。

检查页支持全文搜索、分区展开、场景预览、刷新和复制全部。复制包含折叠、被搜索过滤的分区，内容不按屏幕长度截断。搜索提交或展开分区后收起键盘，保留查询文字。现有两角色各返回 21 个服务端分区，客户端追加 2 个分区，共 23 个。

- **完整角色原文**：当前角色的全部源设定，包括背景、性格、价值观、说话习惯、私有设定、音色设计等。
- **全部提示词与结构**：规划与旁白提示、当前轮任务约束、回复长度、完整 JSON Schema、实际模型与采样参数。
- **当前上下文**：当前草稿、启动/切换/待机等触发场景、关系与情绪、历史上下文、实际选中记忆、可用动作和偏好。与正式请求共用构造函数，标明这是预览，尚未调用模型。
- **全部记忆与本机设定**：本账号、本角色的服务端记忆，以及完整本机记忆、相处偏好、声音设置和问候记录。实际发送有原有上下文数量限制，完整存储内容和本轮选择分开展示。
- **声音与表现**：当前音色绑定、完整声音设计、情绪/语气/非语言发声映射、识别热词，以及当前角色动作与表情资源目录、条件、冷却等。
- **真实发送正文**：显式开启测试后，保存本账号、本角色最近 12 次实际 provider 请求，包括规划、格式修正、旁白、TTS 和 ASR 请求正文。旧版本没有采集的记录不伪造；已超过 12 条的记录不宣称仍保留。
- **完整执行规则**：附服务端当前部署的提示、结构、问候、表演选择、朗读清洗、编排、provider、识别、存储模块原文，以及本测试安装包的会话、问候、语音和缓存相关原生代码。避免将实现中的条件和阈值压缩成手写摘要而遗漏。

平台 Key、认证头和本机凭证不是角色调教，不进入检查报告或剪贴板。报告只读，不执行模型生成、不合成声音、不预留额度、不回写记忆召回时间。真实请求记录由既有发送路径采集，不为展示额外发送一次。清空会话时同步清除本账号、本角色的这些测试记录。

## 开关与发布边界

1. 客户端 `STARRY_TEST_TOOLS` 编译条件默认不由生成器开启。本机忽略文件 `.local/character-ai-client/TestTools.json` 写入 `{"enabled":true}` 后，重新生成宿主即可开启；环境变量 `STARRY_TEST_TOOLS=0` 强制生成普通版本。测试规则附件仅打包进开启的版本，正式发布应明确用 0 重新生成两个宿主项目，不能复用开发阶段生成的项目设置。
2. Python worker `enable_test_inspector` 默认 false；当前私有开发配置显式 true。关闭时检查接口返回 404。接口沿用连接凭证与账号/安装身份，记忆、状态及请求记录严格按 owner + character 限定。
3. Go 平台只在 `development` / `test` 代理该路由，`production` 一律 404；worker 仍须独立开启。公开部署不开放测试调教数据。本轮没有增加生产端绕过登录的通道。

接口为 `POST /v1/testing/characters/{id}/inspector`，账户代理加 `/v1/ai/` 前缀。请求结构复用现有角色对话 Request；返回有版本、角色 ID、采集时间及完整分区字符串。生成预览与实际发送共用 `structured_messages` / `structured_payload`，防止调试界面与实际提示词漂移。

## 原始待机能力：有运动不等于额外站立摇晃

新增只读脚本 `python3 scripts/audit_vrchat_idle.py`：重新校验原 ZIP 及全部源动画文件 SHA-256，读取既有 Unity 原片段采样，核对每条采样来源，并计算头、颈、胸、脊柱、髋相对首帧的变化。输出留在 `.local/checks/character-settings/source-idle-audit.json`；原曲线、截图和受限模型不公开提交。

不能使用相对绑定姿势的 `maxAngle` 来判断待机幅度：静态站姿也可能与绑定骨架相差很多度。审查对四元数先归一化、处理 q/-q 等价，再计算时间序列相对首帧的最短旋转角；0 秒姿势不算循环运动。

| 角色 | 原片段 / Transform 采样数 | 除呼吸外的独立站立头身摇晃 | 原呼吸中实际运动 |
| --- | --- | --- | --- |
| 琪宝 | 99 / 38 | 未找到 | 2.5 秒；胸约 0.845°、头约 0.663°、髋约 0.303°，髋位移约 0.382 mm |
| 豆日向 | 64 / 20 | 未找到 | 2.5 秒；胸约 1.595°、头约 1.251°、髋约 0.573°，髋位移约 0.725 mm |

这些数值是局部骨骼相对首帧的最大变化，不是往返全幅或画面像素幅度。原 `stand`、手部 idle 等是静态姿势；耳尾局部表现不等同于头身待机。琪宝另外有 6 秒睡眠循环、约 7.83 秒入睡、约 11.17 秒起身，属于明确的睡眠/切换动作，不自动混入站立聊天。

当前默认站姿已经接入原呼吸。此前用户要求幅度更明显时，琪宝与豆日向的原呼吸头/胸变化分别做了 **4 倍 / 3 倍 App 幅度适配**；它不是原作者原始幅度。本轮保留此前已授权的呼吸、眨眼和环境风，不再增加程序化身体摇摆、不覆盖原作文件、不重复叠加呼吸。
