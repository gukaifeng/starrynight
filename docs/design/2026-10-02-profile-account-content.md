本轮以 0.86.0 / 116 实现。服务器权威代码在独立的 starrynight-server 仓库；客户端没有恢复 Mac 后端或打包服务凭据。

## 用户可见变化

- 发现删除精选区域和精选 tab；卡片只保留封面、名字与简短邀请，不显示分类标签和作者。全局分类搜索仍可用；作者在角色资料页查看。用户作品筛选保留。
- 我的采用紧凑账户卡片，订阅 / 关注 / 自建 / 聊过四个数据入口，存储缓存、隐私数据、帮助反馈三个服务入口；主题、语言、字号、称呼、关于仍由设置承接。
- 账户显示服务器永久 UUID，不再把可修改的登录用户名当作星夜号。可编辑昵称、简介、性别和内置头像；登录账号、密码与退出其他设备需要当前密码验证。
- 反馈提交真实服务器并返回工单 ID；账户资料导出为受保护临时 JSONL，按页写入，不在内存拼装无限历史。文件是平台变更事件导出，含版本和删除记录；不是全量 AI worker 数据快照。
- 保持简体、繁体和英文文案；真实功能与尚未开通的短信/微信/邮箱渠道区分，不做假验证码服务。

## 身份与下载实现

用户永久 ID 由服务器 UUIDv7 生成，数据库触发器和 API 双层保护不可修改。昵称与登录账号不同；修改登录名不会创建新用户或丢失已有关系。登录 token 位于 Keychain，不进下载请求/清单。

服务端按账户验证角色可见性后签发私有 OSS 短期 URL。客户端 `CharacterDownloadStore` 提供 HTTPS、拒绝重定向、大小限制、逐块 SHA-256、临时目录、失败保留旧版本和按账户分隔缓存；`PlatformAPI.downloadCharacter` 已承接授权清单。下载 actor 不占 UI 主线程处理整个大文件。

**本轮没有改变现有 Unity Resources 加载路径，没有宣称 App 已经可以直接打开远程资源包。** 这是一套经验证的账户/下载协议基础。实际按需交付还需配置私有 OSS/RAM 权限、合法成品发布，以及匹配平台/引擎/宿主能力的 AssetBundle/Addressables 加载适配与真实角色验证。用户没有授权公开分发受限资源，本轮只同步代码和文字目录。

服务器补齐 41 个角色的目录身份，使后来导入的角色也能订阅、保存偏好和同步。不含模型、图片、动画二进制，不新增资源分发许可。
