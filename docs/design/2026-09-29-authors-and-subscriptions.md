# 角色订阅与作者关注 · v0.31.0

角色订阅表示「把这个角色放进我的陪伴与消息列表」；作者关注表示「关注这个创作者，查看其公开作品」。两种关系独立，不涉及收费，也不自动互相创建或删除。

## 页面与行为

| 入口 | 行为 |
|---|---|
| 角色资料 | 顶部订阅／已订阅；独立作者行含圆头像、名字、作者主页入口及关注作者按钮；模型素材署名另有入口 |
| 进入会话 | 未订阅时明确为「订阅并聊天」，记录订阅与最近角色，再打开会话 |
| 作者主页 | 公共头像、名字、简介、稳定作者号、公开角色和本机关注者；作者本人可编辑资料，不能关注自己 |
| 发现 | 角色／作者两种浏览；角色分类包含已订阅、关注作者；角色搜索包含作者名；作者可按名字、简介、作者号搜索 |
| 我的 | 订阅、关注、角色、聊过四个独立数字入口；身份仍打开账户，另有自己的作者主页 |
| 发布 | 角色自动绑定创建者，公开与撤回、更新设定仍归本人管理；作者资料更新统一体现在已有作品中 |

关注作者后，其公开作品进入「发现 → 角色 → 关注作者」。作者页的角色先打开资料，再由用户进入会话，不直接打断当前聊天。作者资料、作品与嵌套页面返回使用现有柔和过渡；仅打开／关闭页面不改变Unity取景。跨角色进入会话等真正的导航发生在原弹层关闭完成后。

取消订阅不删除对话、记忆或作者关注。当前角色在资料卡中被取消订阅后，普通返回会选择仍订阅的角色，或显示首页空状态；若点击「订阅并聊天」则明确重新订阅。聊过列表／历史搜索仍能找到可访问的旧会话，再次进入会重新订阅。

撤回公开作品后，其他身份无法通过已知ID读取其模型或新资料，也不会继续在作者作品、关注作者分类或消息列表展示。订阅列表保留「暂不可用」占位并允许移除，不清理聊天文件；重新公开后已有订阅恢复可用。私有作品由本人在「我的 → 角色」中管理，仍可在自己的发现目录找到；不会出现在其他身份的发现目录或公共作者主页。

## 身份与来源

内置角色的角色设定／整理作者统一为「星夜」，不虚构外部创作者账户或粉丝数。Tda、monjo3456、Crypton、MakeHuman素材作者、pixiv/VRoid、Quaternius等原素材署名从现有来源文件单独展示；角色作者不替代模型原作者。

每个登录身份有独立、不含登录ID的随机稳定`authorID`；公共AuthorProfile只保存名字、简介、头像样式和资料版本。账号到作者的映射保存在私有本机目录，公开资料不带手机号、邮箱、聊天、记忆或私人偏好。预置头像为圆形原生符号，编辑器返回时校验并保存，空名字或持久化失败阻止丢失草稿。

## 数据迁移与一致性

- CharacterLibraryArchive从1升级为2：旧`accounts.*.followed`逐项迁移到`subscriptions`；作者关注初始为空，绝不推断用户曾关注某位作者。显式空列表、原顺序和最近角色保持，重复ID去重。
- 迁移先保存原始`.v1.backup`，再原子写入v2。旧自建角色根据ownerID获得稳定authorID，角色ID、profile、collection及CompanionStore文件不变。未来未知schema或读写失败保留文件并停止修改。
- 订阅／关注均为幂等设置操作。失败不乐观修改内存。不可用的订阅仍可删除；新订阅必须可见。发布、作者编辑都在仓库层检查所有权，不能靠隐藏按钮保护。
- 新身份默认订阅初音未来，不默认关注任何作者。首次从游客登录新身份时承接游客的两类关系与明确空选择，只承接一次；既有身份恢复自己的关系，另一个新身份不接收已交接的游客资料。
- 角色发布资料有updatedAt／revision；作者资料有revision，重复保存不制造假更新。订阅、作者关系和数量当前来自这台设备，尚无网络同步、真实跨设备粉丝或推送。

## 视觉与实现选择

继续使用月白深色主题：深底#101114、层#1E2025、墨白#EEF3F6、柔金#D6C3AA、次字#ABAEB9。角色强调自己的形象，作者用更小、安静的圆形符号头像；作者主页以作品列表为主体，不放虚构热度或装饰性排行榜。我的四项统计用数字在上、说明在下的等宽布局，避免四列横排挤压。

先通过skills.sh及skills CLI检索SwiftUI技能，沿用已读取的frontend-design指引与项目现有原生呈现方式，没有安装不必要的运行时组件。Unity模型／场景不改变，不需要重新导出Unity。
