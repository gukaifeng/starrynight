# 横屏与可变窗口设计 · 小伴 0.12

目标：iPhone 17、iPad Pro 11 英寸 M4 的横屏均可完整聊天、定制、使用动作和弹层。旋转只改变布局，不重新加载模型、不丢草稿、不重置姿势或取景偏好。

## 视觉与布局

延续品牌现有暖白 #F7F5F0、浅绿 #EAF2ED、墨绿 #274A43、玉绿 #B8D5C5、辅助灰绿 #5B7168。标题使用系统圆体，正文使用系统字体，参数用等宽数字。视觉重点仍是实际 3D 角色；右侧对话用从透明到暖白的横向渐变过渡，没有不透明分割线或可见滚动条。

| 场景 | 布局 |
|---|---|
| 竖屏 / 窄窗口 | 保留全屏角色和约半屏底部渐变聊天 |
| 宽横屏 | 左侧角色主区域，右侧完整聊天列；不再等键盘出现才切换侧栏 |
| 横屏键盘 | 聊天输入在键盘上方；左侧构图平滑避开停靠键盘，浮动键盘只影响重叠的聊天列 |
| 横屏定制、取景 | 右侧透明编辑栏，左侧实时预览，取消/完成固定可见 |
| 音乐、工具、资料、记忆、历史、账号、关于 | 同一弹层容器，横屏侧栏、竖屏底部弹层，内容可无指示条滚动 |
| 首页 | 宽窗口双列角色卡片，窄窗口单列；不随角色数量把所有次要角色塞进同一行 |
| 登录 | 宽窗口欢迎区和登录表单并列，矮窗口收紧装饰；表单可滚动且系统键盘避让 |
| 独立互动舞台 | 横屏压缩辅助提示，将帧率入口放进顶栏，保留底部动作栏 |

断点根据当前窗口宽高：宽度至少 680pt 且宽/高大于 1.08 时采用并列布局。不是根据设备型号或重力传感器来决定；iPad 分屏、缩放窗口也走同一几何规则。方向权限：iPhone 支持竖屏及左右横屏，iPad 额外保留倒置竖屏。

右列按安全区域宽度约 41% 计算，限制 300–440pt。编辑侧栏按窗口和内容推荐宽度计算，限制 320–480pt。安全区覆盖刘海、灵动岛、Home 指示器和窗口控制区。紧凑聊天优先输入/发送/收键盘，减少推荐话题与重复说明；聊天数据不变。实时消息窗口最多显示 60 条，采用可确定完整高度的普通 VStack，减少短视口动画和流式内容同时变化时的测量不稳定；完整历史仍保留在独立历史页。资料输入的“完成输入”复用标题栏位置，避免额外键盘工具条挤没输入框。

## 运行与交互

AdaptiveViewerLayout 统一计算聊天、模型构图和弹层矩形。UIKit 负责原生交互；Unity 收到归一化 compositionArea，继续使用现有包含深度约束的八角点构图求解和相机弹簧。Camera.rect 始终全屏，FOV 保持原值，不靠裁剪或缩放 Unity 视图适配横屏。上方小区域取景会提高镜头俯角，并让俯角与位置、距离共同通过解析弹簧过渡，防止低姿态角色被地板遮挡；不是仅检查脸部投影坐标。内部导出门禁 framingProtocol 升至 7、镜头动画 revision 升至 2，角色/环境源包接口不变。

宽低躺姿、站坐蹲、全身动作均使用已有模型/姿势包围盒在目标区域内取景，视线继续朝向实际虚拟镜头。方向改变不修改 CharacterFraming、CharacterStudio 或对话资料，也不新增模型包协议。触摸坐标仍对应完整实际画面，只有模型外的 UI 区域截获触摸。

保留同一个聊天 hosting controller、编辑草稿和模型实例；旋转时由系统 transition coordinator 驱动原生布局，渐变从当前 presentation 值过渡，镜头保持速度。弹层横屏向侧边进入/退出，竖屏向底部进入/退出。横屏拖动顶部手柄向右关闭，竖屏仍可上拉展开或下拉关闭；始终有可见完成/取消按钮。

## 验收范围

1. iPhone 和 iPad 左右横屏，返回竖屏；所有方向均确认 Unity 与原生比例同步。
2. 聊天草稿随键盘旋转不丢失，输入/发送/收键盘按钮可点，消息仍有阅读空间。
3. 站立/坐姿/躺姿、动作、头部点击及直接手势；模型头部与聊天列分离。
4. 取景未保存草稿旋转保留，取消回原值；姿势面板旋转不丢当前预览。
5. 音乐/工具及登录/首页/互动舞台；无可见滚动指示条。
6. 几何矩阵覆盖 iPad 窄/半宽/宽窗口以及停靠/浮动键盘。实际窗口拖动和系统浮动键盘是否做过设备 UI 验收须在最终记录明确，不能将数学检查等同于系统操作。
7. 采集实际桥事件，检查旋转/面板期间不新增显式相机 Snap、全屏 viewport 和 FOV 不变。模拟器不作为真机持续 FPS 证明。
