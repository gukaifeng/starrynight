# 页面与角色取景分离 · 星夜 0.28.1

用户要求：打开窗口或页面时，角色的位置、缩放与观察角度保持不变。本版取代早期“弹窗出现时把角色缩进剩余空间”的设计；不再通过调慢镜头动画解决问题，而是取消这些界面事件对镜头的控制。

## 统一规则

- 资料卡、定制首页、八个定制子页、外观分类切换、面板展开收起、返回、窗外关闭和滑动关闭都不改变取景。
- 键盘和聊天区域高度只影响聊天界面。横屏中也不再因为键盘或侧栏的尺寸而重新缩放、移动角色。
- 切换底栏菜单后回到同一会话，继续保留当前角色及镜头。
- 用户明确操作取景的范围／大小／朝向、恢复推荐，或者解锁后直接拖动／缩放时，仍按现有规则调整并保存。
- 真正旋转设备或改变窗口大小时仍适配新的屏幕比例；切换角色时仍恢复所选角色的独立设置。自然动作、口型和注视不冻结。

## 实现

`ViewerOverlayController` 将角色构图区域和当前聊天／弹层布局分开计算：使用固定底栏占位、不含键盘的正常会话区域作为构图依据。竖屏保持全屏构图；横屏保留原有角色列。删除根据弹窗上边界、剩余高度、编辑侧栏宽度重新拟合角色的分支及缓存。

`CharacterStudioPanel` 删除进入身形、空间、姿势分类时自动切全身、回面容时切近景的回调。`CompanionCustomizationPanel` 删除子页返回时重新发送取景配置的逻辑。关闭窗口不再补发“恢复”镜头指令；主动编辑仍通过原有的统一关闭／保存流程持久化。

未修改的外观或取景草稿直接结束保存，避免仅浏览一次页面就重新配置模型、姿势和镜头。SwiftUI 保留原有草稿状态与页面过渡，UIKit 弹层本身继续渐变和动画。没有修改 Unity 运行时或模型资源，沿用已验证的两平台导出。

按用户约定先使用 find-skills 检索 SwiftUI 状态实践（[检索目录](https://skills.sh/avdlee/swiftui-agent-skill/swiftui-expert-skill)）；检索结果包含 AvdLee 的 swiftui-expert-skill。本次问题来自项目内 UIKit/Unity 取景耦合，未为此额外安装技能或运行时库。

## 验证方式

真实 UI 操作逐一覆盖资料、八个子页、外观分类、键盘、面板展开与不同关闭方式、底栏返回。比较相机位置、距离、俯仰、朝向、视野角、构图区域及切镜计数；同时保存整个过程的 Unity 相机采样，避免只比首尾而漏掉中间缩放。

另验证主动设置全身／110%／右20°仍生效、进入其他子页保持这套设置、横屏键盘和侧栏保持镜头、主动恢复推荐仍生效。完整结果和截图见 [验证记录](../verification/panel-camera-stability/README.md)。
