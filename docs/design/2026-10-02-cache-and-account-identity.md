# 预备对话缓存、星夜号与用户头像

日期：2026-10-02。客户端 0.88.0（118），服务端实现提交 `c7896089c5d2`。

## 缓存变慢的原因和修复

目标系统引入后，预备回复的指纹同时包含请求携带的目标快照和工作进程保存的最新快照。回复提交关系进度时，没有同步更新用于补缓存的源请求，导致下一次请求把实际仍然匹配的预备内容判为过期。此外，预测其他角色的进入问候会替换当前活跃角色并取消其后台任务，影响当前角色的接话和互动缓存。

服务端现在只对一份单调协调后的目标快照计算指纹；提交反馈时同步更新源请求和工作进程快照。旧的在途请求不能回滚新进度。真正改变目标、上下文、音色或回复选项时仍会失效，不能为了速度使用错误场景的内容。只预测进入问候不会切换活跃角色，也不会取消当前角色的准备任务。

后台准备限制为四个并发槽，按智能接话、进入问候、摇晃/捏/扯等互动、待机发言排序。已准备完成的文字、表现和 PCM 直接交付，不重新调用模型、不进入生成队列；准备中的内容可以接续当前流。每个适用场景或接话选项仍只保留一组，用后再补。首次自我介绍继续使用角色包内的文字和语音，不改为现场生成。

实际生成还未完成、缓存刚用完、服务器重启或用户更改了上下文时，仍有必要等待生成。本次修复解决误失效和后台任务相互取消，不能把冷缓存描述成瞬时可用。

权威实现位于独立服务端仓库：`services/character_ai/goals.py`、`reaction_pool.py`、`preparation_gate.py` 与 `orchestrator.py`。设计见 `../starrynight-server/docs/design/prepared-cache-public-identity-2026-10-02.md`。

## 两层用户标识

- 内部 `id`：原有 UUID，永久身份与鉴权、对话、记忆、外键归属仍以它为准。
- 对外 `starry_id`：`XY` 加 12 位十进制数字，例如 `XY100000000001`。由数据库非循环序列分配，唯一约束保证不重复；存量账户自动补号。
- 当前资料修改接口和数据库保护都不允许改星夜号，登录名和昵称独立可改。
- `account_handles` 留存已分配号码。以后开放改号时需要单独的鉴权、审计和别名迁移事务，不能修改 UUID 或重绑定对话；账户删除也不会把已用号码重新分配给别人。

客户端账户和“我的”页面显示星夜号。升级前 Keychain 缓存没有新字段时显示“同步中…”，激活同步主动读取 `/v1/me`，不把 UUID 当作临时星夜号，也不要求用户重新登录。

## 默认头像与照片

默认小夜猫以及月亮兔、小星球为原生矢量绘制，采用深夜、月光和柔和星色。没有调用图片生成模型。旧的明确选择过的系统符号仍能显示；服务端原默认值迁移为小夜猫。

“我的 → 账户 → 编辑资料”可选择预设或相册照片。PhotosPicker 获取照片后在后台降采样和裁切，不在 UI 主线程解码原始大图。服务端鉴权后重新编码 JPEG/PNG，规范为 256px JPEG，剥除元数据，限制输入尺寸和输出大小；照片与资料引用以版本检查原子提交。

照片通过私有 `/v1/me/avatar` 读写，仅当前账户可访问，不能伪造其他账户的照片引用。当前小头像保存在 PostgreSQL，每用户一份；大型角色包不使用这条存储路径。后续换对象存储时可保留内容哈希和资料引用协议。

本机图片缓存按账户 UUID 和 SHA-256 隔离，并验证内容哈希，应用重启后仍可离线显示已缓存照片。预设选项和照片引用随账户保存在服务器；照片不会发送给 AI 服务。
