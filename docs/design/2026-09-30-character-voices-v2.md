# 角色音色第二版 · v0.54.2 / build 78

## 设计与交付

用户要求现有两位角色都重做为清纯、年幼的女孩声线。原版琪宝偏慵懒气声，豆日向描述仍偏少女；第二版将生成条件明确为原创日系动漫稚嫩童声，普通话清晰，减少成熟胸腔感、沙哑、过多气声与捏嗓感，不通过播放变速或机械升调改变年龄感。

| 角色 | 音色设计 | 区分方式 |
|---|---|---|
| 琪宝 | 清澈、轻细、软糯，安静略害羞 | 较柔和，稍慢，短句自然停顿、尾音收住 |
| 豆日向 | 清甜、明亮、纤细，开朗好奇 | 较清脆，节奏轻快，有自然笑意与小幅语调起伏 |

`profiles.py` 保存两份独立 `voice_prompt`、短预览文字与 `voice_delivery`。两款均使用版本 `childlike-v2`，各自创建新的独立音色 ID；不是只改客户端标签。正式合成的语气指令也保持各自的稚嫩、轻柔或活泼特征。

继续采用百炼 `voice-enrollment` 声音设计，目标模型为现有 `qwen-audio-3.1-tts-flash`，合成保持 24 kHz / 16-bit / 单声道。目标模型须与合成端一致，按[声音设计 API](https://help.aliyun.com/zh/model-studio/voice-design-api-references)和[合成 API](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)实现。

## 替换、回退和费用

- 原管理接口默认返回现有绑定，不能因启动、更新部署或普通重试产生新的设计费用。只有带已在角色配置中定义的 `revision` 才进入重做流程。
- 每角色/版本使用稳定任务 ID。已有候选直接复用；正在创建、超时或不确定失败都拒绝再次自动付费请求。新候选生成与短句合成验证期间，旧音色仍能服务。
- 新预览使用独立文件名，保留旧预览。成功返回音色 ID 后立即落盘任务元数据，即使预览解码失败也能人工恢复已创建资源，不丢失付费结果。
- 管理确认须匹配候选 `job_id`，SQLite 事务内归档旧绑定、切换新绑定并清除候选。过期确认、缺失候选标识不误切换；两个角色彼此独立。
- 替换前用 SQLite backup 保存私有状态快照。原先两次设计记录保留，本机设计总额度从 2 显式提高到 4，正好覆盖本次新增两款；日常对话额度仍关闭。
- 专项付费验证为 **2 次音色设计＋2 句短 TTS**，每句为“你好，今天也想听你说说话。”。普通测试全用传输替身或本地音频夹具，不调用付费 AI；安装后 App 自身的正常问候另按现有逻辑运行。

## 旧语音缓存

服务端缓存原本已经包含实际音色 ID，替换后自然进入新缓存。iOS 原先只有固定 `designed-v1` 代际，会命中历史旧录音；两名内置角色一起切换时将客户端代际升到 `designed-v2`。新对话和重新播放旧消息都走当前音色，旧文件按缓存回收规则淘汰，不删除聊天记录。

这是当前两角色一起发布的缓存代际更新。今后仅服务端更新其他音色版本时，也必须让对应客户端缓存版本跟随，不能只替换服务端绑定便声称所有历史播放已切换。

首次模拟器编译的失败来自测试代码试图使用 `CloudSpeech` 的私有 WAV 构造函数。改为在旧缓存键放入必须被忽略的哨兵数据，不放宽生产代码可见性；重新编译并执行音频测试通过。

波形检查验证有效音频与播放链路，不代表对“年幼感”的主观听感已经由人验收；新预览已保存在本机供试听。音频风格需要以实际听感为准，不能仅凭音高或波形推断年龄。

私有证据位于 `.local/checks/voice-v2/`：预览与短句 WAV、`review.json`、`activation.json`、`live-status.json`、`audio-playback-final.xcresult`、`install.json` 和状态备份。部署数据里的 `voice_history` 保存原音色绑定；供应商 ID、密钥、完整数据库及原始声音不公开提交。
