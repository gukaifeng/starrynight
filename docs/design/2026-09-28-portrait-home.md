# 小伴 · 轻量界面与角色头像（0.16.0 / 29）

## 目标

首页负责选择一个想聊天的角色；角色页让模型保持视觉主体。取消刚加入的四宫格与显示模式切换，回到唯一的横向单卡。角色头像必须是真实模型的可辨认近景，并与保存的外观对应。

## 视觉取舍

延续品牌色，不为此次调整另起风格：纸白 #F7F5F0、薄荷 #EAF2ED、深绿 #274A43、灰绿 #5B7168、浅玉 #B8D5C5、暖桃 #E7BCAD。角色名用系统圆体中等字重 22 pt，界面正文用系统常规体，辅助文字 11–12 pt。首页卡片宽约 300 pt、最高约 358 pt，可见头像不超过 144 pt；横屏为头像与文字并排。以真实小头像为视觉重点，其余边框、按钮底片和阴影保持克制。

分页指示放在卡片上方，活动短线与其他小点明确表达当前位置，支持点选和左右滑动；没有首页纵向滚动。

分页使用横向 ScrollView 的 viewAligned 与 scrollPosition。头像缓存刷新不重建 Image 分支，聊天期间忽略后台页面自动写回选中项，返回后恢复当前角色；避免异步头像更新令系统 TabView 跳页。iOS 18 及以上使用 alwaysByOne，iOS 17 使用 always 限制，按实际卡片对齐；不因大屏快速滑动连续跳过角色。统一定制页的子页位于淡出的分类页上层，防止过渡时旧页面截获操作。

角色页顶部两按钮为 34 pt 可见底片、44 pt 命中区域、16 pt 常规字重图标，默认白色底片透明度 32%；减少透明度辅助设置仍提供实色。输入栏固定为文字、语音、发送顺序；发送圆底 32 pt，命中区域 44 pt；输入框支持 1–3 行增长，紧凑横屏限制一行。收键盘按钮移到键盘工具栏，避免挤占文字宽度。

## 返回过渡

旧流程先暂停 Unity、拆除聊天层，再从 Unity 根视图取得 UIKit 快照并覆盖首页淡出。Metal 内容不保证被快照完整捕获，且先拆除与暂停会改变最后可见帧。

新流程引入 closing 状态：保持 Unity 窗口、3D 画面与原生聊天层不变；首页先在其后完成布局，Unity 整窗 380 ms ease-in-out 淡出，结束后隐藏窗口、交还 key window，再停止会话与渲染。减少动态效果时为 180 ms。过渡期间不允许重复返回或打开另一个角色。加载取消仍直接回首页，不展示上一次角色。

## 真实头像与缓存

- 独立离屏相机复制角色、采样中性 Idle、使用已保存的脸型、身材、发型、服装、配色与角色包参数；不移动聊天相机、不改变用户姿势。
- 从模型标准的 headRenderer 获得实际变形后头部范围，再依据身高留出头发与肩部空间。输出 512 × 512、4 倍 MSAA 的引擎渲染图。
- 使用固定柔光背景、单独的灯光；同步渲染期间的全局状态和灯光 mask 在 finally 中还原，临时模型和网格释放。
- 初始头像由同一渲染器在 Editor 中导出并随 App 打包。缓存键包含渲染版本、角色 ID/包版本、保存的外观及配色；聊天内容、昵称、相机、背景与姿势不影响头像键。
- 角色打开与外观保存后合并请求，返回时补交尚未生成的保存外观。Swift 只接受可关联的请求及与最新保存外观一致的结果，缓存到本机，重启复用。失败时保留内置头像，下次打开重试，不阻止聊天。
- 没有每帧截图或联网图片生成；首次生成、保存后生成的耗时不等同于持续渲染帧率证明。

依据：Unity 官方 [SingleCameraRequest / SubmitRenderRequest](https://docs.unity.com/en-us/engine/6000.0/manual/cameras/urp/multiple/user-render-requests)。没有新增第三方依赖。分页依据 Apple 官方 [viewAligned](https://developer.apple.com/documentation/swiftui/scrolltargetbehavior/viewaligned)，API 可用性同时核对本机 SDK。
