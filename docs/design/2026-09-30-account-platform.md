# 独立账户平台开发决策

完整技术设计维护在 [backend/docs/architecture.md](../../backend/docs/architecture.md)，执行入口在 [backend/README.md](../../backend/README.md)。后端迁移走其自己的版本与 CI，不随 Unity 导出或 iOS 编译触发。

本轮选择 Go + chi/Huma + PostgreSQL + Redis。保留现有 `ios/`、`unity/`、角色 SDK 和 AI worker 的独立职责；在同仓库中增加可搬走的 `backend/`，不进行会破坏资源导出路径的大规模搬目录。

主要决策：

- 先实现有事务边界的模块化单体；会话和限流在共享 Redis，资料在 PG，API 可以水平扩容。
- 内部账户 UUID 与公开作者 ID 分离。角色订阅和作者关注继续分开，公开角色元数据不能夹带私有账户 ID。
- 先支持真实账号密码与开发游客。游客原地注册保留资料，生产配置禁止游客绕过；微信和短信只预留身份扩展，不伪装已有供应商。
- 使用资源版本、账户提交顺序和未知字段保留实现可升级同步。不能保证任意未来变化零成本，破坏性变化必须有新版本、迁移与旧客户端验证。
- App 本机缓存照常可用；网络错误保留改动，冲突显式处理。系统凭证进 Keychain；连接配置不包含付费 Key。
- 付费 AI 沿用独立 worker，并加服务端账户鉴权入口。账户测试绝不调用付费模型，也不重复设计角色音色。

关键问题：pgx 无命名预编译执行模式无法自动推断 `map[string]any` 的 JSONB 类型，曾导致注册 503；已在连接建立时注册 JSONB 默认映射，并通过真实 PG/Redis 集成测试。Swift 的账户字典同时读写触发独占访问编译错误，改为局部副本更新。同步收到原版本回执时覆盖离线改动、RFC 7396 删除 null 后持续重传、同步页逐条写大文件等问题也分别处理并留下协议测试。

后半程执行权限收紧：本机网络、CoreSimulator、Swift 宏插件受限；没有删除数据库锁文件、重置模拟器或关闭系统保护来绕过限制。最终结果必须以 [验证记录](../verification/account-platform/README.md) 为准，不能沿用旧通过结果宣称最新 App 已安装。
