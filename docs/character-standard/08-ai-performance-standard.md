# AI 表演适配标准 v1

本标准补充 XCP `core.performance@1` 和 `core.autonomy@1`。模型制作仍独立于聊天后端。导入新角色时不能仅凭动作名字将资源交给 AI。

1. XCP先通过原有清单、许可、骨骼、运行时与动作验证；保留作者原始资源。
2. 在后端角色档案登记独立人设、世界观、知识边界、说话习惯和Voice Design绑定。付费Key与voice管理凭证不是角色公开包内容。
3. 为适合自动触发的原作资源登记asset_id、原组名、expression/action类型、abstract intent、observable_effects、强度范围、关系条件、冷却、时长、权重、稀有度、能否打断/恢复、enabled。参照`services/character_ai/profiles.py`当前两位角色；不要复制原曲线/贴图到公开后端。
4. observable_effects必须是单独观察该资源时确实可见的效果。仅手指张开不等于举手/挥手；眼型变化不等于扭头；有笑脸不等于有捂嘴动画。
5. 客户端每轮传实际安装角色的可用资源ID，后端匹配取交集；第一阶段脑模型只收到抽象能力。不可用资源回退neutral/idle，不谎称执行。
6. 自动表现目前只接expression与hands；循环睡眠、换装、姿势和物件交互须增加相应冲突/中断/恢复与原生验证后才能开放。资源丰富不代表默认都让AI随机调用。
7. 台词、可见心声、动作旁白分开；hidden与待解锁心声不下发。声音事件使用平台内部枚举，供应商标签只在TTS适配器内生成。
8. 原生按beat开始播放时触发表演，结束/取消恢复先前选择；手动操作优先。待机微动作继续在本地执行，禁止绑定逐帧或定时高频模型调用。
9. 每个新角色要验证：角色能力交集、缺失动作回退、旁白无虚构、语音不读心声、切换取消、恢复默认、账号/角色记忆隔离、音色不同且不重复设计。

协议扩展应新增可选字段/新版本端点，并给旧客户端缺省与降级规则。不能承诺未来任何需求都没有兼容性成本；新能力只有在资源、后端筛选与客户端执行都就绪时才声明支持。
